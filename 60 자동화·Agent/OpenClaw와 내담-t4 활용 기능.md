# OpenClaw와 내담-t4 활용 기능

> [!summary] 벤토 소개
> **벤토**는 단순 답변형 챗봇이 아니다. MSI 노트북을 중심으로 로컬 환경, 원격 GPU 서버 `내담-t4`, 외부 서비스를 연결해 실제 업무를 수행하는 개인 오케스트레이션 에이전트다.

Telegram에서 짧고 직접적으로 요청하면 목적과 제약을 분석하고, 필요한 작업을 MSI에서 실행하거나 `내담-t4`에 위임한다. 결과는 회수·검수·저장하며 외부 게시나 배포는 승인 후 수행한다.

## 1. 요청 분석과 업무 관리

- 짧은 Telegram 명령을 실행 가능한 작업으로 구조화
- 목적, 입력, 제약, 산출물, 검증 기준 정의
- 복잡한 업무를 단계와 하위 작업으로 분해
- 진행 상태, 실패 원인, 미완료 항목 정리
- 반복 업무를 체크리스트, 스크립트, 워크플로로 전환
- 이전 결정, 사용자 선호, 프로젝트 맥락을 메모리에서 찾아 활용

## 2. 로컬 파일과 문서 작업

- 파일과 폴더 검색, 읽기, 생성, 수정, 비교
- Markdown, TXT, JSON, YAML, CSV 작성
- Word, PDF, PowerPoint, Excel 문서 생성·편집·검수
- 회의록, 보고서, 제안서, 매뉴얼, 체크리스트 작성
- 문서 요약, 번역, 재구성, 형식 통일
- 여러 자료를 하나의 최종 문서로 통합
- Obsidian, Notion 등 지식 저장소 정리

## 3. 소프트웨어 개발

- Java, Spring Boot, Python, JavaScript·TypeScript, Vue·Quasar 코드 작성
- 기존 코드베이스 분석과 변경 영향 범위 조사
- 기능 구현, 버그 수정, 리팩터링과 코드 단순화
- 설정 파일, SQL, Docker, CI/CD 스크립트 작성
- 단위 테스트와 통합 테스트 실행
- 빌드 오류, 런타임 오류, 로그 분석
- Node.js `--inspect`, Python `pdb`·`debugpy` 기반 디버깅
- API 설계와 연동 코드 작성
- MCP 서버, AI Agent, RAG 파이프라인 구현
- 실행 방법, 검증 절차, 장애 대응 문서화

## 4. Git과 GitHub

- 저장소 상태, 브랜치, diff, 이력 분석
- 안전한 코드 수정과 변경 내용 검토
- 커밋 메시지와 PR 본문 작성
- GitHub 이슈, PR, 워크플로 조사 및 관리
- 충돌 원인 분석과 해결 지원
- 릴리스 노트와 변경 이력 작성
- 범위가 명확한 변경의 로컬 커밋

> [!warning] 승인 필요
> 원격 저장소 `push`, 병합, 브랜치 삭제 등 공유 저장소에 영향을 주는 작업은 범위를 확인하고 수행한다.

## 5. 시스템과 운영

- Linux·WSL 환경 점검
- CPU, 메모리, 디스크, GPU(`nvidia-smi`), 프로세스, 포트 확인
- OpenClaw Gateway, Telegram 연동, cron, systemd 상태 진단
- Docker 컨테이너·볼륨·네트워크 조회와 로그 분석
- Docker Compose, nginx, Caddy, SSH 설정 분석
- 로그 수집과 장애 원인 추적
- 환경변수, 경로, 권한 문제 진단
- 방화벽, 포트, 바인딩과 `healthcheck` 기반 보안 점검
- 운영 점검 스크립트와 복구 절차 작성
- 정기 상태 확인과 이상 알림 구성

> [!warning] 승인 필요
> 서비스 재시작·중단, 컨테이너 재생성, 운영 설정 변경 등 영향이 있는 작업은 대상과 복구 방법을 확인한 후 수행한다.

## 6. 내담 GPU 서버 오케스트레이션

- SSH를 통한 서버 상태 확인과 작업 실행
- Ollama와 로컬 LLM 추론 요청
- 대량 문서 처리, 임베딩, RAG 평가 위임
- GPU 기반 이미지 생성과 장시간 배치 작업 수행
- 원격 로그와 결과물 수집
- `rsync`, `scp`를 이용한 결과 회수
- 입력 경로, 출력 경로, 실행 상태, 오류를 추적 가능한 형태로 관리

### 로컬 GPU 콘텐츠 생성

- **`sd-image`**: 간단한 이미지 요청을 n8n 승인 흐름과 연계해 생성
- **`story-image`**: 이야기 원문을 씬별로 분석하고 삽화를 자동 생성
- **`story-video`**: ComfyUI와 Wan 2.1로 이야기를 씬별 짧은 영상으로 생성
- 영상 예상 처리 시간은 씬당 약 27분이며 장시간 작업은 약 5분 간격으로 진행 상황을 보고

## 7. AI·LLM·RAG·MCP

- 모델과 아키텍처 비교·선정
- 프롬프트 설계와 평가셋 작성
- 문서 수집, 분할, 임베딩, 검색, 재랭킹 설계
- pgvector, Neo4j, Ollama, OpenWebUI 연계
- RAG 품질 평가와 실패 사례 분석
- Agent, Tool, MCP 서버 설계 및 구현
- 가설, 지표, 성공 기준을 정의한 정량 실험
- 내부망과 보안 정책을 고려한 기업용 PoC 설계
- PoC → 파일럿 → 제한 운영 → 확산 계획 수립
- 공식 문서와 최신 웹 자료를 조사해 출처와 함께 보고
- 씬 분석, 요약, 분류, 정보 추출

> [!note] Claude API 제약
> `내담-t4`에는 별도의 Anthropic API 키가 없으므로 서버 스크립트에서 Claude를 자동 호출할 수 없다. 현재 사용 가능한 로컬 모델이나 별도 승인된 연동 방식을 사용한다.

## 8. 웹 조사와 데이터 수집

- 최신 기술, 제품, 정책, 적용 사례 조사
- 공식 문서, 논문, 웹페이지, PDF 분석
- 여러 출처의 주장 비교와 사실 검증
- 표, 비교표, 의사결정 자료 작성
- 웹페이지에서 필요한 정보 추출
- 브라우저 자동화를 통한 반복 입력과 조회
- 웹사이트 기능 테스트와 스크린샷·로그 수집

> [!note] 수동 전환
> 로그인, CAPTCHA, 2단계 인증처럼 사용자 확인이 필요한 지점에서는 수동 전환을 요청한다.

## 9. 콘텐츠 제작

- 하나의 원문을 블로그, SNS, 강의, 보고서로 재가공
- 기술 블로그, 강의 자료, 칼럼, 책 초안 작성
- 검색 의도를 반영한 제목, 목차, SEO 구조 설계
- 네이버 블로그와 티스토리에 맞춘 문체·형식 변환
- Threads 등 SNS용 짧은 콘텐츠와 연재안 작성
- 맞춤법, 논리, 중복, 사실성, 공개 가능 여부 검수
- 게시용 썸네일, 삽화, 다이어그램 기획 및 생성

> [!warning] 승인 필요
> 블로그와 SNS 등 외부 채널 게시는 최종 미리보기 확인과 승인 후 수행한다.

## 10. 이미지·디자인·미디어

- 새 이미지, 일러스트, 썸네일, 상징적 장면 생성
- 기존 이미지 수정, 배경 제거, 스타일 변경
- 다이어그램, 아키텍처도, 프로세스 시각화
- 프레젠테이션용 시각 자료 제작
- 웹 UI 시안과 프론트엔드 디자인
- 동영상 프레임 추출과 분석
- GIF, 밈, 알고리즘 아트, 간단한 영상 콘텐츠 제작
- 음성 합성이 가능한 환경에서 낭독용 오디오 생성

## 11. 브라우저와 외부 서비스 자동화

- 관리 화면 접속과 반복 입력 자동화
- 게시물 작성 화면 구성과 미리보기
- Google Workspace(`gog`): Gmail, Calendar, Drive, Docs, Sheets, Contacts, Tasks
- Notion, GitHub 등 연결된 서비스 활용
- n8n Webhook, API, 승인 워크플로 연계
- 날씨 조회
- Telegram 등 메신저 메시지, 투표, 리마인더 발송
- 필요한 연결 플러그인이 있으면 설치를 제안한 뒤 활용

> [!warning] 외부 전송
> 이메일 발송, 메시지 전송, 외부 게시처럼 다른 사람이나 서비스에 영향을 주는 작업은 대상과 내용을 확인한 후 실행한다.

## 12. 자동화와 일정 작업

- Bash, Python, Node.js 자동화 스크립트 작성
- cron 기반 정확한 시간의 반복 작업 구성
- n8n 기반 승인, 재시도, 채널 분기 워크플로 설계
- Heartbeat 기반 주기적 상태 점검
- 실패 로그, 재시도 기준, 알림 조건 설계
- 정기 보고서, 콘텐츠 생산, 서버 점검 자동화

```text
트리거 → 입력 검증 → 처리 → 결과 확인 → 로깅·알림
```

## 13. 프로젝트·경영 지원

- WBS, 일정, 리스크, 이슈, 의사결정 자료 작성
- 임원용 1분 요약과 실무용 상세 보고 분리
- 요구사항, 범위, 품질 기준 정리
- 대안의 장단점, 적용 조건, 도입 난이도, 운영 부담 비교
- 1인 기업의 콘텐츠, 상품, 업무 프로세스 설계
- 아이디어를 실행 계획, 산출물, 자동화 흐름으로 구체화

## 14. 지식·기억 관리

- `MEMORY.md`, 일별 `memory` 파일, 세션 기록을 활용한 연속 기억
- 메모리 검색을 통한 과거 결정과 작업 맥락 복원
- Obsidian 볼트와 메모리 위키 정리·유지관리
- Context7을 활용한 라이브러리 공식 문서 조회

## 15. 노드·기기 제어

- 페어링된 기기의 카메라, 화면, 위치, 알림 상태 조회
- MSI 노트북과 연결 기기 사이의 파일 송수신
- 기기별 실행 명령과 결과 확인

> [!warning] 개인정보와 기기 접근
> 카메라, 화면, 위치 등 민감한 기기 정보는 명시된 대상과 목적 범위 안에서만 조회한다.

## 실행 권한과 안전 기준

### 직접 수행할 수 있는 작업

안전하고 되돌릴 수 있으며 요청 범위가 명확한 다음 작업은 바로 진행할 수 있다.

- 파일 분석과 문서 작성
- 코드 수정과 테스트
- 로컬 환경과 서버 상태 진단
- 웹 조사와 자료 비교
- 콘텐츠 초안 생성
- 결과물의 품질·형식·보안 검수

### 사전 승인 또는 범위 확인이 필요한 작업

- 이메일, 블로그, SNS 등 외부 발송과 게시
- 유료 API 호출과 비용 발생 작업
- 운영 서비스 재시작과 중단
- 대량 파일 삭제 또는 덮어쓰기
- Git `push`, 병합, 브랜치 삭제
- 계정, 권한, 보안 설정 변경
- 민감정보가 포함될 수 있는 외부 전송

### 보안 원칙

- API 키, 토큰, 비밀번호를 채팅이나 문서에 그대로 노출하지 않는다.
- 확인하지 않은 결과를 완료된 것으로 보고하지 않는다.
- 외부 게시 전 민감정보, 공개 범위, 대상 채널을 검수한다.
- 운영 변경 전 영향 범위와 복구 방법을 확인한다.

## 업무 수행 흐름

```text
Telegram 명령 수신
  → 요청 분석 및 작업 구조화
  → MSI 로컬 실행 또는 내담-t4 원격 위임
  → 결과 회수
  → 품질·형식·보안 검수
  → 저장 및 결과 보고
  → 승인 후 외부 게시·배포
```

## 효과적인 요청 예시

- “이 저장소의 빌드 오류를 찾아 수정하고 테스트해.”
- “내담 서버 상태를 확인하고 Ollama 모델 응답 속도를 측정해.”
- “이 자료로 기술 블로그 초안과 Threads 게시물 5개를 만들어.”
- “이번 주 프로젝트 이슈를 임원 보고용 1페이지로 정리해.”
- “매일 오전 9시에 서버와 cron 상태를 점검하도록 구성해.”
- “이 문서들로 사내 RAG PoC 구조와 평가 기준을 만들어.”
- “이 이야기의 주요 장면을 분석하고 삽화를 만들어.”
- “이 문서를 Obsidian에 분류하고 관련 노트와 연결해.”
