> 왜 ChatGPT는 틀린 답을 확신 있게 말할까?

**1\. 설명회 개요**

이번 설명회는 LLM(대규모 언어 모델)의 동작 원리와 한계를 구조적으로 이해하는 것을 목표로 한다. 단순히 “똑똑한 AI”로 인식하는 수준을 넘어, 확률 기반 예측 시스템이라는 본질을 명확히 전달하는 데 초점을 둔다.

​

핵심 내용은 Token, Embedding, Context와 같은 기본 개념을 기반으로, Transformer 구조와 Attention 메커니즘을 통해 LLM이 문맥을 처리하는 방식을 설명한다. 이어서 Next Token Prediction이라는 생성 원리를 통해 LLM이 실제로 어떻게 답변을 만들어내는지를 이해하도록 구성된다.

​

또한 Hallucination, Context 제한, 최신성 부족과 같은 구조적 한계를 분석하고, 이는 단순 성능 문제가 아니라 설계 구조에서 비롯된 문제임을 강조한다. 이를 바탕으로 RAG, Agent, Prompt Engineering과 같은 실무적 보완 전략을 제시한다.

​

결론적으로 본 설명회는 LLM을 “잘 사용하는 방법” 이전에, “왜 틀리는지 이해하는 것”을 핵심으로 하며, 이를 통해 실무에서 활용 가능한 AI 시스템 설계 관점까지 연결하는 것을 목표로 한다.

* * *

**2\. LLM의 핵심 개념**

![](https://postfiles.pstatic.net/MjAyNjA0MjRfOTUg/MDAxNzc2OTcyNTI3Nzg2.AGQe_1vZxqvCQlqQhxeFs2ggWc_0qvOe_NEHUxtYMK4g.1kz92Q2c-0_OK-IYF4rqzt5ImoLtNyXnAQD1sI0lpGkg.PNG/ChatGPT_Image_2026%EB%85%84_4%EC%9B%94_24%EC%9D%BC_%EC%98%A4%EC%A0%84_04_28_04.png?type=w80_blur)

LLM은 생각하는 존재가 아니다. 확률 기반으로 다음 단어를 예측하는 모델이다.

​

**1) Token**

문장을 잘게 쪼갠 단위 → LLM은 문장이 아니라 토큰 시퀀스를 처리한다.

  * 단어가 아니라 “토큰 단위” 

  * 예: "Hello world" → 여러 토큰으로 분리 

​

**2) Embedding**

토큰을 숫자로 변환한 벡터 → “단어의 의미 공간”을 만든다.

  * 의미를 수치화 

  * 유사한 단어는 가까운 위치 

​

**3) Context**

모델이 참고할 수 있는 입력 범위 → LLM의 “기억력” 한계

  * 이전 대화 포함 

  * 길이에 제한 존재 

* * *

**3\. Transformer 구조**

**1) Transformer란**

Transformer는 LLM의 핵심 아키텍처로, 문장을 순차적으로 처리하는 기존 방식(RNN, LSTM)에서 벗어나 문맥 전체를 동시에 처리하는 구조이다. Transformer는 “문장을 하나씩 읽는 방식”이 아니라 “문장 전체를 보면서 중요한 관계를 찾는 구조”라고 이해하면 된다. 

​

기존 방식은 문장을 앞에서부터 하나씩 읽었다. 반면 Transformer는 문장을 **한 번에 전체로 보고 처리** 한다. 이 구조 덕분에 LLM은 자연스럽고 문맥에 맞는 문장을 생성할 수 있다. 

​

**2) Attention 개념**

가장 중요한 개념은 Attention이다. Attention 메커니즘을 통해 단어 간 관계를 병렬적으로 계산하는 데 있다. 문장 안에서 어떤 단어가 중요한지 스스로 판단하고, 서로 어떤 관계인지 계산한다. 예를 들어 “나는 사과를 먹었다”라는 문장에서 “먹었다”는 “사과”와 연결된다는 것을 자동으로 파악한다.

​

**3) Transformer 특징**

  * 중요한 단어에 집중 → 모든 단어를 똑같이 보는 것이 아니라, 의미 있는 관계에 가중치를 둔다.

  * 병렬 처리 가능 → 속도와 확장성 확보. 문장을 순서대로가 아니라 동시에 처리한다. 속도가 빠르고, 긴 문장도 잘 다룬다.

  * 장거리 의존성 처리 → 긴 문맥에서도 관계 유지. 문장의 위치 정보도 함께 고려한다. 단어 순서를 잃지 않도록 위치 정보를 넣는다.

​

**4) Transformer 구성 요소**

  * Self-Attention: 모든 토큰 간 관계 계산. 각 토큰이 문장 내 다른 모든 토큰과의 관계를 계산하여, 어떤 단어에 집중해야 하는지를 결정한다. 예를 들어 “나는 사과를 먹었다”라는 문장에서 “먹었다”는 “사과”와 강하게 연결되며, 이러한 관계를 Attention이 수치적으로 반영한다. 

  * Multi-Head Attention: 다양한 관점에서 문맥 해석. 하나의 Attention이 아니라 여러 개의 Attention을 병렬로 수행하여, 문법적 관계, 의미적 관계 등 다양한 관점에서 문맥을 동시에 해석한다. 이를 통해 단일 시각이 아닌 다차원적인 문맥 이해가 가능해진다.

  * Feed Forward Network: 비선형 변환으로 표현력 확장. Attention을 통해 재구성된 벡터를 비선형 변환하여 표현력을 확장한다. 이는 단순 관계 계산을 넘어 더 복잡한 패턴을 학습하도록 돕는다. 

  * Positional Encoding: 단어 순서 정보 보존. Transformer는 순서를 직접 처리하지 않기 때문에, 토큰의 위치 정보를 별도로 주입하여 문장의 순서를 인식하도록 한다.

* * *

**4\. LLM의 동작 방식**

LLM의 동작 방식은 매우 단순한 원리로 설명할 수 있다. 핵심은 Next Token Prediction이다. LLM은 문장을 “이해해서” 생성하는 것이 아니라, 현재까지의 입력을 기준으로 다음에 올 단어의 확률을 계산한다.

​

LLM의 동작 흐름은 다음과 같다.

a. 사용자가 문장을 입력하면, 모델은 그 문장을 토큰 단위로 나눈다.

b. 그리고 그다음에 올 수 있는 후보 단어들의 확률을 계산한다.

c. 그중에서 가장 확률이 높은 단어를 선택한다.

d. 이 과정을 반복하면서 문장을 계속 이어간다.

​

결국 LLM은 입력 → 확률 계산 → 단어 선택 → 반복이라는 과정을 통해 답변을 만들어낸다. LLM은 의미를 “이해”해서 답하는 것이 아니라, 데이터 기반으로 **가장 그럴듯한 문장** 을 생성하는 시스템이다. 그래서 자연스럽게 보일 수는 있지만, 항상 정확하다고 보장할 수는 없다.

* * *

**5\. LLM의 한계 (중요)**

> LLM의 오류는 성능 문제가 아니라 구조 문제다

**1) Hallucination (환각)**

  * 사실이 아닌 정보를 그럴듯하게 생성 

  * 틀린 답도 확신 있게 표현. 정답이 아니라 “확률” 기반 생성

​

**2) Context 제한**

  * 긴 문서를 모두 기억하지 못함 

  * 이전 대화 일부만 반영 

​

**3) 최신성 부족**

  * 학습 시점 이후 정보 반영 불가 

  * 실시간 데이터 없음 

* * *

**6\. 핵심 포인트**

여기서 중요한 인식 전환이 필요하다. 많은 개발자들은 “모델 성능이 좋아지면 정확도 문제도 해결된다”고 생각한다. 그러나 실제로는 그렇지 않다. LLM의 오류는 단순한 성능 부족이 아니라, 확률 기반 생성 구조에서 비롯된 한계다. 즉, 모델을 아무리 고도화해도 “틀릴 수 있는 구조” 자체는 변하지 않는다. 정확도 문제는 모델의 크기나 성능 문제가 아니라, 구조적인 문제다.

​

따라서 해결 방향도 달라져야 한다. 모델을 더 키우는 것이 아니라, **구조를 보완하는 방식** 으로 접근해야 한다.

![](https://postfiles.pstatic.net/MjAyNjA0MjRfMjQ0/MDAxNzc2OTczOTc5MzQ4.ZILfRmuqhokQzBUSwYaRNe4NCSRgXx6LcBu5w2zvSFEg.dP3ZTMCRkGkkFWe7rxtauC_Ugi4E7k_IgPJ4bLU0rGgg.PNG/ChatGPT_Image_2026%EB%85%84_4%EC%9B%94_24%EC%9D%BC_%EC%98%A4%EC%A0%84_04_52_47.png?type=w80_blur)

**1) RAG(Retrieval-Augmented Generation) - “정확한 답이 필요한 경우”**

외부 데이터베이스나 문서를 연결하여, 모델이 실제 근거 기반으로 답하도록 만든다.

→ “기억”이 아니라 “검색”을 통해 정확도를 보완한다.

​

**2) Agent - “자동화나 실행이 필요한 경우”**

LLM이 단순히 답변만 하는 것이 아니라, 도구를 사용하고 작업을 수행하도록 확장한다.

→ 계산, 검색, API 호출 등을 통해 실제 실행 기반 결과를 만든다.

​

**3) Prompt Engineering - “출력 품질을 제어하고 싶은 경우”**

입력 구조를 설계하여 모델의 출력 방향을 제어한다.

→ 같은 모델이라도 프롬프트에 따라 결과 품질이 크게 달라진다.

​

결론적으로 LLM 활용의 핵심은 “더 좋은 모델을 쓰는 것”이 아니라 “모델의 한계를 이해하고, 이를 보완하는 구조를 설계하는 것”이다.

* * *

**7\. 주요 LLM**

대규모 언어 모델(LLM)은 인터넷에 공개된 방대한 텍스트를 학습한 모델이다. 사람이 분당 250단어를 읽고 하루 8시간씩 읽는다고 가정하면, 그 분량은 수십만 년에 해당할 정도로 방대하다.

> LLM은 엄청난 기억력을 가진 다방면에 똑똑한 컨설턴트다.

다만 이것을 사람처럼 “이해하고 기억하는 지능”으로 보는 것은 정확하지 않다. LLM은 방대한 데이터를 바탕으로, 문맥에 맞는 다음 단어를 확률적으로 예측하는 방식으로 동작한다. 그 결과 다양한 주제에 대해 매우 유창하고 폭넓게 답할 수 있어, 실무에서는 다방면의 지식을 가진 컨설턴트처럼 활용된다.

​

**1) OpenAI의 GPT**

GPT는 OpenAI가 개발한 대표적인 대규모 언어 모델이다. 대규모 Transformer 구조를 기반으로 하며, 자연어 이해와 생성 능력이 매우 뛰어나다. 텍스트뿐 아니라 이미지까지 함께 처리할 수 있는 멀티모달 기능도 제공하며, ChatGPT와 API 서비스 형태로 널리 활용된다. 실무에서는 문서 작성, 요약, 질의응답, 코드 생성, 업무 자동화 등 다양한 영역에 적용할 수 있다.

​

**2) Anthropic의 Claude**

Claude는 Anthropic이 개발한 언어 모델로, 안전성과 윤리성을 중요하게 고려한 설계가 특징이다. 사용자의 의도를 비교적 안정적으로 해석하고, 긴 문서를 다루거나 정리하는 작업에 강점을 보이는 경우가 많다. 특히 인간과의 협업, 신뢰성 있는 응답, 데이터 보호 관점에서 주목받는 모델이다.

​

**3) Google의 Gemini**

Gemini는 Google DeepMind가 개발한 언어 모델이다. 텍스트뿐 아니라 이미지, 음성, 영상 등 다양한 형태의 정보를 함께 다루는 멀티모달 방향을 지향하며, 구글 서비스와의 연계성이 큰 장점이다. Gmail, Google Docs, Google Search 등과 연결해 활용할 수 있어, 구글 생태계 안에서의 생산성 향상에 유리하다.

​

**4) Google의 Gemma**

Gemma는 Google DeepMind가 공개한 경량 계열 모델이다. 대형 상용 모델과 달리 비교적 가볍게 활용할 수 있어, 개발자나 연구자가 직접 실험하고 응용하기에 적합하다. 로컬 환경이나 제한된 자원에서도 실행 가능하다는 점에서, 연구용·개발용 모델로 의미가 크다.

​

**5) Alibaba의 Qwen**

Qwen은 Alibaba에서 개발한 LLM으로, 최근 빠르게 성장하고 있는 모델 계열이다. 특히 코드 생성, 수학 문제 해결, 구조적 응답 생성에서 강점을 보이며, Agent 및 자동화 시스템에 적합한 특성을 가진다. 오픈 모델 형태로 제공되는 경우가 많아, 온프레미스 환경이나 RAG, Agent 시스템 구축에 활용도가 높다. 실무에서는 “정확도와 구조화된 출력”이 중요한 작업에 유리한 모델로 평가된다.

​

**6) Microsoft의 Phi**

Phi는 Microsoft가 개발한 소형·경량 계열 언어 모델이다. 상대적으로 작은 규모이지만 효율성과 실용성을 중시하며, Microsoft의 AI 전략과 함께 활용되는 모델군으로 볼 수 있다. 특히 자사 서비스 및 개발 환경과 결합해 생산성을 높이는 방향에서 의미가 있다.

​

**7) Meta의 LLaMA**

LLaMA는 Meta가 개발한 공개형 언어 모델 계열이다. 연구 커뮤니티와 개발자 생태계에서 폭넓게 활용되며, 다양한 파생 모델과 응용 사례를 만들어냈다. 비교적 효율적인 구조를 바탕으로 성능과 활용성의 균형을 추구하며, 오픈 모델 생태계 확장에 큰 영향을 준 모델이다.

​

**8) DeepSeek의 DeepSeek**

DeepSeek는 중국 AI 기업이 개발한 공개형 언어 모델이다. 수학, 추론, 코드 관련 작업에서 강점을 보이는 모델로 알려져 있으며, 비교적 낮은 비용과 높은 효율을 강조한다. 또한 문제를 단계적으로 분석하고 추론 과정을 구조적으로 보여주는 방식이 특징으로 자주 언급된다.

**주요 LLM 비교 정리**

**8\. 마무리**

LLM을 제대로 활용하기 위해서는 “잘 쓰는 방법”보다 선행되어야 할 것이 있다. 바로 **왜 틀리는지를 이해하는 것** 이다.

​

LLM은 확률 기반으로 문장을 생성하는 구조이기 때문에, 겉으로는 자연스럽고 논리적으로 보이더라도 실제로는 틀린 답을 생성할 수 있다. 이 특성을 이해하지 못하면, 모델을 과신하거나 잘못된 결과를 그대로 사용하는 문제가 발생한다. 

​

반대로, 이 한계를 명확히 이해하면 접근 방식이 달라진다. 

단순히 모델에게 맡기는 것이 아니라, **보완 구조를 설계하는 방향** 으로 전환된다.

​

이때 비로소 다음과 같은 확장이 가능해진다. 

RAG를 통해 외부 지식을 연결하고, 

Agent를 통해 실제 작업을 수행하게 하며, 

프롬프트 설계를 통해 출력의 품질을 통제할 수 있다.

​

LLM 활용의 출발점은 기술이 아니다.

‘왜 틀리는지 이해하는 것’이 모든 설계의 시작이다.
