# 2025-05-03 223854206375 PL SQL - 커서(Cursor)의 개념과 활용 방법

​

데이터베이스 프로그래밍 언어인 PL/SQL에서 대량의 쿼리 결과를 효율적으로 처리하고자 할 때, 커서(Cursor)는 필수적으로 이해하고 활용해야 할 중요한 개념 중 하나이다. 본 문서에서는 커서의 정의, 종류, 사용 방법, 관련 속성 및 실습 예제를 통해 커서의 활용 방법을 체계적으로 소개하고자 한다.

**​**

**1\. 커서란 무엇인가?**

일반적으로 ‘커서’라 하면, 컴퓨터 화면 상에서 깜빡이며 입력 위치를 알려주는 도구를 떠올리기 쉽다. 이와 유사하게, PL/SQL에서의 커서란 **메모리 상에서 SQL 문이 실행되는 위치를 가리키는 포인터** 역할을 한다.

​

SQL 쿼리를 실행하면, 그 결과는 일시적으로 메모리에 저장된다. 커서는 이 결과 집합을 참조하여, **한 행(row)씩 순차적으로 접근하고 처리** 할 수 있게 한다. 데이터가 다수의 행으로 반환될 경우, 이를 한 번에 처리하는 대신, 커서를 통해 한 행씩 인출(fetch)하여 필요한 작업을 수행하는 방식이 일반적이다.

​

모든 행이 처리된 이후에는 커서를 반드시 닫아야 한다. 이처럼 커서는 쿼리 결과에 대한 **선형 탐색 제어 구조** 라 할 수 있다.

​

​

**2\. 커서의 종류**

PL/SQL에서 커서는 크게 두 가지 유형으로 구분된다.

​

**(1) 암시적 커서 (Implicit Cursor)**

  * 모든 DML 문(INSERT, UPDATE, DELETE) 및 SELECT 문이 실행될 때 PL/SQL 내부적으로 자동 생성되는 커서이다.

  * 개발자가 별도로 선언하거나 관리하지 않아도 되며, Oracle이 실행과 동시에 커서를 생성, 열기, 행 인출, 종료까지 자동으로 처리한다.

**​**

**(2) 명시적 커서 (Explicit Cursor)**

  * 프로그래머가 직접 선언하고 제어하는 커서이다.

  * 쿼리 결과가 여러 행으로 반환될 경우 이를 하나씩 명확하게 처리하고자 할 때 사용한다.

  * 개발자가 OPEN, FETCH, CLOSE의 3단계를 수동으로 수행해야 한다.

  * 명시적 커서는 **현재 처리 중인 행을 추적** 할 수 있으며, **활성 집합(active set)**이라는 형태로 쿼리 결과 전체를 메모리에 유지한다.

​

​

**3\. 명시적 커서의 사용 단계**

명시적 커서를 사용하는 기본적인 흐름은 다음과 같다.

  1. **커서 열기 (OPEN)** : SQL 쿼리를 실행하고 결과 집합을 준비한다.

  2. **행 인출 (FETCH)** : 한 번에 한 행씩 결과를 변수에 저장한다.

  3. **커서 닫기 (CLOSE)** : 모든 행 처리가 끝나면 커서를 닫아 자원을 반환한다.

OPEN cursor_name; FETCH cursor_name INTO 변수; CLOSE cursor_name; 

**​**

**​**

**4\. 커서의 주요 속성**

커서에는 현재 상태를 확인할 수 있는 다양한 속성이 제공된다:

  * %ROWCOUNT : 지금까지 인출한 행(row)의 수

  * %FOUND : 가장 최근에 인출한 행이 존재하는 경우 TRUE

  * %NOTFOUND : 인출한 행이 없을 경우 TRUE

  * %ISOPEN : 커서가 열려 있는 상태이면 TRUE

​

이 속성들은 커서 제어 흐름에 유용하게 사용되며, 예외 처리 시에도 활용될 수 있다.

IF NOT cursor_name%ISOPEN THEN OPEN cursor_name; END IF; 

**​**

**5\. 명시적 커서 예제**

다음은 mobile_phone 테이블에서 상품 이름을 한 행씩 출력하는 간단한 예제이다.

DECLARE v_mp mobile_phone.product_name%TYPE; CURSOR cursor_mp IS SELECT product_name FROM mobile_phone; BEGIN OPEN cursor_mp; LOOP FETCH cursor_mp INTO v_mp; EXIT WHEN cursor_mp%NOTFOUND; DBMS_OUTPUT.PUT_LINE(v_mp); END LOOP; DBMS_OUTPUT.PUT_LINE('총 row 수 : ' || cursor_mp%ROWCOUNT); CLOSE cursor_mp; END; / 

  * 명시적으로 OPEN, FETCH, CLOSE를 수행하였다.

  * 결과는 서버 출력(DBMS_OUTPUT)을 통해 확인할 수 있다.

**​**

**​**

**6\. 커서 FOR LOOP 문 (권장 방식)**

PL/SQL에서는 커서 제어를 자동화하는 **FOR LOOP 문** 이 존재한다. 이를 사용하면 OPEN, FETCH, CLOSE를 명시할 필요 없이 더 간결한 코드 작성이 가능하다.

DECLARE CURSOR cursor_mp IS SELECT brand, product_name FROM mobile_phone; BEGIN FOR record_mp IN cursor_mp LOOP IF record_mp.brand = 'LG' THEN DBMS_OUTPUT.PUT_LINE(record_mp.brand || ' => ' || record_mp.product_name); END IF; END LOOP; END; / 

  * 이 예제에서는 LG 브랜드의 제품만 출력한다.

  * record_mp는 암시적으로 선언된 레코드 타입 변수이며, 커서의 각 행을 순회한다.

  * 커서의 열기 및 닫기는 자동으로 처리된다.

**​**

**​**

**7\. 파라미터를 사용하는 커서**

커서 선언 시 파라미터를 포함시키면, **조건에 따라 유동적으로 결과 집합을 변경** 할 수 있다.

DECLARE v_product mobile_phone.product_name%TYPE; v_brand mobile_phone.brand%TYPE; CURSOR cursor_mp(p_brand VARCHAR2) IS SELECT brand, product_name FROM mobile_phone WHERE brand = p_brand; BEGIN OPEN cursor_mp('LG'); LOOP FETCH cursor_mp INTO v_brand, v_product; EXIT WHEN cursor_mp%NOTFOUND; DBMS_OUTPUT.PUT_LINE(v_brand || ' => ' || v_product); END LOOP; DBMS_OUTPUT.PUT_LINE(v_brand || ' 총 ' || cursor_mp%ROWCOUNT || ' 건'); CLOSE cursor_mp; OPEN cursor_mp('SAMSUNG'); LOOP FETCH cursor_mp INTO v_brand, v_product; EXIT WHEN cursor_mp%NOTFOUND; DBMS_OUTPUT.PUT_LINE(v_brand || ' => ' || v_product); END LOOP; DBMS_OUTPUT.PUT_LINE(v_brand || ' 총 ' || cursor_mp%ROWCOUNT || ' 건'); CLOSE cursor_mp; END; / 

  * 브랜드를 매개변수로 전달받아, 조건에 맞는 상품을 조회한다.

  * 커서를 두 번 열어 각각 LG와 SAMSUNG 브랜드의 상품을 출력하였다.

**​**

PL/SQL에서 커서는 대량의 데이터를 다루거나, 복잡한 반복 처리를 제어하는 데 있어 매우 유용한 도구이다. 암시적 커서는 단순한 작업에 적합하며, 명시적 커서는 세밀한 제어가 필요한 상황에서 적합하다. 특히, FOR LOOP나 파라미터 커서와 같이 커서를 다양하게 응용하면 프로그램의 효율성과 유연성이 대폭 향상된다.

​

​

**8\. 실용적인 PL/SQL 커서 예제**

**예제** |  **실무 용도** |  **커서 기능 활용**  
---|---|---  
예제 1. 고객 등급 업데이트 |  조건 기반의 대량 UPDATE |  명시적 커서, 조건 분기  
예제 2. 월별 자동 청구 |  월별 집계 및 INSERT |  파라미터 커서  
예제 3. 오류 로그 기록 |  예외 발생 시 로깅 및 부분 건너뛰기 |  예외 처리 + 커서  
  
**​**

**예제 1: 고객 등급 업데이트 — 조건 기반으로 대량 갱신**

고객의 누적 구매 금액(total_purchase)을 기준으로 등급(grade)을 다음과 같이 나누고자 한다.

**등급** |  **조건**  
---|---  
VIP |  500만 원 이상  
GOLD |  100만 원 이상  
SILVER |  100만 원 미만  
  
**테이블 구조**

CREATE TABLE customer ( customer_id NUMBER PRIMARY KEY, name VARCHAR2(100), total_purchase NUMBER, grade VARCHAR2(10) ); 

**프로시저**

DECLARE CURSOR cur_customer IS SELECT customer_id, total_purchase FROM customer; v_id customer.customer_id%TYPE; v_purchase customer.total_purchase%TYPE; BEGIN OPEN cur_customer; LOOP FETCH cur_customer INTO v_id, v_purchase; EXIT WHEN cur_customer%NOTFOUND; IF v_purchase >= 5000000 THEN UPDATE customer SET grade = 'VIP' WHERE customer_id = v_id; ELSIF v_purchase >= 1000000 THEN UPDATE customer SET grade = 'GOLD' WHERE customer_id = v_id; ELSE UPDATE customer SET grade = 'SILVER' WHERE customer_id = v_id; END IF; END LOOP; CLOSE cur_customer; COMMIT; DBMS_OUTPUT.PUT_LINE('고객 등급 갱신이 완료되었습니다.'); END; / 

실제 현장에서는 위와 같이 등급, 할인율, 상태 플래그 등을 대량 조건 갱신하는 로직에 커서를 많이 활용한다.

​

​

**예제 2: 월별 자동 청구 데이터 생성 — 커서 + 파라미터**

월말마다 **사용자별 서비스 이용 내역** 을 바탕으로 자동 청구 데이터를 생성해야 한다.

**​**

**기본 테이블**

CREATE TABLE usage_log ( user_id NUMBER, usage_date DATE, usage_amount NUMBER ); CREATE TABLE billing ( billing_id NUMBER PRIMARY KEY, user_id NUMBER, billing_month VARCHAR2(6), total_amount NUMBER ); 

​

**파라미터 커서 + 삽입 로직**

DECLARE CURSOR cur_billing(p_month VARCHAR2) IS SELECT user_id, SUM(usage_amount) AS total FROM usage_log WHERE TO_CHAR(usage_date, 'YYYYMM') = p_month GROUP BY user_id; v_user_id usage_log.user_id%TYPE; v_total usage_log.usage_amount%TYPE; v_month VARCHAR2(6) := '202504'; -- 예: 2025년 4월 BEGIN FOR rec IN cur_billing(v_month) LOOP INSERT INTO billing (billing_id, user_id, billing_month, total_amount) VALUES (billing_seq.NEXTVAL, rec.user_id, v_month, rec.total); END LOOP; COMMIT; DBMS_OUTPUT.PUT_LINE(v_month || ' 월 자동 청구 데이터 생성 완료'); END; / 

반복적이고 정기적인 청구, 포인트 적립, 리포트 기록 등에 사용된다.

​

​

**예제 3: 오류 로그 자동 기록 — 예외 처리와 함께 커서 사용**

배치 작업에서 다수의 고객 데이터를 처리하되, 오류가 발생하는 경우 해당 고객 정보를 별도 로그 테이블에 남겨야 함.

​

**기본 테이블**

CREATE TABLE error_log ( log_id NUMBER PRIMARY KEY, customer_id NUMBER, error_msg VARCHAR2(4000), log_time DATE DEFAULT SYSDATE ); 

​

**커서 + 예외 처리 + 로그 기록**

DECLARE CURSOR cur_customers IS SELECT customer_id FROM customer; v_id customer.customer_id%TYPE; BEGIN OPEN cur_customers; LOOP FETCH cur_customers INTO v_id; EXIT WHEN cur_customers%NOTFOUND; BEGIN \-- 예: 고객 혜택 계산 함수 호출 calculate_benefits(v_id); EXCEPTION WHEN OTHERS THEN INSERT INTO error_log (log_id, customer_id, error_msg) VALUES (error_log_seq.NEXTVAL, v_id, SQLERRM); END; END LOOP; CLOSE cur_customers; COMMIT; DBMS_OUTPUT.PUT_LINE('배치 처리 완료. 오류는 error_log 테이블 참조.'); END; /
