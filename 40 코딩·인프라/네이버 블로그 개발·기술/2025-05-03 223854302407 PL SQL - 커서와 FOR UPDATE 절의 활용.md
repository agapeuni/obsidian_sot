# 2025-05-03 223854302407 PL SQL - 커서와 FOR UPDATE 절의 활용

## 본문

![](https://postfiles.pstatic.net/MjAyNTA1MDNfMTMy/MDAxNzQ2MjUwNzA3NTg3.Fq6E60HSCGeeiS5GxrF9HQgFM8K9_q2dxONkIkE5L7Qg.NItpVONOTzekpRLQdeo5McCDlJyGIR0qCgyIIELW8O4g.PNG/PL_SQL-001_\(4\).png?type=w80_blur)

​

데이터베이스에서 여러 사용자가 동일한 데이터를 동시에 처리할 경우, 데이터 무결성과 충돌을 방지하는 것이 매우 중요하다. PL/SQL에서는 이러한 문제를 해결하기 위해 커서(Cursor)와 함께 FOR UPDATE 절을 사용할 수 있다. 이 글에서는 FOR UPDATE 절의 개념과 사용 목적, 그리고 NOWAIT 및 WAIT 옵션을 포함한 실습 예제를 통해 실제적인 활용 방안을 소개하고자 한다.

**​**

**​**

**1\. FOR UPDATE 절이란?**

FOR UPDATE 절은 SELECT 문을 통해 검색된 **결과 집합의 행을 잠그는 기능** 을 수행한다. 즉, SELECT 문을 실행하는 순간, 해당 행들을 다른 세션에서 동시에 수정하거나 삭제하지 못하도록 선점적 잠금(Locking)을 거는 방식이다.

​

이 절은 다음과 같은 특징을 가진다.

  * SELECT 문 **맨 마지막** 에 위치하며, ORDER BY 절보다도 뒤에 위치해야 한다.

  * 결과 집합 내 **각 행을 행 수준(Row-Level)으로 잠근다**.

  * 주로 **기존 값을 기준으로 갱신하거나 삭제** 할 때, 다른 사용자의 영향을 사전에 차단하는 데에 사용된다.

SELECT ... FROM ... WHERE ... FOR UPDATE OF column_name [NOWAIT | WAIT n];

**​**

**2\. 주요 옵션: NOWAIT와 WAIT**

  * **NOWAIT** : 잠금이 되어 있는 행에 대해 기다리지 않고 **즉시 오류를 반환** 한다. 동시성 제어가 필요한 업무에서 **즉시 분기 처리** 가 가능해 효율적이다.

  * **WAIT n** : 최대 n초 동안 잠금을 기다리다가, 시간이 초과되면 오류를 반환한다. 상대적으로 여유 시간을 두고 재시도를 허용한다.

  * 옵션을 생략하면, 기본적으로 **해당 행이 잠금 해제될 때까지 무한정 대기** 하게 된다.

**​**

**​**

**3\. 실습 예제: FOR UPDATE 절의 실제 사용**

다음은 mobile_phone 테이블을 대상으로 brand 값이 'LG'인 행들을 검색하면서 해당 행을 잠그는 예제이다.

​

**예제 1: FOR UPDATE (기본)**

DECLARE v_product mobile_phone.product_name%TYPE; v_brand mobile_phone.brand%TYPE; CURSOR cursor_mp(p_brand VARCHAR2) IS SELECT brand, product_name FROM mobile_phone WHERE brand = p_brand FOR UPDATE OF brand; -- NOWAIT 생략 BEGIN OPEN cursor_mp('LG'); LOOP FETCH cursor_mp INTO v_brand, v_product; EXIT WHEN cursor_mp%NOTFOUND; DBMS_OUTPUT.PUT_LINE(v_brand || ' => ' || v_product); END LOOP; DBMS_OUTPUT.PUT_LINE(v_brand || ' 총 ' || cursor_mp%ROWCOUNT || ' 건'); CLOSE cursor_mp; END; / 

  * 이 예제에서는 brand = 'LG'인 행들을 모두 조회하면서 잠근다.

  * 다른 세션에서 해당 행들을 갱신하거나 삭제하려고 하면 **잠금이 해제될 때까지 대기** 하게 된다.

**​**

**실습 팁**

  1. 두 개의 세션을 동시에 실행한다.

  2. **Session 1** 에서 위 커서를 실행하고, commit 없이 대기한다.

  3. **Session 2** 에서 동일한 행을 UPDATE하려고 시도하면 **대기 상태** 에 빠지게 된다.

  4. 이때 Session 1이 COMMIT 또는 ROLLBACK을 하면 잠금이 해제되고 Session 2의 작업이 진행된다.

**​**

**​**

**예제 2: FOR UPDATE ... NOWAIT**

DECLARE v_product mobile_phone.product_name%TYPE; v_brand mobile_phone.brand%TYPE; CURSOR cursor_mp(p_brand VARCHAR2) IS SELECT brand, product_name FROM mobile_phone WHERE brand = p_brand FOR UPDATE OF brand NOWAIT; BEGIN OPEN cursor_mp('LG'); LOOP FETCH cursor_mp INTO v_brand, v_product; EXIT WHEN cursor_mp%NOTFOUND; DBMS_OUTPUT.PUT_LINE(v_brand || ' => ' || v_product); END LOOP; DBMS_OUTPUT.PUT_LINE(v_brand || ' 총 ' || cursor_mp%ROWCOUNT || ' 건'); CLOSE cursor_mp; END; / 

  * NOWAIT 절을 사용하면, 이미 잠금된 행에 접근 시 **즉시 오류를 반환** 한다.

  * 이 방식은 **대기 시간을 최소화하고 빠르게 분기 처리** 가 필요한 비즈니스 로직에 적합하다.

**​**

**​**

**예제 3: FOR UPDATE ... WAIT n**

DECLARE v_product mobile_phone.product_name%TYPE; v_brand mobile_phone.brand%TYPE; CURSOR cursor_mp(p_brand VARCHAR2) IS SELECT brand, product_name FROM mobile_phone WHERE brand = p_brand FOR UPDATE OF brand WAIT 10; BEGIN OPEN cursor_mp('LG'); LOOP FETCH cursor_mp INTO v_brand, v_product; EXIT WHEN cursor_mp%NOTFOUND; DBMS_OUTPUT.PUT_LINE(v_brand || ' => ' || v_product); END LOOP; DBMS_OUTPUT.PUT_LINE(v_brand || ' 총 ' || cursor_mp%ROWCOUNT || ' 건'); CLOSE cursor_mp; END; / 

  * WAIT 10은 **최대 10초까지 잠금 해제를 기다린다**.

  * 해당 시간이 초과되면 잠금 실패로 인한 예외가 발생한다.

  * 이 옵션은 일정 시간 내에만 대기하도록 하여 **트랜잭션 지연을 제어** 하는 데 유용하다.

**​**

**​**

**4\. 실용 예제: 주문 처리 시 동시 작업 방지**

**시나리오**

온라인 쇼핑몰 시스템에서는 orders 테이블에 저장된 주문 목록 중 "대기" 상태인 주문을 하나씩 처리해야 한다. 이때 동시에 여러 프로세스 또는 사용자가 같은 주문을 처리하면 중복 출고나 데이터 충돌이 발생할 수 있다.

​

이를 방지하기 위해, 커서를 사용하여 **status = '대기'인 주문을 하나씩 처리하고, FOR UPDATE 절로 행을 잠근 후 상태를 '처리중'으로 변경** 한다. 이 작업은 트랜잭션 커밋 전까지 다른 세션에서 같은 주문을 처리하지 못하게 한다.

**​**

**테이블 구조**

CREATE TABLE orders ( order_id NUMBER PRIMARY KEY, customer_name VARCHAR2(100), order_date DATE, status VARCHAR2(20) -- '대기', '처리중', '완료' ); 

주문 상태(status)는 "대기", "처리중", "완료" 중 하나의 값을 가진다.

**​**

**커서 예제 (FOR UPDATE 사용)**

DECLARE v_order_id orders.order_id%TYPE; v_name orders.customer_name%TYPE; CURSOR cur_orders IS SELECT order_id, customer_name FROM orders WHERE status = '대기' FOR UPDATE OF status NOWAIT; -- 잠금 처리 BEGIN FOR rec IN cur_orders LOOP BEGIN \-- 잠긴 행에 대해 상태를 '처리중'으로 업데이트 UPDATE orders SET status = '처리중' WHERE CURRENT OF cur_orders; DBMS_OUTPUT.PUT_LINE('주문 번호 ' || rec.order_id || ' (' || rec.customer_name || ') 처리 시작'); \-- 실제 처리 로직이 들어갈 위치 (예: 출고 처리 등) \-- 예제에서는 딜레이를 주기 위해 DBMS_LOCK 사용 (옵션) \-- DBMS_LOCK.SLEEP(2); \-- 처리 완료 후 상태를 '완료'로 변경 UPDATE orders SET status = '완료' WHERE order_id = rec.order_id; DBMS_OUTPUT.PUT_LINE('주문 번호 ' || rec.order_id || ' 처리 완료'); EXCEPTION WHEN OTHERS THEN DBMS_OUTPUT.PUT_LINE('처리 중 오류 발생: 주문 번호 ' || rec.order_id || ' - ' || SQLERRM); END; END LOOP; COMMIT; END; / 

**주요 포인트**

  * FOR UPDATE OF status를 통해 **status 컬럼이 속한 행만 잠금** 한다.

  * WHERE CURRENT OF cur_orders 구문은 **커서가 현재 가리키고 있는 행** 을 명확하게 UPDATE한다.

  * NOWAIT를 사용하여 다른 세션이 이미 해당 주문을 처리 중이라면 **즉시 오류 반환** → 병렬처리 분기 가능

  * 예외 처리 구문이 포함되어 있어 오류 발생 시에도 루프는 계속된다.

**​**

**테스트 시나리오**

  1. **Session A** 에서 위 프로시저를 실행하여 주문을 처리한다.

  2. 동시에 **Session B** 가 동일한 "대기" 상태 주문에 접근하려 하면, 이미 행이 잠겨 있어 ORA-00054: 리소스가 사용 중 오류가 발생한다.

  3. Session A가 COMMIT하거나 ROLLBACK하면 잠금이 해제되고, 그제서야 다른 세션에서 접근할 수 있다.

**​**

**​**

**5\. 정리 및 활용 팁**

**기능** |  **설명**  
---|---  
FOR UPDATE |  SELECT된 행을 갱신/삭제 전용으로 잠금  
OF column_name |  특정 컬럼을 기준으로 잠금을 제한  
NOWAIT |  즉시 오류 반환 → 다른 처리 흐름으로 빠르게 분기 가능  
WAIT n |  n초 동안 잠금 시도 후 실패 시 오류 발생  
  
**활용 사례**

  * **재고 수량을 확인한 후 바로 출고 처리해야 하는 시스템**

  * **특정 사용자의 정보를 수정하는 중복 요청 방지**

  * **동시성 제어가 필요한 배치 시스템의 작업 병렬화 제어**

**​**

​

FOR UPDATE 절은 PL/SQL 프로그래밍에서 동시성 문제를 사전에 제어하는 강력한 도구이다. 단순히 데이터를 읽는 것이 아니라, 읽은 데이터를 신뢰하고 곧바로 변경하려는 시나리오에서 특히 유용하다. NOWAIT 및 WAIT 옵션을 적절히 활용하면, 사용자 경험을 개선하고 트랜잭션 충돌로 인한 시스템 오류를 최소화할 수 있다.​
