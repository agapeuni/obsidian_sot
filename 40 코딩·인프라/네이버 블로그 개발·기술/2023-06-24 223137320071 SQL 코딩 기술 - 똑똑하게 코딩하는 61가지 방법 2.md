3장 데이터 모델 설계를 변경할 수 없는 경우

좋지 않게 설계된 모델에서 필요한 데이터를 취급하려고 할 때 쿼리를 변형해서 사용하는 경우와 별도의 객체를 생성하여 작업하는 방법이 있다.

​

방법 18 설계를 변경할 수 없을 때는 뷰로 데이터를 간소화하자

뷰는 하나 이상의 테이블이나 다른 뷰에서 필요한 컬럼만으로 새롭게 테이블처럼 볼 수 있는 객체이다. 뷰를 사용하게 되면 특정한 데이터에 집중을 할 수 있고 컬럼 이름을 간소화하거나 좀 더 직관적인 이름으로 변경할 수 있다. 테이블에 민감하고 중요한 정보가 저장되어 있을 때에 뷰를 만들어 테이블의 일부 컬럼을 감출 수가 있다. 여러 테이블에 있는 데이터를 보고용 테이블처럼 취합하여 사용할 수 있다.

CREATE VIEW vActiveCustomerStatistics AS SELECT a.CustomerID, a.CustFirstName, a.CustLastName, s.LastOrderDate, s.GrandOrderTotal FROM vActiveCustomers AS a INNER JOIN vCustomerStatistics AS s ON a.CustomerID = s.CustomerID;

​

방법 19 비관계형 데이터를 정보성 데이터로 변환할 때는 ETL을 사용하자

추출(Extract), 변환(Transform), 로드(Load)를 의미하는 ETL은 외부 소수에 있는 데이터를 추출한 후 관계형 설계 규칙이나 다른 요구 사항에 맞게 변환하고, 분석이나 다른 목적으로 사용하려고 데이터베이스에 로드하는 일련의 과정을 의미한다. ETL 도구를 사용하면 비관계형 데이터를 적은 노력을 들여 관계형 데이터베이스에 가져올 수 있다.

SELECT CAST('2015-01-01' AS Date) AS SalesMonth, Product, Jan AS SalesAmt FROM tblPostSales UNION ALL SELECT CAST('2015-02-01' AS Date) AS SalesMonth, Product, Feb AS SalesAmt FROM tblPostSales UNION ALL SELECT CAST('2015-03-01' AS Date) AS SalesMonth, Product, Mar AS SalesAmt FROM tblPostSales UNION ALL SELECT CAST('2015-04-01' AS Date) AS SalesMonth, Product, Apr AS SalesAmt FROM tblPostSales UNION ALL SELECT CAST('2015-05-01' AS Date) AS SalesMonth, Product, May AS SalesAmt FROM tblPostSales UNION ALL SELECT CAST('2015-06-01' AS Date) AS SalesMonth, Product, Jun AS SalesAmt FROM tblPostSales UNION ALL SELECT CAST('2015-07-01' AS Date) AS SalesMonth, Product, Jul AS SalesAmt FROM tblPostSales UNION ALL SELECT CAST('2015-08-01' AS Date) AS SalesMonth, Product, Aug AS SalesAmt FROM tblPostSales UNION ALL SELECT CAST('2015-09-01' AS Date) AS SalesMonth, Product, Sep AS SalesAmt FROM tblPostSales UNION ALL SELECT CAST('2015-10-01' AS Date) AS SalesMonth, Product, Oct AS SalesAmt FROM tblPostSales UNION ALL SELECT CAST('2015-11-01' AS Date) AS SalesMonth, Product, Nov AS SalesAmt FROM tblPostSales UNION ALL SELECT CAST('2015-12-01' AS Date) AS SalesMonth, Product, Decm AS SalesAmt FROM tblPostSales;

방법 20 요약 테이블을 만들어 관리하자

요약 테이블은 집계에 필요한 쿼리를 최소화할 수 있다. 요약 테이블을 생성하면 필요한 데이터를 한 테이블에 저장할 수 있어 데이터 구조 파악이 쉽고 원하는 정보를 빠르게 파악할 수 있다. 트리거를 사용할 수 있지만 저장 프로시저나 배치 모듈을 사용하여 주기적으로 요약 테이블을 모두 삭제하고 다시 데이터를 생성하여 작업의 부하를 줄일 수 있다.

​

방법 21 비정규화된 데이터를 ‘언피벗’하려면 UNION 문을 사용하자

SalesSummary 테이블은 정규화 되지 않았다. UNION 쿼리를 사용하여 다른 컬럼의 이름을 통일하면 정규화된 데이터처럼 표시할 수 있다. UNION 쿼리를 사용하면 중복 ROW는 제거가 된다. 중복되는 ROW까지 추출하려면 UNION 대신 UNION ALL을 사용하면 된다.

SELECT Category, 'Oct' AS SalesMonth, OctQuantity AS Quantity, OctSales AS SalesAmt FROM SalesSummary UNION SELECT Category, 'Nov', NovQuantity, NovSales FROM SalesSummary UNION SELECT Category, 'Dec', DecQuantity, DecSales FROM SalesSummary UNION SELECT Category, 'Jan', JanQuantity, JanSales FROM SalesSummary UNION SELECT Category, 'Feb', FebQuantity, FebSales FROM SalesSummary ORDER BY SalesMonth, Category;

방법 22 관계 대수와 이를 SQL로 구현하는 방법을 이해하자

1\. 선택 - WHERE나 HAVING 절을 사용하여 반환되는 ROW를 선택한다.

2\. 추출 - 집계 함수와 GROUP BY 절을 사용하여 필요한 컬럼을 선택한다.

3\. 조인 - 키값으로 연결된 데이터나 테이블을 조인으로 연결하여 반환한다.

4\. 카티전곱 - 데이터 집합에 있는 모든 ROW를 결합한 결과를 반환한다.

5\. 교집합 - 컬럼이 동일한 두 집합에서 각 컬럼 값과 일치하는 ROW를 반환한다.

6\. 합집합 - 컬럼의 유형이 동일한 두 데이터 집합을 병합한다.

7\. 차집합 - 기본적으로 한 집합에서 다른 집합을 빼는 것이다.

8\. 나누기 - 나누기 연산은 몫과 나머지를 얻으려고 하는 것인데 구현된 상용 DBMS는 없다.

방법 23 일치하지 않거나 누락된 레코드를 찾아내자

서브쿼리에서 NOT IN이나 NOT EXISTS 연산자로 포함되지 않는 데이터를 조회할 수 있다.

SELECT P.ProductNumber, P.ProductName FROM Products AS P WHERE P.ProductNumber NOT IN (SELECT ProductNumber FROM Order_Details); SELECT P.ProductNumber, P.ProductName FROM Products AS P WHERE NOT EXISTS (SELECT * FROM Order_Details AS OD WHERE OD.ProductNumber = P.ProductNumber);

​

​방법 24 CASE로 문제를 해결해야 할 때를 파악하자

어떤 값이나 표현식이 정확한 결과를 산출하는지 검사를 해야 할 때 CASE를 사용한다. CASE는 IF - THEN - ELSE 문의 SQL 버전이다.

SELECT Products.ProductNumber, Products.ProductName, CASE WHEN (SELECT SUM(QuantityOrdered) FROM Order_Details WHERE (Order_Details.ProductNumber = Products.ProductNumber)) <= 200 THEN 'Poor' WHEN (SELECT SUM(QuantityOrdered) FROM Order_Details WHERE (Order_Details.ProductNumber = Products.ProductNumber)) <= 500 THEN 'Average' WHEN (SELECT SUM(QuantityOrdered) FROM Order_Details WHERE (Order_Details.ProductNumber = Products.ProductNumber)) <= 1000 THEN 'Good' ELSE 'Excellent' END FROM Products; ​

방법 25 다중 조건 문제를 해결하는 기법을 파악하자

관련된 테이블들에 여러 조건을 검사해야 하는 경우, 그 방법이 간단하지 한다. 서브쿼리와 IN, NOT IN을 사용하거나 EXISTS나 NOT EXIST를 사용하여 원하는 결과가 나오는지를 단계적으로 실행해 가며 작성하는 것이 좋다.

방법 27 날짜와 시간을 모두 포함하는 컬럼에서 날짜 범위를 올바르게 검색하는 방법을 알아 두자

날짜를 조건으로 검색하는 경우는 날짜 변환 함수를 사용하여 명시적인 조건으로 변환하는 것이 좋다. BETWEEN 대신 >=, <= 연산자를 사용한다.

SELECT L.LogUserID, L.Logger, L.LogLevel, L.LogMessage FROM ProgramLogs AS L WHERE L.LogDate >= CONVERT('2016-07-04', datetime) AND L.LogDate < CONVERT('2016-07-05', datetime);

방법 28 데이터베이스 엔진이 인덱스를 사용하도록 사거블 쿼리를 작성하자

DBMS 엔진이 인덱스를 잘 활용하려면 WHERE, ORDER BY, GROUP BY, HAVING 절이 인덱스를 사용하도록 해야 한다.

방법 29 LEFT 조인의 오른쪽 데이터를 올바르게 걸러 내자

조인을 하기 전에 조건을 검색하여 데이터를 걸러 내야 한다.

SELECT Customers.CustomerID, Customers.CustFirstName, Customers.CustLastName, OFiltered.OrderNumber, OFiltered.OrderDate, OFiltered.OrderTotal FROM Customers LEFT JOIN (SELECT Orders.OrderNumber, Orders.CustomerID, Orders.OrderDate, Orders.OrderTotal FROM Orders WHERE Orders.OrderDate BETWEEN CAST('2015-10-01' AS DATETIME) AND CAST('2015-12-31' AS DATETIME)) AS OFiltered ON Customers.CustomerID = OFiltered.CustomerID;

5장 집계

보고서 데이터를 생성하는데 집계 기능이 유용하다. GROUP BY와 HAVING 절을 사용하여 집계 기능을 사용한다. 좀 더 복잡한 집계 작업을 처리할 수 있는 윈도우 함수도 SQL 표준 협회에서 내놓았다. ROLLUP, CUBE, GROUPING SETS 기능을 사용하면 좀 더 복잡한 형태의 그루핑 연산을 수행할 수 있다.

​

방법 30 GROUP BY 절의 작동 원리를 이해하자

SELECT 컬럼1, 컬럼2, ... FROM 테이블 WHERE 검색조건 GROUP BY 그룹 표현식 HAVING 검색조건 ORDER BY 정렬 표현식

  1. FROM 절에서 데이터 집합을 만든다.

  2. 데이터 집합에서 WHERE 조건에 맞는 데이터를 걸러 낸다.

  3. WHERE 절에서 필터링 한 데이터 집합을 GROUP BY로 집계한다.

  4. GROUP BY로 집계한 데이터 집합을 HAVING 절의 조건에 맞게 필터링 한다.

  5. SELECT 절은 집계하고 필터링한 데이터 집합을 집계 함수로 처리한다.

  6. ORDER BY 절로 반환된 데이터 집합을 정렬한다.

방법 34 OUTER JOIN에서는 잘못된 결과를 내는 COUNT( ) 함수를 사용하지 말자

​방법 36 겹치지 않는 개수를 얻으려면 DISTINCT를 사용하자

COUNT(*) : 널 값과 중복된 값을 포함해 항목 개수를 반환
