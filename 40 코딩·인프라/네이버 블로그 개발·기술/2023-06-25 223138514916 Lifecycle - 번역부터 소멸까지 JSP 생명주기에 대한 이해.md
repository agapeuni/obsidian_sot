# 2023-06-25 223138514916 Lifecycle - 번역부터 소멸까지 JSP 생명주기에 대한 이해

- 원문: https://blog.naver.com/PostView.naver?blogId=agapeuni&logNo=223138514916&categoryNo=982
- 게시일: 2023. 6. 25. 22:24

## 본문

![](https://postfiles.pstatic.net/MjAyNTA0MTZfNjQg/MDAxNzQ0Nzg5OTAwMDgz._NL9z3pABtHYt0hAhwKpbrMgLzhE94xzRfNjCp9-ZWMg.ciw7ekxpxMpAsOEz0n0tKkIdHxAPIVXWVwWpdKG5OZEg.PNG/JSP-001_\(16\).png?type=w80_blur)

​

JSP(JavaServer Pages)의 생명주기는 JSP 페이지가 생성되어 실행되고 최종적으로 소멸되기까지의 일련의 과정을 의미하며, 이는 내부적으로 서블릿(Servlet)으로 변환되어 실행되는 JSP의 특성상 서블릿의 생명주기와 유사한 구조를 가진다. 아래에서는 JSP 생명주기의 각 단계를 단계별로 정리한다.

​

1\. JSP 번역(Translation)

클라이언트가 웹 서버에 요청을 보내면 해당 요청은 웹 컨테이너로 전달된다. 이때 JSP 파일이 기존의 서블릿 클래스보다 새롭게 수정된 경우, JSP 페이지는 다시 번역 과정을 거치게 된다. 반대로 변경 사항이 없을 경우 이 단계는 생략된다.

​

2\. JSP 컴파일(Compilation)

JSP 파일은 최초 요청 시 또는 수정 이후 컴파일된다. JSP 엔진은 JSP 페이지를 파싱하여 자바 서블릿 클래스(.java)로 변환한 뒤, 이를 컴파일하여 클래스(.class) 파일로 생성한다. 이 과정은 동적인 웹 콘텐츠를 제공하기 위한 기반 작업이 된다.

​

3\. 클래스 로딩(Class Loading)

컴파일이 완료된 서블릿 클래스는 클래스 로더에 의해 JVM 메모리로 로딩된다. 이를 통해 웹 애플리케이션 내에서 해당 JSP의 기능을 사용할 준비가 완료된다.

​

4\. 인스턴스화(Instantiation)

서블릿을 컴파일하고 나서 서블릿의 객체가 생성된다. 클래스가 로딩된 후, JSP 컨테이너는 해당 클래스로부터 인스턴스를 생성한다. 이 인스턴스는 JSP 페이지의 요청을 처리하는 데 사용되며, 이 시점에서 ServletConfig 및 ServletContext 객체에 접근할 수 있다.

​

5\. 초기화(Initialization)

인스턴스가 생성된 이후, JSP 컨테이너는 jspInit() 메서드를 호출하여 초기화를 수행한다. 이 단계에서는 데이터베이스 연결, 네트워크 리소스 할당 등 요청 처리에 필요한 초기 작업이 이루어진다.

​

6\. 서비스(Service)

서블릿 인스턴스 초기화 후 스레드가 생성된다. JSP 페이지는 클라이언트의 요청을 처리하기 위해 service() 메서드를 통해 응답을 생성한다. 이 메서드는 클라이언트 요청 시마다 호출되며, HTML 코드와 자바 코드가 결합된 동적인 웹 콘텐츠를 생성하여 클라이언트에 전달한다. service() 메서드는 요청이 있을 때마다 호출된다. JSP 생명주기에서 가장 핵심적인 단계이다.

​

7\. 소멸(Destruction)

JSP 인스턴스의 수명이 종료되면, JSP 컨테이너는 jspDestroy() 메서드를 호출하여 리소스를 정리한다. 이 단계에서는 데이터베이스 연결 해제, 네트워크 연결 종료 등의 작업을 통해 JSP 객체가 메모리에서 완전히 제거된다.

​

이와 같이 JSP의 생명주기는 사용자 요청에 따라 자동적으로 제어되며, 각 단계는 웹 애플리케이션의 성능과 안정성에 중요한 역할을 한다. JSP 기반의 웹 개발을 진행할 때 이러한 생명주기의 흐름을 정확히 이해하는 것은 매우 중요하다.
