​

Gradle은 JVM 기반 프로젝트의 빌드와 의존성 관리를 위해 널리 사용되는 도구로, 대규모 프로젝트에서 강력한 생산성을 제공한다. 소프트웨어 개발에 있어 빌드 구성은 이제 필수가 되었다. Gradle은 다양한 기본 태스크(task)를 제공하여 컴파일, 테스트, 클린, 배포 등을 손쉽게 수행할 수 있도록 한다. 

​

이번 글에서는 Gradle을 활용하여 Gradle 프로젝트를 배포하는 과정을 단계별로 설명한다. Gradle 프로젝트를 효율적으로 배포하기 위한 필수 단계를 다룬다. 배포를 자동화하고 유지보수를 단순화하기 위해 Gradle과 관련 도구들을 활용하면 편리하다.

​

​

**Gradle 태스크 확인**

Gradle에서 태스크는 프로젝트 빌드 과정에서 실행되는 작업 단위이다. Gradle은 다양한 태스크를 제공하며, 이를 통해 프로젝트 빌드, 테스트, 패키징, 배포 등의 작업을 자동화할 수 있다. 필요에 따라 새로운 태스크를 정의하거나 기본 태스크를 확장할 수 있다.

​

**Gradle 프로젝트 준비**

**1) Gradle 설정 파일 구성**

Gradle 프로젝트는 기본적으로 build.gradle 또는 build.gradle.kts 파일을 통해 설정된다.

​

  * **플러그인 적용:**

plugins { id 'java' id 'maven-publish' }

  * **의존성 설정:**

dependencies { implementation 'org.springframework:spring-core:5.3.12' testImplementation 'junit:junit:4.13.2' }

  * **버전 및 그룹 설정:**

group = 'com.example' version = '1.0.0'

​

**2) 프로젝트 빌드**

Gradle로 프로젝트를 빌드 하려면 아래 명령어를 실행한다. 이 명령어는 프로젝트를 컴파일하고 테스트를 실행한 뒤 결과물을 생성한다.

gradlew build

배포를 위한 환경 설정

**1) Maven Publish 플러그인**

maven-publish 플러그인은 프로젝트를 Maven Central Repository 또는 사설 Maven 저장소에 배포할 수 있도록 지원한다. 

​

설정은 다음과 같다.

publishing { publications { mavenJava(MavenPublication) { from components.java pom { name = 'MyLibrary' description = 'A sample library for demonstration' url = 'https://github.com/example/mylibrary' licenses { license { name = 'Apache-2.0' url = 'https://www.apache.org/licenses/LICENSE-2.0' } } developers { developer { id = 'developerId' name = 'Your Name' email = 'your.email@example.com' } } scm { connection = 'scm:git:git://github.com/example/mylibrary.git' developerConnection = 'scm:git:ssh://github.com/example/mylibrary.git' url = 'https://github.com/example/mylibrary' } } } } repositories { maven { url = uri("https://oss.sonatype.org/service/local/staging/deploy/maven2/") credentials { username = project.findProperty("ossrhUsername") ?: "" password = project.findProperty("ossrhPassword") ?: "" } } } }

​

**2) GPG 서명**

Maven Central Repository에 배포하려면 GPG 서명이 필요하다. signing 플러그인을 사용하여 설정한다.

signing { useInMemoryPgpKeys(findProperty("signing.keyId"), findProperty("signing.secretKeyRingFile"), findProperty("signing.password")) sign publishing.publications.mavenJava }

​

Gradle의 gradle.properties 파일에 인증 정보를 추가한다.

ossrhUsername=yourUsername ossrhPassword=yourPassword signing.keyId=yourKeyId signing.secretKeyRingFile=/path/to/secret-key.gpg signing.password=yourKeyPassword

​

**배포 과정**

**1) 테스트 배포**

Maven Central Repository의 Staging Repository를 통해 테스트 배포를 진행한다.

gradlew publish

**2) 배포 확인**

Sonatype Nexus Repository Manager에 접속하여 업로드된 아티팩트를 확인한다. 문제가 없으면 Staging Repository를 Release 한다.

​

**3) 최종 배포**

Release가 완료되면 Maven Central Repository에 아티팩트가 공개된다.

​

​

**추가 팁**

  * **Gradle Wrapper 사용:** Gradle Wrapper(gradlew)를 사용하면 프로젝트와 호환되는 Gradle 버전을 보장할 수 있다.

  * **CI/CD 통합:** Jenkins, GitHub, GitLab 등과 Gradle을 통합하여 자동 배포 프로세스를 구축하면 효율성이 높아진다.

  * **에러 디버깅:** 배포 중 발생하는 문제를 디버깅할 때 --info 또는 --debug 플래그를 사용하면 상세한 로그를 확인할 수 있다.

./gradlew publish --info
