# 2025-05-03 223854486953 PL SQL - 트리거(Trigger)

- 원문: https://blog.naver.com/PostView.naver?blogId=agapeuni&logNo=223854486953&categoryNo=982
- 게시일: 2025. 5. 3. 22:40

## 본문

![](https://postfiles.pstatic.net/MjAyNTA1MDNfOTAg/MDAxNzQ2MjY2MDk4Mzk0.ngjSQeiGvPIUE3SI2I74GtnUUTmqfl24bhIeuQ9ZAR0g.0LrsVZ6Gf69MascG36AzNqfVArtEJMzwPSRBWC7vgv8g.PNG/PL_SQL-001_\(13\).png?type=w80_blur)

**​**

Oracle 데이터베이스에서는 특정 이벤트가 발생하였을 때 자동으로 실행되는 프로시저를 트리거(Trigger)라 한다. 트리거는 사용자가 직접 호출하지 않아도 데이터 조작(INSERT, UPDATE, DELETE) 또는 객체 생성(CREATE, ALTER, DROP) 등의 이벤트가 발생할 경우 자동으로 실행되어 **데이터 무결성 유지, 보안 통제, 업무 규칙 실행, 변경 기록 보관 등** 다양한 목적을 수행한다.

**​**

**​**

**1\. 트리거란 무엇인가?**

트리거는 테이블이나 뷰와 같은 하나의 데이터베이스 오브젝트(Database Object)로 간주된다. 총기의 방아쇠(trigger)를 당기면 탄환이 발사되듯이, **특정 데이터베이스 이벤트가 발생할 때 자동으로 실행되는 로직** 을 의미한다. 사용자가 데이터를 삽입하거나 수정하는 등의 작업을 시도할 경우, 시스템은 미리 정의된 조건에 따라 트리거를 실행하며, 이를 통해 부적절하거나 허가되지 않은 데이터 변경을 사전에 차단할 수 있다.

**​**

**​**

**2\. 트리거의 실생활 예시**

예를 들어 Employee 테이블에 대해 DDL 권한(DROP, CREATE, ALTER 등)을 가진 사용자가 있다고 가정하자. 이 사용자가 자주 구조를 변경하여 시스템 안정성을 저해한다면, 직접 권한을 회수하는 것이 원칙일 수 있다. 그러나 해당 사용자가 반드시 테이블을 다뤄야 하는 업무를 맡고 있는 경우, **트리거를 이용하여 관리자 승인 없이 구조 변경을 막는 방법** 이 적절할 수 있다.

​

관리자는 트리거를 정의하여 Employee 테이블에 대해 DDL 작업이 발생할 경우, 에러 메시지를 출력하도록 설정한다. 이후 작업이 필요할 경우에는 트리거를 일시적으로 비활성화(DISABLE)하고, 작업이 완료되면 다시 활성화(ENABLE)하는 방식으로 제어할 수 있다.

**​**

**​**

**3\. 트리거의 주요 목적**

  * **업무 규칙 자동 실행**

  * **참조 무결성 유지**

  * **보안 정책 구현**

  * **변경 기록 관리 (Auditing)**

  * **자동 값 생성 (예: 대문자 변환)**

  * **데이터 복제 및 동기화**

**​**

**​**

**4\. 트리거의 종류**

Oracle에서는 다양한 유형의 트리거를 제공한다.

**구분** |  **설명**  
---|---  
DML 트리거 |  INSERT, UPDATE, DELETE 이벤트에 반응  
DDL 트리거 |  CREATE, ALTER, DROP 등의 객체 이벤트에 반응  
Instead-of 트리거 |  View에 대한 INSERT, UPDATE, DELETE 대응  
이벤트 트리거 |  LOGON, LOGOFF, STARTUP, SHUTDOWN 등 시스템 이벤트 대응  
  
**​**

**5\. 트리거의 구성 구문**

**1) DML 트리거 (행/문 단위)**

CREATE [OR REPLACE] TRIGGER 트리거이름 {BEFORE | AFTER} INSERT OR UPDATE OR DELETE ON 테이블명 [FOR EACH ROW] [WHEN (조건)] BEGIN \-- 트리거 실행 시 동작할 로직 END; 

​

**예제** : 부서명이 항상 대문자로 저장되도록 설정

CREATE OR REPLACE TRIGGER trg_upper_dept BEFORE INSERT OR UPDATE ON employee FOR EACH ROW BEGIN :NEW.dept_name := UPPER(:NEW.dept_name); END; 

​

**실행 결과** :

INSERT INTO employee(dept_name) VALUES ('finance'); SELECT dept_name FROM employee; \-- 출력: FINANCE 

**​**

**2) DDL 트리거**

CREATE [OR REPLACE] TRIGGER 트리거이름 {BEFORE | AFTER} CREATE OR ALTER OR DROP ON SCHEMA BEGIN \-- 동작 로직 END; 

**예제** : 특정 사용자 스키마에서 DROP 시도 시 차단

CREATE OR REPLACE TRIGGER prevent_drop BEFORE DROP ON SCOTT.SCHEMA BEGIN RAISE_APPLICATION_ERROR(-20001, '승인 없이 DDL 작업을 수행할 수 없습니다.'); END; 

**​**

**6\. 트리거의 실행 시점과 레벨**

**구분** |  **설명**  
---|---  
BEFORE |  SQL문 실행 전에 트리거 동작  
AFTER |  SQL문 실행 후에 트리거 동작  
Row-level |  각 행마다 개별적으로 트리거 실행  
Statement-level |  SQL문 전체에 대해 한 번만 트리거 실행  
  
**​**

**7\. 트리거 관리**

  * ALL_TRIGGERS 또는 USER_TRIGGERS 뷰를 통해 트리거 목록 및 본문 확인 가능

  * 트리거 비활성화/활성화

ALTER TRIGGER 트리거이름 DISABLE; ALTER TRIGGER 트리거이름 ENABLE; 

  * .sql 파일로 관리하여 재적용 시 쉽게 사용할 수 있도록 하는 것이 바람직함

**​**

**​**

**8\. 이벤트 트리거 예시 – DB 시작 및 종료 감지**

시스템 관리자가 수동으로 오라클을 시작하거나 종료할 경우 로그가 남지 않는 경우가 있다. 이러한 상황에서 다음과 같이 트리거를 정의하면, 이벤트 발생 시 로그 테이블에 기록을 남길 수 있다.

CREATE TABLE uptime_log ( database_name VARCHAR2(20), event_name VARCHAR2(20), event_time DATE, trigger_user VARCHAR2(30) ); 

CREATE OR REPLACE TRIGGER startup_log_trg AFTER STARTUP ON DATABASE BEGIN INSERT INTO uptime_log VALUES (sys.database_name, sys.sysevent, SYSDATE, sys.login_user); COMMIT; END; / CREATE OR REPLACE TRIGGER shutdown_log_trg AFTER SHUTDOWN ON DATABASE BEGIN INSERT INTO uptime_log VALUES (sys.database_name, sys.sysevent, SYSDATE, sys.login_user); COMMIT; END; / 

Oracle의 트리거는 **자동화된 감시자** 라고 할 수 있다. 데이터 변경 또는 객체 조작이 발생하는 순간 자동으로 실행되어, 데이터베이스의 **무결성, 일관성, 보안, 추적성** 을 유지하는 데 필수적인 도구로 활용된다.

​

특히 업무상 승인 절차, 데이터 감사(audit), 부정 변경 차단 등의 목적에서 실무적으로 매우 중요한 역할을 수행하므로, 트리거를 잘 설계하고 관리하는 것은 데이터베이스 품질을 유지하는 핵심 역량 중 하나라 할 수 있다.
