연말까지 조용히 지나가는가 했는데 아주 바빠지게 되었어요. 

​

개발팀 회의 끝나고 들은 건데. 내년에 바로 신성 물산 프로젝트에 투입될 수 있다고 하네요. 그래서 연말까지 회사에서 고객 구매 데이터를 활용한 인공지능 PoC 프로젝트를 수행해서 결과를 보고해야 해요.

​

![](https://postfiles.pstatic.net/MjAyNDEyMjVfMTY2/MDAxNzM1MTMyNjg0MDIx.Q02x6Q59Z-QASNt7fr4DF3dePiyZBG4HyTQNn-sQ2Iwg.VwClhDuqYx5MHfQ8VpcLGVdjcs9ORC7LmFy-YKR-444g.PNG/man_garo__00003_.png?type=w80_blur)

그래, 하나 씨. 나도 조금 전에 웨이 과장님에게 들었어.

PoC 프로젝트이니 너무 부담 갖지 말고 차분하게 준비해 봐. 고객 구매 데이터와 인공지능을 활용하려면 공부는 좀 해야겠네.

​

부담이 될 수도 있겠지만 이런 일을 통해 하나 씨 능력도 향상시키고 회사에 어필할 수도 있고 좋은 기회라 생각해봐. 진행하다가 어렵거나 힘든 일이 있으면 부담 없이 물어보구.

​

​

![](https://postfiles.pstatic.net/MjAyNDEyMjVfMTE1/MDAxNzM1MTMzMTg4ODUx.sKCU3ReFsdEAWdwbqc-zOodrTQfOJL523MU5O1Vmp4sg.OyqtDQ9Yjr1U8oIpSqrbXl6gseUNzN7CAm6qKSvQmSwg.PNG/ComfyUI_temp_jbusa_00039_.png?type=w80_blur)

네, 말씀만이라도 고맙습니다. 

그런데 한길 대리님은 그런 경우 없었나요. 프로젝트 형상관리를 위해 회사 github 사용하다 보면 어느 순간 작성하던 소스코드가 갑자기 사라져서 맨붕인 경우가 있어요. 

​

애써 작성한 코드가 git 명령어로 한 번에 사라지면 손에 힘이 풀려버려요.

지난주에도 git reset 한번 했다가 오전 내내 작성한 코드가 날아갔어요. ㅠㅠ

​

​

![](https://postfiles.pstatic.net/MjAyNDEyMjVfMTI1/MDAxNzM1MTMzMjIwMzQ1.bUTxBhIVegDBPW0IxqwQkOZuwVYdLCmzuR3KwCHHv3Qg.qN2bvVO0BvuxOtx1YBYGp6vxKtlois5a-MmoYdNh1lsg.PNG/man_garo__00043_.png?type=w80_blur)

어이구 많이 속상했겠네. 

​

하나씨 이야기를 들어보니 아무래도 git reset 옵션을 잘 못 준거 같은 생각이 드는데...

git reset 명령어를 실행할 때 어떤 옵션을 주는지에 따라 결과가 아주 달라져.

​

git을 잘 사용하고 있으니 작업 디렉터리, 스테이지 영역, 저장소 개념은 잘 알고 있을 거 같고. 

​

​

![](https://postfiles.pstatic.net/MjAyNDEyMjVfMTAg/MDAxNzM1MTM0NTgyNDc1.Yx1XHCshXUQOMQ7A314lr9L8vV5poDwsZWAmMIVXUJYg.ypb6ELNVUC-z8WBKNWCLRpRa3VU4Z-O-4yC_F6cp3FUg.PNG/ComfyUI_temp_jbusa_00036_.png?type=w80_blur)

git reset 명령어에 --hard 옵션을 사용했어요. 

\--hard 옵션을 사용하면 작업 디렉터리가 해당 커밋의 상태로 완전히 바뀐다고 해서...

​

작성 중인 소스코드를 안전하게 잘 보관하려면, git reset --hard 명령을 사용하기 전에 소스코드를 다른 곳에 임시로 백업을 해두어야 하나요?

​

​

​

![](https://postfiles.pstatic.net/MjAyNDEyMjVfODUg/MDAxNzM1MTM0ODI5MzEy.1H9EjAslwQk5SwzJwbF5uOWKnpsgkNOxml5r0z_1JBkg.D--dsTMWB1h77nWdDAXkBW-CM_DesM-Er8aCfYvyLV8g.PNG/man_garo__00009_.png?type=w80_blur)

그럴 필요는 없어. git reset에는 --hard, --soft, --mixed 3가지 옵션이 있어. 이 옵션들은 작업 디렉터리, 스테이지 영역에 미치는 영향이 달라.

​

HEAD가 과거의 커밋을 가리키게 되는 점은 동일하지만, 작업 디렉터리가 과거 커밋 상태로 바뀌는 것은 --hard 옵션을 사용할 때만 발생해. --soft와 --mixed는 작업 디렉터리를 유지하고. 

​

git reset에 대해 명확히 알고 싶으면 아래에 주소를 남겨놓을게.

​

![](https://postfiles.pstatic.net/MjAyNDEyMjVfNzQg/MDAxNzM1MTM1MjU4Nzkw.kT7tsA_YKcExZblOAAvsRvO-4FTSy8pZHogV3fYWYxEg.vxJCoDELmtiPB3rQSsxPRbtg42XAUO8UM-elChHrz60g.PNG/ComfyUI_temp_jbusa_00040_.png?type=w80_blur)

저와 같은 상황에선 --soft 옵션이나 --mixed 옵션을 사용했어야 했네요.

간단히 정리해 보면 soft reset은 커밋만 되돌리는 것이고, mixed reset은 커밋과 스케이지만 되돌리는 것이네요. hard reset은 커밋과 스테이지 그리고 작업 디렉토리까지 모두 되돌리니, 작성한 소스코드가 사라진거네요.
