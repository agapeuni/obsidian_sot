1\. Docker Compose 

Docker Compose는 여러 개의 Docker 컨테이너를 쉽게 관리하고 실행할 수 있는 도구로, 복잡한 시스템을 관리를 편리하게 해준다.

​

기본적으로 Docker 컨테이너는 필요한 애플리케이션과 종속성을 모두 포함하여 실행되어 소프트웨어를 어디서든 실행할 수 있도록 해줍니다. 그러나 마이크로 서비스 아키텍처와 같이 여러 개의 컨테이너로 구성된 복잡한 시스템을 다루게 되면, 각각의 컨테이너를 개별적으로 관리하기 어려울 수 있다.

​

이때 Docker Compose가 해결책을 제공한다. Docker Compose를 사용하면 각 컨테이너의 설정을 정의하고, 한 번에 여러 개의 컨테이너를 실행하고 관리할 수 있다. 이를 통해 여러 개의 컨테이너로 구성된 복잡한 시스템을 간편하게 관리할 수 있다.

​

Docker Compose는 **docker-compose.yml** 파일을 사용하여 컨테이너의 설정을 정의한다. 이 파일에는 각 컨테이너의 이미지, 포트 매핑, 환경 변수 등을 설정할 수 있다. 이후에는 `docker-compose up` 명령을 사용하여 설정된 모든 컨테이너를 한 번에 실행할 수 있다.

​

​

2\. docker-compose.yml

파일 : docker-compose.yml

version: '3' services: kanban-postgres: image: "postgres:9.6-alpine" container_name: kanban-postgres volumes: \- kanban-data:/var/lib/postgresql/data ports: \- 5432:5432 environment: \- POSTGRES_DB=kanban \- POSTGRES_USER=kanban \- POSTGRES_PASSWORD=kanban kanban-app: build: ./kanban-app container_name: kanban-app environment: \- DB_SERVER=kanban-postgres \- POSTGRES_DB=kanban \- POSTGRES_USER=kanban \- POSTGRES_PASSWORD=kanban ports: \- 8080:8080 links: \- kanban-postgres kanban-ui: build: ./kanban-ui container_name: kanban-ui ports: \- 4200:80 links: \- kanban-app volumes: kanban-data: 

**1) 공통**

version: `3` |  Compose 파일의 버전을 나타낸다.  
---|---  
services : |  이 변수 뒤에는 실행하려는 모든 서비스를 정의할 수 있다. 칸반보드 프로젝트에는 3개가 있다.  
  
​

**2) kanban-postgres:**

kanban-postgres: image: "postgres:9.6-alpine" container_name: kanban-postgres volumes: \- kanban-data:/var/lib/postgresql/data ports: \- 5432:5432 environment: \- POSTGRES_DB=kanban \- POSTGRES_USER=kanban \- POSTGRES_PASSWORD=kanban 

image |  컨테이너의 기반이 될 Docker 이미지를 정의한다. Docker Hub에서 가져온 Postgres 이미지이다. 알파인 버전은 일반적인 버전보다 훨씬 작다.  
---|---  
container_name |  결과 컨테이너의 이름을 지정한다.  
volumes |  데이터베이스의 데이터 저장소로 처리되는 Docker 볼륨을 나타낸다. kanban-data는 첫 번째 Compose 실행 중에 생성될 볼륨의 이름이다. Docker 컨테이너 내부의 디렉터리를 가리키고 있다. (/var/lib/postgresql/data )  
ports |  PC의 포트(5432)를 컨테이너의 노출된 포트(5432)에 매핑한다.  
environment |  Docker 컨테이너 내부에 포함될 환경 변수를 정의할 수 있다.  
  
​

**3) kanban-app:**

kanban-app: build: ./kanban-app container_name: kanban-app environment: \- DB_SERVER=kanban-postgres \- POSTGRES_DB=kanban \- POSTGRES_USER=kanban \- POSTGRES_PASSWORD=kanban ports: \- 8080:8080 links: \- kanban-postgres

build |  이미 준비된 Docker 이미지를 사용하는 대신 Compose는 Dockerfile을 기반으로 이미지를 생성한다. kanban-app Spring Boot 앱의 코드가 있는 폴더에 있다 .  
---|---  
container_name |  컨테이너의 이름을 표현한다.  
environment |  환경 변수로 데이터베이스 연결 속성 파일에 사용된다.  
ports |  호스트 포트를 컨테이너 포트에 매핑합니다.  
links |  데이터베이스 서비스에 대한 종속성을 표현한다. (kanban-postgres)  
  
​

kanban-app Spring Boot 앱의 코드가 있는 폴더에 Dockerfile

### STAGE 1: Build ### FROM maven:3.6.1-jdk-8-slim AS build RUN mkdir -p /workspace WORKDIR /workspace COPY pom.xml /workspace COPY src /workspace/src RUN mvn -f pom.xml clean package ### STAGE 2: Run ### FROM openjdk:8-alpine COPY --from=build /workspace/target/*.jar app.jar EXPOSE 8080 ENTRYPOINT ["java","-jar","app.jar"]

Dockerfile은 두 가지 빌드 단계로 구성된다. 첫 번째 단계에서는 앱의 코드가 jar 파일로 컴파일되고, 두 번째 단계에서는 jar 파일이 복사된 다음 새 컨테이너에서 실행된다. 각 단계는 서로 다른 Docker 이미지이지만 마지막 이미지만 결과로 사용된다. 이런 접근 방식을 사용하는 이유는 결과 Docker 컨테이너를 최대한 가볍게 만드는 것이다. 즉, 소스 코드 없이 컴파일된 jar 파일만 포함한다.

**4) kanban-ui:**

이 서비스의 정의에는 특별히 새로운 것이 없다. 

이전과 유사하게 호스트의 4200 포트가 컨테이너의 80 포트에 매핑되고 links는 백엔드 서비스를 정의한다.

kanban-ui: build: ./kanban-ui container_name: kanban-ui ports: \- 4200:80 links: \- kanban-app

​

기본 Docker 이미지를 빌드해야 하며 Dockerfile은 kanban-ui와 함께 Angular 코드가 있는 폴더에 있다. 두 가지 빌드 단계가 있는데, 첫 번째는 컴파일을 위한 것이고 두 번째는 컴파일된 프로젝트를 실행하기 위한 것이다. 그리고 애플리케이션이 nginx 서버에서 실행되고 있기 때문에 일부 기본 구성도 추가되어 있다. 

### STAGE 1: Build ### FROM node:12.7-alpine AS build WORKDIR /usr/src/app COPY package.json ./ RUN npm install COPY . . RUN npm run build ### STAGE 2: Run ### FROM nginx:1.17.1-alpine COPY default.conf /etc/nginx/conf.d/default.conf COPY --from=build /usr/src/app/dist/kanban-ui /usr/share/nginx/html EXPOSE 80

version: `3` |  Compose 파일의 버전을 나타낸다.  
---|---  
services : |  이 변수 뒤에는 실행하려는 모든 서비스를 정의할 수 있다. 칸반보드 프로젝트에는 3개가 있다.

3\. Kanban Board

칸반은 Toyota 자동차에 처음 도입된 도구이다. 칸반 보드는 작업 관리를 위해 널리 사용되는 소프트웨어이다.

Docker Compose를 사용하여 단일 명령으로 프런트엔드, 백엔드, 데이터베이스 컨테이너를 한 번에 실행해 보자. 3개의 Docker 컨테이너가 성공적으로 실행되면, 칸반 애플리케이션을 실행할 수 있다.

​

칸반 보드는 3개의 Docker 이미지로 구성된다.

  * kanban-ui — 프런트엔드 애플리케이션, 백엔드 서비스에서 제공하는 REST 엔드포인트를 사용한다.

  * kanban-app — Java 기반 애플리케이션. 데이터베이스에 연결하고 Spring Boot 로 작성된 REST 엔드포인트를 노출한다.

  * kanban-postgres — PostgreSQL 데이터베이스. 칸반보드 데이터를 저장한다.
