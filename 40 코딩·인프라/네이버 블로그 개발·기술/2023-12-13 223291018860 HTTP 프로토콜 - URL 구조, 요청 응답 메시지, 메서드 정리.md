**1\. HTTP(Hypertext Transfer Protocol)**

HTTP는 인터넷에서 데이터를 송수신하는 데 사용되는 프로토콜이다. 프로토콜은 통신규약으로 상호 간에 특정 목적을 위해 약속한 규칙을 정의한다. TCP/IP 위에서 HTML, 이미지, 음성, 동영상 등을 전송하기 위해 정의되었다. HTTP 프로토콜을 통해 웹 브라우저에서 인터넷 페이지들을 접근할 수 있다.

​

HTTP 프로토콜은 상태를 저장하지 않아 이전의 요청과 현재의 요청과의 관계를 알지 못한다. 데이터를 주고받기 위해 각각의 요청이 독립적으로 수행된다. 클라이언트(Client)에서 서버(Server)로 요청(Request)을 보내고 서버는 요청을 처리하여 적절한 응답(Response)을 클라이언트에게 반환한다.

​

​

**2\. URL(Uniform Resource Locators)**

URL은 웹에서 리소스를 고유하게 식별하는 주소이다. URL은 아래와 같은 형식으로 구성한다.

[URL] protocol://host:port/path-and-file?query \- protocol : 클라이언트와 서버에서 사용하는 응용 프로그램 프로토콜 \- host : 서버의 DNS 도메인 이름 또는 IP 주소 \- port : 서버가 클라이언트로부터 들어오는 요청을 수신하는 TCP 포트 번호 \- path-and-file : 서버 디렉토리 아래에서 요청 된 자원의 이름 및 위치 \- query : 사용자 입력 파라미터를 전달 [URL Example] http://www.domain.com:8080/search.do?name=web&type=http ftp://www.ftp.org/docs/test.txt mailto:user@test101.com news:soc.culture.Singapore telnet://www.nowhere123.com/

​

**3\. HTTP 요청(Request) 메시지**

브라우저의 주소 입력란에 URL을 입력하면 브라우저는 지정된 프로토콜에 따라 입력된 URL을 HTTP 요청 메시지로 변환하여 서버로 보낸다. HTTP 요청 메시지는 메시지 헤더와 메시지 본문으로 구성되고 빈 출로 구분을 한다.

​

예를 들어 브라우저에서 URL을 [http://www.test.com/doc/index.html](http://www.test.com/doc/index.html%EB%9D%BC%EA%B3%A0) 라고 입력하면 아래와 같이 변환한다.

GET /docs/index.html HTTP/1.1 Host: www.test.com Accept: image/gif, image/jpeg, */* Accept-Language: en-us Accept-Encoding: gzip, deflate User-Agent: Mozilla/4.0 (compatible; MSIE 6.0; Windows NT 5.1) (blank line)

​

HTTP 요청 메시지의 첫 줄은 "요청메소드명(Request Method Name) 요청 URI(Request URI) HTTP 버전(HTTP Version)"으로 되어 있다.​

GET /test.html HTTP/1.1 HEAD /query.html HTTP/1.1 POST /index.html HTTP/1.1

​

​

**4\. HTTP 응답(Response) 메시지**

요청 메시지가 서버에 도착하면 서버는 수신된 요청 메시지를 해석하여 서버의 파일이나 프로그램의 실행 결과를 응답메시지로 반환한다.

HTTP 응답 메시지도 HTTP 요청 메시지와 같이 메시지 헤더와 메시지 본문으로 구성되고 빈 출로 구분을 한다.

​

클라이언트에 보내는 HTTP 응답 메시지는 다음과 같다. 브라우저에서 응답 메시지를 받으면 적절한 결과를 화면에 표시한다.

HTTP/1.1 200 OK Date: Sun, 18 Oct 2019 08:56:53 GMT Server: Apache/2.2.14 (Win32) Last-Modified: Sat, 20 Sep 2020 07:16:26 GMT ETag: "10000000565a5-2c-3e94b66c2e680" Accept-Ranges: bytes Content-Length: 44 Connection: close Content-Type: text/html X-Pad: avoid browser bug <html><body><h1>It works!</h1></body></html>

​

HTTP 응답 메시지의 첫 줄은 "HTTP 버전(Version) 상태 코드(Status Code) 상태 메시지(Reason Phrase)"로 되어 있다.

HTTP/1.1 200 OK HTTP/1.0 404 Not Found HTTP/1.1 403 Forbidden

​

​

**5\. HTTP 요청 메서드(Request Methods)**

![](https://postfiles.pstatic.net/MjAyMzEyMTNfMjI1/MDAxNzAyNDA4NTc0MDE2.ePVbDF6aIQqN0hruTbtvfTZH0gNDAM6SD1A_l5ujlWwg.OiPw1rKVd45omCUoE1EqEZ9LQX6LwKAjJDHJqIcv5jEg.JPEG.agapeuni/img1.daumcdn.jpg?type=w80_blur)

URL을 이용하여 서버에 데이터를 요청할 때 수행할 동작을 HTTP 요청 메서드로 정의할 수 있다.

웹에서는 주로 GET과 POST를 사용하고 OPEN API 나 RESTful 방식으로 구현할 때는 GET, POST, PUT, DELETE를 사용한다.

GET : 서버에 존재하는 자원을 가져온다. (SELECT) POST : 서버에 새로운 데이터를 게시한다. (INSERT) PUT : 서버에 존재하는 데이터를 변경한다. (UPDATE) DELETE :서버에 존재하는 데이터를 삭제한다. (DELETE) HEAD : (HTTP) 헤더 정보를 요청한다. OPTIONS : 웹서버가 지원하는 메서드의 종류를 요청한다. TRACE : 클라이언트의 요청을 그대로 반환한다. CONNECT : 프록시가 사용하는 요청이다.

​

​

**6\. HTTP 프로토콜 전송과정**

정리해 보면 HTTP(HyperText Transfer Protocol) 프로토콜을 사용하여 클라이언트에서 HTTP 요청 메시지로 요청 메서드와 URL을 보내면 서버가 처리하여 상태 코드와 HTTP 응답 메시지를 반환한다.

​

클라이언트와 서버 간에 데이터를 전송하는 과정은 다음과 같다.

​

1) 클라이언트 요청

클라이언트(일반적으로 웹 브라우저)가 서버에 데이터를 요청한다. 이 요청은 HTTP Request 메시지에 담겨져 있다. 요청 메시지는 일반적으로 요청하는 리소스의 URL과 함께 전송된다.

​

2) 서버 응답

서버는 클라이언트의 요청을 받고, 해당하는 리소스에 대한 응답을 생성한다. 이 응답은 HTTP Response 메시지에 담겨져 있다. 응답 메시지는 일반적으로 상태 코드, 헤더, 그리고 요청한 리소스의 데이터로 구성된다.

​

3) 데이터 전송

클라이언트와 서버 간에 데이터가 전송된다. 이때, 전송되는 데이터는 HTTP 메시지의 본문(body)에 포함된다. 클라이언트는 응답을 받아들이고, 필요에 따라 화면에 표시하거나 다운로드한다.

​

4\. 연결 종료

데이터 전송이 완료되면, 클라이언트와 서버 간의 연결이 종료된다. 이 과정에서 일반적으로 TCP/IP 연결이 닫힌다.
