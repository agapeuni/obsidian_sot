1\. 아이노드 (Inode)

리눅스 파일 시스템에서 아이노드(Inode)는 파일에 대한 메타데이터를 저장하는 데이터 구조다. 아이노드 번호는 파일 시스템 내에서 고유하다. 파일의 실제 데이터는 아이노드가 가리키는 데이터 블록에 저장된다. 파일 이름은 아이노드에 포함되지 않는다. 파일 이름은 디렉터리 엔트리(덴트리, Dentry)에 의해 관리된다. 

​

아이노드에는 다음과 같은 정보가 포함된다.

  * 파일의 크기: 파일의 바이트 크기를 저장한다.

  * 파일의 소유자: 파일을 소유한 사용자의 ID를 저장한다.

  * 파일의 권한: 읽기, 쓰기, 실행 권한을 나타낸다.

  * 파일의 유형: 디렉터리, 일반 파일, 심볼릭 링크 등 파일의 유형을 정의한다.

  * 파일의 생성, 수정, 접근 시간: 각각의 타임스탬프를 기록한다.

  * 파일의 데이터 블록 주소: 파일의 실제 데이터가 저장된 블록들의 위치 정보를 포함한다.

​

stat 명령어는 파일의 상세한 정보를 표시하는 명령어이다. stat 명령어로 Inode 값을 확인할 수 있다.

sgkim@3d:~$ stat hello.sh File: hello.sh Size: 26 Blocks: 8 IO Block: 4096 regular file Device: fd00h/64768d Inode: 7340832 Links: 1 Access: (0775/-rwxrwxr-x) Uid: ( 1001/ sgkim) Gid: ( 1001/ sgkim) Access: 2024-10-05 08:45:38.681348359 +0900 Modify: 2024-10-05 08:43:28.390760784 +0900 Change: 2024-10-05 08:45:35.233279627 +0900 Birth: 2024-10-05 08:43:28.390760784 +0900 sgkim@3d:~$

​

​

2\. 덴트리 (Dentry)

덴트리(Dentry, Directory Entry)는 파일 이름과 아이노드 번호 간의 연결을 나타낸다. 디렉터리 안에 파일이 존재할 때, 그 파일의 이름은 덴트리에 저장되며, 덴트리는 해당 파일의 아이노드를 가리킨다. 

​

덴트리는 파일의 계층 구조를 유지하는 역할을 담당한다. 디렉터리 자체도 파일이므로, 디렉터리 역시 아이노드와 덴트리를 가지고 있다. 덴트리는 파일의 경로 탐색 시 중요한 역할을 하며, 빠른 파일 이름 해석을 위해 캐시된다. 

​

*** 덴트리 역할**

\- 파일 이름 관리: 디렉터리 안에서 파일의 이름을 관리한다.

\- 아이노드 연결: 파일 이름을 해당 파일의 아이노드 번호와 연결한다.

​

​

3\. 하드 링크 (Hard Link)

하드 링크는 하나의 파일에 대해 여러 개의 파일 이름을 만들 수 있게 해주는 기능이다. 파일을 연결한다기 보다는 또 하나의 클론을 만들다고 생각하면 된다. 즉, 하나의 아이노드 번호를 여러 개의 파일 이름으로 연결하는 것이다.

​

  * 같은 아이노드 공유: 하드 링크는 원본 파일과 동일한 아이노드를 가리킨다.

  * 동일한 파일: 원본 파일과 하드 링크 파일은 사실상 동일한 파일이며, 하나에서 수정한 내용은 다른 파일에서도 반영된다.

  * 독립적인 파일 이름: 파일을 삭제할 때, 모든 하드 링크가 삭제되지 않는 한, 데이터는 삭제되지 않는다.

  * 제한사항: 하드 링크는 같은 파일 시스템 내에서만 생성할 수 있다.

​

file1에 대한 하드 링크를 file2로 생성

ln file1 file2 

​

​

4\. 소프트 링크 (Soft Link 또는 Symbolic Link)

소프트 링크(심볼릭 링크)는 파일 또는 디렉터리의 경로를 가리키는 별칭이다. 즉, 원본 파일의 위치 정보를 포함한 특수한 파일이다.

​

  * 다른 아이노드 사용: 소프트 링크는 원본 파일과 다른 아이노드를 가진다.

  * 경로를 참조: 원본 파일의 경로를 저장하고 그 경로를 참조한다.

  * 파일 삭제 시: 원본 파일이 삭제되면 소프트 링크는 유효하지 않게 된다(죽은 링크, dead link).

  * 파일 시스템 간 링크 가능: 소프트 링크는 다른 파일 시스템이나 다른 파티션에 있는 파일을 가리킬 수 있다.

​

file에 대한 소프트 링크 생성

ln -s /path/to/file link_name 

​

*** 하드 링크와 소프트 링크의 차이점**

**특징** |  **하드 링크** |  **소프트 링크**  
---|---|---  
**아이노드 공유** |  동일한 아이노드를 공유 |  다른 아이노드를 사용  
**파일 시스템 내 제한** |  같은 파일 시스템에서만 가능 |  다른 파일 시스템 간에도 가능  
**파일 삭제 시** |  하나의 링크가 삭제되어도 파일은 남음 |  원본 파일이 삭제되면 링크 깨짐
