6장 서브쿼리

서브쿼리는 괄호 안에 완전한 SELECT 문을 넣고 이름을 붙여 생성한 테이블 표현식이다. 컬럼 한 개나 0개를 반환하거나 값을 한 개만 반환하는 서브쿼리는 컬럼 이름 한 개나 단일 값을 사용할 수 있는 곳에서 활용할 수 있다.

​

​

방법 40 서브쿼리를 어디에 사용할 수 있는지 알아 두자

완전한 SELECT 문을 괄호로 둘러싸고 괄호 밖에는 AS 절과 함께 별칭을 주는 것이다.

​

테이블 서브쿼리

SELECT BeefRecipes.RecipeTitle FROM (SELECT Recipes.RecipeID, Recipes.RecipeTitle FROM (Recipes INNER JOIN Recipe_Ingredients ON Recipes.RecipeID = Recipe_Ingredients.RecipeID) INNER JOIN Ingredients ON Ingredients.IngredientID = Recipe_Ingredients.IngredientID WHERE Ingredients.IngredientName = 'Beef') AS BeefRecipes INNER JOIN (SELECT Recipe_Ingredients.RecipeID FROM Recipe_Ingredients INNER JOIN Ingredients ON Ingredients.IngredientID = Recipe_Ingredients.IngredientID WHERE Ingredients.IngredientName = 'Garlic') AS GarlicRecipes ON BeefRecipes.RecipeID = GarlicRecipes.RecipeID;

​

단일 컬럼 테이블 서브쿼리

SELECT Products.ProductName FROM Products WHERE Products.ProductNumber NOT IN (SELECT Order_Details.ProductNumber FROM Orders INNER JOIN Order_Details ON Orders.OrderNumber = Order_Details.OrderNumber WHERE Orders.OrderDate BETWEEN '2015-12-01' AND '2015-12-31');

​

스칼라 서브쿼리​

SELECT Products.ProductNumber, Products.ProductName, (SELECT MAX(Orders.OrderDate) FROM Orders INNER JOIN Order_Details ON Orders.OrderNumber = Order_Details.OrderNumber WHERE Order_Details.ProductNumber = Products.ProductNumber) AS LastOrder FROM Products;

​

방법 41 연관성 있는 서브쿼리와 연관성 없는 서브쿼리의 차이점을 파악하자

연관성 있는 서브쿼리는 WHERE 절이나 HAVING 절에서 주 쿼리가 제공하는 값에 의존하는 조건을 하나 이상 사용하는 쿼리이다. 데이터베이스 엔진은 주 쿼리에서 반환되는 모든 ROW에서 서브쿼리를 한 번씩 실행해야 한다.

SELECT Recipe_Classes.RecipeClassDescription, (SELECT COUNT(*) FROM Recipes WHERE Recipes.RecipeClassID = Recipe_Classes.RecipeClassID) AS RecipeCount FROM Recipe_Classes;

연관성 없는 서브쿼리는 바깥쪽에 반환되는 값에 의존하지 않고 독립적으로 수행될 수 있다. 연관성 없는 서브쿼리는 FROM 절의 데이터 집합, IN 조건에 쓸 단일 컬럼 데이터 집합, WHERE 또는 HAVING 절의 비교 조건에 스칼라 값을 반환하는 데 사용된다.

​

​

방법 42 가능하면 서브쿼리 대신 공통 테이블 표현식(CTE)을 사용하자

CTE를 잘 사용하면 코드양이 줄고 간략하게 된다. CTE를 여러 개 만들어 한 CTE 내에서 다른 CTE를 참조할 수 있다. MySQL은 공통 테이블 표현식(CTE)을 지원하지 않는다. 대신 VIEW를 사용할 수 있지만 관리하기가 어렵다.

WITH SeqNumTbl(SeqNum) AS (SELECT 1 FROM dual UNION ALL SELECT SeqNum + 1 AS SeqNum FROM SeqNumTbl WHERE SeqNum < 100) SELECT SeqNum FROM SeqNumTbl;

​

​

방법 43 서브쿼리 대신 조인을 사용해 더 효율적인 쿼리를 작성하자

서브쿼리에 있는 테이블 크기가 아주 작은 것이 아니라면 조인을 사용하는 것이 효율적이다. 데이터베이스 엔진은 조인에 대한 최적화를 잘 수행한다.

SELECT StyleNm FROM Styles WHERE CountryFK IN (SELECT CountryID FROM Countries WHERE CountryNM = 'Belgium'); SELECT S.StyleNm FROM Styles AS S INNER JOIN Countries AS C ON S.CountryFK = C.CountryID WHERE C.CountryNM = 'Belgium';

​

7장 메타데이터 획득 및 분석

데이터의 데이터인 메타데이터가 필요할 때가 있고 데이터를 가져오는 방식과 관련된 데이터가 필요할 때가 있다. 몇몇 DBMS에서는 SQL로 메타데이터를 가져올 수 있다.

​

​

방법 44 사용 중인 시스템의 쿼리 분석기 사용법을 파악하자

SQL을 실행하기 전에 DBMS의 옵티마이저는 최적으로 수행할 수 있는 방법을 결정한다. 실행 계획을 생성해서 이를 결정하는데, 실행 계획에 따라 SQL문은 단계적으로 수행된다. MySQL에서는 EXPLAIN 단어를 SQL 문 앞에 두면 실행 계획을 만들 수 있다.

EXPLAIN SELECT CustomerID, Sum(OrderTotal) FROM Orders GROUP BY CustomerID;

​

​

방법 45 데이터베이스 관련 메타데이터를 수집하는 방법을 배우자

데이터베이스 정보를 제공할 때 대부분은 SQL 표준인 INFORMATION_SCHEMA 뷰에서 필요한 정보를 가져온다. INFORMATION_SCHEMA는 DBMS마다 다를 수 있다.

​

​

방법 46 실행 계획의 작동 원리를 이해하자

SQL 쿼리를 최적화하거나, 인텍스나 모델 설계에서 필요한 스키마 변경을 수행할 수 있도록 실행 계획을 읽는 방법과 실행 계획의 의미를 이해해야 한다. 실행 계획을 읽을 때는 데이터베이스 엔진이 어떻게 데이터를 수집하며, 가장 효율적인 방식으로 처리하려고 올바른 실행 계획을 선택하는지 점검해야 한다. 데이터를 가져오는 최상의 방법을 찾는 것은 옵티마이저에게 일임하는 것이 좋다.

​

9장 탤리 테이블

탤리 테이블은 보통 1부터 시작해 상황에 맞는 최대 수까지 일련번호 값이 있는 단일 컬럼으로 구성된다.

​

방법 51 매개변수를 기준으로 널 로우를 만들려면 탤리 테이블을 사용하자

보고서용 데이터를 가져올 때 널이나 빈 ROW를 생성할 수 있으면 매우 유용하다.

SELECT ' ' AS CustName, ' ' AS CustStreetAddress, ' ' AS CustCityState, ' ' AS CustZipCode FROM ztblSeqNumbers WHERE Sequence <= 3 UNION ALL SELECT CONCAT(C.CustFirstName, ' ', C.CustLastName) AS CustName, C.CustStreetAddress, CONCAT(C.CustCity, ', ', C.CustState, ' ', C.CustZipCode) AS CustCityState, C.CustZipCode FROM Customers AS C ORDER BY CustZipCode;​

방법 55 날짜 계산을 쉽게 하려면 날짜 테이블을 사용하자

날짜와 시간은 다루기 까다로운 데이터 타입이다. 사용하려고 하는 날짜 테이블을 미리 만들고 사용하면 편리하다. 예를 들면 1년 치 날짜 데이터를 만들면서 달, 월, 요일, 주차 등을 미리 생성한다. 날짜 계산을 많이 수행하는 로직을 탤리 테이블을 사용해 아주 간단하게 만들 수 있다.

​

방법 56 특정 범위에 있는 모든 날짜를 나열한 일정 달력을 만들자

방법 57 탤리 테이블로 데이터를 피벗하자

피벗 대상 데이터에 대해 컬럼 범위를 결정하는 값이 가변적이라면, 탤리 테이블을 사용해 SQL을 간단히 만드는 것이 좋다.

10장 계층형 데이터 모델링

방법 58 인접 리스트 모델을 시작점으로 사용하자

모든 직원에게는 관리자가 있다. 관리자도 직원에 속하며 그에게도 관리자가 있을 수 있다. 이럴 경우 자기 참조를 해서 기본키에 외래키 제약 조건이 있는 테이블을 만들어 처리하면 된다. 이처럼 일관된 계층형 구조를 만들 때는 인접 리스트 모델을 사용한다.

​

​

방법 59 자주 갱신되지 않는 데이터의 쿼리 성능을 빠르게 하려면 중첩 집합을 사용하자

중첩 집합 모델을 이용하면 Left와 Right 개수를 계산할 수 있어서 통계 정보를 효율적으로 관리할 수 있다. 데이터가 자주 갱신되면 중첩 집합 모델이 적합하지 않다. 빈번한 변경으로 인해 교착 상태에 빠지기 쉽다.

​

​

구체화된 경로(Materialized Path)는 중첩 집합에 비해 설정도 간단하고 이해하기 훨씬 쉽다. 개념적으로 파일 시스템 경로와 동일하다.
