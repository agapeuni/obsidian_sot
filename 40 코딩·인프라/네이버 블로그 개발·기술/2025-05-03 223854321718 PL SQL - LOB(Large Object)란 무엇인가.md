# 2025-05-03 223854321718 PL SQL - LOB(Large Object)란 무엇인가

- 원문: https://blog.naver.com/PostView.naver?blogId=agapeuni&logNo=223854321718&categoryNo=982
- 게시일: 2025. 5. 3. 16:00

## 본문

![](https://postfiles.pstatic.net/MjAyNTA1MDNfMTA1/MDAxNzQ2MjUxOTY2NzY2.osDTIH5C8lMGLZhiSZfPUWzfXgWOOFtlRwmH8GkJXkog.FEmj25dgXss4R_v2Vjn3fWH1xNmeimVU2L9NecJBpMUg.PNG/PL_SQL-001_\(5\).png?type=w80_blur)

​

현대의 데이터베이스 환경에서는 단순한 숫자나 문자열 외에도 이미지, 문서, 오디오 파일 등 다양한 형식의 대용량 데이터를 함께 다루는 경우가 많아지고 있다. 오늘날의 데이터베이스 환경에서는 단순한 텍스트나 숫자 데이터 외에도 이미지, 동영상, 오디오 파일 등 다양한 형태의 대용량 비정형 데이터를 저장하고 처리할 필요성이 점점 커지고 있다. 

​

이러한 데이터를 효과적으로 관리하기 위하여 Oracle 데이터베이스에서는 LOB(Large Object)라는 데이터 유형을 제공하고 있다. LOB의 개념과 종류, 저장 방식, 내부 LOB 관리 방법, 그리고 CLOB 컬럼을 활용한 실습 예제에 이르기까지 구체적으로 살펴보자.

**​**

**1\. LOB이란 무엇인가?**

LOB은 "Large Object"의 약어로, 대용량의 비정형 데이터를 저장하기 위한 데이터 유형을 의미한다. 일반적으로 데이터베이스 테이블에 저장되는 데이터는 비교적 크기가 작고 구조화되어 있으나, 텍스트 문서, 이미지, 오디오, 동영상 등은 크기가 크고 구조화되지 않아 기존의 데이터 타입으로는 처리에 한계가 있다. 이에 따라 LOB은 이러한 데이터를 효율적으로 저장하고 접근할 수 있도록 설계되었다.

​

예전에는 LONG, LONG RAW와 같은 유형이 사용되었으나, 이들은 기능적 제약이 많아 현재는 대부분의 경우 LOB 유형으로 대체되고 있다. 기존 LONG 또는 LONG RAW 데이터를 LOB으로 변환하고자 할 때에는 TO_LOB 함수를 사용할 수 있다.

**​**

**​**

**2\. LOB의 종류**

Oracle 데이터베이스에서는 다음과 같은 네 가지 주요 LOB 유형을 제공한다.

**​**

**1) CLOB (Character Large Object)**

문자 기반의 대용량 데이터를 저장하는 데 사용된다. Oracle은 CLOB과 VARCHAR2 사이의 암시적 형 변환을 지원한다.

**​**

**2) BLOB (Binary Large Object)**

이미지, 동영상, 오디오 파일 등 이진 데이터를 저장하는 데 적합하다.

**​**

**3) NCLOB (National Character Large Object)**

내셔널 문자셋(National Character Set)을 사용하는 문자 데이터를 위한 LOB 유형이다.

**​**

**4) BFILE**

데이터베이스 외부의 운영체제 파일 시스템에 저장된 이진 파일의 경로 정보를 저장한다. 해당 파일은 읽기 전용 모드로 접근할 수 있다.

**​**

**​**

**3\. LOB의 저장 방식**

LOB 데이터는 저장 위치에 따라 내부 저장 방식과 외부 저장 방식으로 구분된다.

**​**

**1) 내부 저장 (BLOB, CLOB, NCLOB)**

데이터베이스 테이블에 LOB 컬럼을 생성한 후, 해당 컬럼에는 LOB 데이터의 실제 위치를 가리키는 위치자(Locator)가 저장된다. 데이터 자체는 별도의 LOB 저장 공간에 저장된다.

​

**2) 외부 저장 (BFILE)**

BFILE은 운영체제 파일 시스템 상에 존재하는 파일의 경로와 이름을 데이터베이스에 저장하며, 이 파일은 읽기 전용으로만 접근 가능하다.

**​**

**​**

**4\. LOB의 특징**

LOB 유형의 주요 특징은 다음과 같다.

  * 하나의 테이블에 다수의 LOB 컬럼을 정의할 수 있다.

  * 최대 약 4GB의 데이터를 저장할 수 있다.

  * SELECT 문을 이용하여 위치자를 반환받고 이를 통해 데이터를 참조할 수 있다.

  * 데이터를 순서대로 또는 순서를 고려하지 않고 저장할 수 있으며, 임의 위치 접근이 가능하다.

​

LOB은 데이터 자체가 테이블에 직접 저장되지 않으며, 테이블의 해당 컬럼에는 위치자만이 존재한다는 점에서 일반적인 데이터 유형과 차별된다.

**​**

**​**

**5\. 내부 LOB 관리 방식**

내부 LOB은 데이터베이스 내부에 저장되며, 다양한 프로그래밍 방법을 통해 접근 및 조작이 가능하다. 

대표적인 관리 절차는 다음과 같다.

  1. LOB 데이터 유형을 포함하는 테이블을 생성한다.

  2. 프로그램 상에서 LOB 위치자를 선언하고 초기화한다.

  3. SELECT FOR UPDATE 문을 이용하여 해당 행을 잠근 뒤, 위치자를 획득한다.

  4. 획득한 위치자를 이용하여 DBMS_LOB 패키지, Oracle Call Interface(OCI), JDBC 등의 방법으로 LOB 데이터를 조작한다.

  5. 조작 후에는 COMMIT 문을 사용하여 변경 사항을 적용한다.

​

LOB 데이터는 유형에 따라 다음과 같이 해석된다.

  * **BLOB** : 비트 스트림으로 해석됨

  * **CLOB** : 단일 바이트 문자 스트림으로 해석됨

  * **NCLOB** : 내셔널 문자셋 기반의 멀티바이트 문자 스트림으로 해석됨

**​**

**​**

**6\. CLOB 실습 예제**

다음은 CLOB 타입의 컬럼을 포함한 테이블을 생성하고, 데이터를 삽입하는 예제이다.

CREATE TABLE CAR ( id NUMBER(6) PRIMARY KEY NOT NULL, name VARCHAR2(20), price NUMBER(10), review CLOB ); INSERT INTO CAR VALUES (100, 'SM7', 25000000, '삼성에서 나온 SM7을 타보니 정말 편안했다.'); INSERT INTO CAR VALUES (200, 'PORTER', 13000000, '역시 1톤트럭의 대표자!!'); INSERT INTO CAR VALUES (300, 'VERNA', 9000000, '싸고 좋은 거 같아용~^^*'); INSERT INTO CAR VALUES (400, 'SANTAFE', 33000000, EMPTY_CLOB()); 

  * review 컬럼은 CLOB 타입으로 선언되어 있으며, 대용량 텍스트 데이터를 저장하는 데 활용된다.

  * EMPTY_CLOB() 함수는 위치자를 초기화하는 데 사용되며, 초기값이 없는 상태로 설정된다.

​

※ 참고로, BLOB 타입은 SQL*Plus에서 직접 조회가 불가능하며, 다음과 같은 오류가 발생할 수 있다.

SP-0678: Column or attribute type can not be displayed by SQL*Plus 

**​**

**7\. 고객 리뷰 저장 – CLOB 활용**

전자상거래 플랫폼에서 사용자들이 상품에 대해 장문의 후기를 남길 수 있도록 시스템을 설계하고자 할 때, 일반적인 VARCHAR2 데이터형은 문자 수 제한으로 인해 적합하지 않다. 이 경우에는 CLOB(Character Large Object) 유형을 사용하여 수천 자 이상의 텍스트를 무리 없이 저장할 수 있다.

​

**테이블 생성시**

CREATE TABLE USER_PROFILE ( user_id NUMBER PRIMARY KEY, username VARCHAR2(50), photo BLOB ); 

​

**데이터 삽입 예시**

INSERT INTO PRODUCT_REVIEW (review_id, product_id, reviewer, review_text) VALUES ( 1, 101, '홍길동', '이 제품을 사용해 본 결과 매우 만족스러웠습니다. 기능이 다양하고 사용법도 직관적이어서 초보자도 쉽게 활용할 수 있습니다...' ); 

CLOB 타입을 사용하면 게시판, 제품 리뷰, 고객 상담 기록 등 다양한 형태의 텍스트 기반 데이터를 손쉽게 저장하고 관리할 수 있다.

**​**

**​**

**8\. 사용자 프로필 사진 저장 – BLOB 활용**

웹 애플리케이션에서 사용자 프로필 이미지를 데이터베이스 내부에 저장하고자 할 경우, 이진 데이터를 처리할 수 있는 BLOB(Binary Large Object) 유형을 사용하는 것이 일반적이다. BLOB은 이미지, 오디오, 영상 등 바이너리 형태의 데이터를 손실 없이 저장할 수 있다.

**​**

**테이블 생성**

CREATE TABLE USER_PROFILE ( user_id NUMBER PRIMARY KEY, username VARCHAR2(50), photo BLOB ); 

**이미지 삽입 (PL/SQL 예시)**

DECLARE img BLOB; v_file BFILE := BFILENAME('PROFILE_DIR', 'user1001.jpg'); BEGIN INSERT INTO USER_PROFILE (user_id, username, photo) VALUES (1001, 'johndoe', EMPTY_BLOB()) RETURNING photo INTO img; DBMS_LOB.OPEN(v_file, DBMS_LOB.LOB_READONLY); DBMS_LOB.LoadFromFile(img, v_file, DBMS_LOB.GETLENGTH(v_file)); DBMS_LOB.CLOSE(v_file); COMMIT; END; 

이와 같은 방식은 사용자 정보와 이미지를 하나의 테이블에서 통합 관리할 수 있게 하며, 이미지 파일의 외부 유실을 방지하고 보안성도 향상시킨다.

**​**

**​**

**9\. 전자문서 저장 시스템 – CLOB과 BLOB의 혼합 활용**

기업 내에서 전자결재 시스템을 구축하는 경우, 문서 본문과 첨부파일을 함께 저장하고자 할 때 CLOB과 BLOB을 혼합하여 사용하는 방식이 적절하다. 문서의 본문은 문자 기반이므로 CLOB으로 저장하고, 첨부파일(PDF, 엑셀 등)은 BLOB으로 저장함으로써 하나의 테이블 내에서 통합적으로 관리할 수 있다.

**​**

**테이블 생성**

CREATE TABLE APPROVAL_DOC ( doc_id NUMBER PRIMARY KEY, title VARCHAR2(200), content CLOB, attachment BLOB, uploaded_at DATE DEFAULT SYSDATE ); 

이러한 구조는 문서 저장과 검색, 이력 관리 등을 일괄적으로 처리할 수 있는 전자문서 시스템에 매우 유용하게 사용된다.

**​**

**​**

**10\. LOB 활용 요약**

**유형** |  **주요 용도** |  **특징**  
---|---|---  
CLOB |  장문 텍스트(리뷰, 게시판, 문서 등) |  수천 자 이상의 문자열 저장 가능  
BLOB |  이미지, 오디오, 파일 등 |  이진 데이터 저장, 외부 파일과 동일 형태  
BFILE |  외부 파일 참조용 |  읽기 전용, OS 파일 시스템 연동  
  
LOB은 현대 데이터베이스 환경에서 대용량 비정형 데이터를 효과적으로 관리하기 위한 핵심 기능 중 하나이다. 내부 저장 방식과 외부 저장 방식의 특성을 이해하고, 각 유형별 LOB 데이터를 적절히 활용함으로써, 멀티미디어를 포함한 다양한 응용 시스템에서 데이터 저장과 접근의 효율성을 높일 수 있다.

​

LOB 데이터 유형은 현대 애플리케이션에서 대용량 텍스트 및 바이너리 데이터를 효율적으로 관리하기 위한 강력한 도구이다. 시스템의 특성과 요구사항에 따라 적절한 LOB 유형을 선택하고 활용한다면, 데이터 무결성을 유지하면서도 다양한 기능을 확장할 수 있다.
