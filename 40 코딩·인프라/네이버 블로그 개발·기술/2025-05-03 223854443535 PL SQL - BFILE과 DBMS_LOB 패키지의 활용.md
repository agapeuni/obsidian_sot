# 2025-05-03 223854443535 PL SQL - BFILE과 DBMS_LOB 패키지의 활용

## 본문

![](https://postfiles.pstatic.net/MjAyNTA1MDNfMTU3/MDAxNzQ2MjU0MTQxNjI3.veSfcbIYHCVpOv6GsO8Xj3otJzXLNIrnZFjZoxECq_0g.gQxFUDCW8EM1bofBJ2Q0b_QlUsCTR1ALMZBz29Urxdwg.PNG/PL_SQL-001_\(6\).png?type=w80_blur)

​

Oracle 데이터베이스는 구조화된 데이터를 저장하고 처리하는 데 매우 강력한 기능을 제공하지만, 때로는 데이터베이스 외부에 저장된 파일을 참조해야 할 필요도 있다. 예를 들어, 대용량 이미지, PDF, 동영상 파일 등을 직접 데이터베이스 내부에 저장하지 않고 파일 시스템에 저장하면서도 이를 데이터베이스를 통해 관리하고자 할 때, Oracle에서는 BFILE 데이터 유형과 DBMS_LOB 패키지를 활용할 수 있다. 본문에서는 BFILE의 개념부터 관련 함수 및 프로시저, 실습 예제까지 구체적으로 살펴보고자 한다.

**​**

**​**

**1\. BFILE이란 무엇인가?**

BFILE은 Oracle 데이터베이스에서 외부 운영체제 파일에 대한 참조를 가능하게 해주는 데이터 유형이다. 일반적인 LOB(CLOB, BLOB, NCLOB)와 달리 BFILE은 파일 자체를 데이터베이스에 저장하지 않으며, 단지 외부 파일의 위치 정보만을 저장하여 이를 읽기 전용으로 접근할 수 있다.

​

**BFILE의 주요 특징은 다음과 같다:**

  * **외부 파일 참조** : BFILE은 Oracle 데이터베이스 외부의 운영체제(OS)에 위치한 파일에 접근하며, 파일의 경로와 이름은 디렉토리 오브젝트를 통해 지정된다.

  * **읽기 전용** : BFILE은 읽기만 가능하며, 데이터 삽입이나 수정은 지원하지 않는다.

  * **트랜잭션 비지원** : COMMIT 또는 ROLLBACK과 같은 트랜잭션 제어가 적용되지 않는다.

  * **파일 핸들링 주의 필요** : 다수의 파일을 동시에 열 경우 too many files open 오류가 발생할 수 있으며, 이를 방지하기 위해 SESSION_MAX_OPEN_FILES 파라미터를 조정해야 한다.

  * **파일은 반드시 닫아야 함** : 파일을 열었다면 사용 후 반드시 명시적으로 닫아야 한다.

**​**

**​**

**2\. 디렉토리 오브젝트**

BFILE을 사용하기 위해서는 먼저 Oracle에서 운영체제의 실제 경로를 참조할 수 있는 *디렉토리 오브젝트(Directory Object)*를 생성해야 한다. 이는 실제 경로 자체를 직접 다루는 것이 아니라, 해당 경로에 대한 추상적 참조를 가능하게 해주는 역할을 한다.

CREATE OR REPLACE DIRECTORY poster_dir AS '/export/home/oracle/plsql'; 

다른 사용자에게 해당 디렉토리에 대한 접근 권한을 부여하고자 할 경우, 다음과 같이 권한을 설정할 수 있다.

GRANT READ ON DIRECTORY poster_dir TO some_user; 

※ 디렉토리 생성자가 자기 자신에게 권한을 부여하려 할 경우 오류가 발생할 수 있으므로 주의가 필요하다.

**​**

**​**

**3\. DBMS_LOB 패키지를 통한 BFILE 처리**

Oracle에서는 DBMS_LOB 패키지를 통해 BFILE을 비롯한 다양한 LOB 객체를 제어할 수 있다. BFILE 관련 주요 함수 및 프로시저는 아래와 같다.

**기능** |  **함수/프로시저** |  **설명**  
---|---|---  
BFILENAME |  Function |  BFILE Locator 생성  
FILEOPEN |  Procedure |  파일 열기  
FILECLOSE |  Procedure |  파일 닫기  
FILECLOSEALL |  Procedure |  모든 열린 파일 닫기  
FILEEXISTS |  Function |  파일 존재 여부 확인 (1: 존재, 0: 없음)  
FILEISOPEN |  Function |  파일이 열려 있는지 여부 확인  
FILEGETNAME |  Procedure |  디렉토리 오브젝트 및 파일명 반환  
COMPARE |  Function |  두 개의 LOB 비교 (0: 동일, 그 외: 다름)  
GETLENGTH |  Function |  LOB의 크기를 byte 단위로 반환  
INSTR |  Function |  특정 패턴 검색 및 위치 반환  
READ |  Procedure |  LOB의 데이터를 메모리로 읽어오기  
SUBSTR |  Function |  지정한 범위의 데이터를 추출하여 반환  
  
**​**

**4\. 실습 예제: 외부 이미지 파일에 접근하기**

다음은 Oracle의 DBMS_LOB 패키지를 이용하여 외부 파일에 접근하고 정보를 확인하는 PL/SQL 예제이다. 본 실습에서는 OS에 존재하는 이미지 파일을 대상으로 한다.

DECLARE v_Imagefile BFILE; v_Dirname VARCHAR2(30); v_Location VARCHAR2(1000); v_Fileisopen INTEGER; v_Fileexists INTEGER; BEGIN \-- 외부 이미지 파일 지정 v_Imagefile := BFILENAME('POSTER_DIR', 'bourne_1.jpg'); \-- 파일 존재 여부 확인 v_Fileexists := DBMS_LOB.FILEEXISTS(v_Imagefile); IF v_Fileexists = 1 THEN DBMS_OUTPUT.PUT_LINE('File Exists!!'); ELSE DBMS_OUTPUT.PUT_LINE('File could not found!!'); END IF; \-- 파일 열림 여부 확인 v_Fileisopen := DBMS_LOB.FILEISOPEN(v_Imagefile); IF v_Fileisopen = 1 THEN DBMS_OUTPUT.PUT_LINE('File is already Open!!'); ELSE DBMS_OUTPUT.PUT_LINE('File is not open!!'); DBMS_LOB.FILEOPEN(v_Imagefile); END IF; \-- 디렉토리 오브젝트 및 파일 이름 출력 DBMS_LOB.FILEGETNAME(v_Imagefile, v_Dirname, v_Location); DBMS_OUTPUT.PUT_LINE('The Directory Object is: ' || v_Dirname); DBMS_OUTPUT.PUT_LINE('The File Name is: ' || v_Location); \-- 파일 닫기 DBMS_LOB.FILECLOSE(v_Imagefile); END; / 

​

**실행 결과**

File Exists!! File is not open!! The Directory Object is: POSTER_DIR The File Name is: bourne_1.jpg 

​

​

다음은 **Oracle BFILE을 실무에 적용할 수 있는 실용적인 예제** 입니다. 실제 업무에서 많이 활용되는 시나리오를 바탕으로 구성하였습니다. 모든 내용은 문어체로 서술하였습니다.

**​**

**​**

**5\. 실용적인 예제: 문서 저장 시스템에서 첨부파일 메타데이터 관리**

한 기업에서는 전자결재 시스템을 통해 **결재문서와** 함께 첨부파일(PDF, 이미지 등)을 업로드한다. 첨부파일 자체는 파일 시스템(서버 디렉토리)에 저장하고, Oracle 데이터베이스에서는 해당 파일의 메타데이터만 관리한다. 이때 Oracle의 **BFILE** 을 사용하면 외부 파일을 효율적으로 관리할 수 있다.

**​**

**1) 디렉토리 오브젝트 생성**

우선, 서버에 저장된 파일들이 위치하는 경로를 Oracle에 알려주기 위해 디렉토리 오브젝트를 생성한다.

CREATE OR REPLACE DIRECTORY doc_dir AS '/data/attachments'; GRANT READ ON DIRECTORY doc_dir TO hr_user; 

※ 실제 파일은 /data/attachments 디렉토리에 저장되어 있어야 하며, Oracle 프로세스가 해당 경로에 접근 가능해야 한다.

**​**

**​**

**2) 테이블 생성: 첨부파일 메타데이터 관리**

파일 자체는 외부에 두고, 데이터베이스에서는 메타정보만 저장한다.

CREATE TABLE doc_attachments ( attach_id NUMBER PRIMARY KEY, doc_id NUMBER, file_name VARCHAR2(255), file_ref BFILE, upload_date DATE DEFAULT SYSDATE ); 

​

**3) BFILE 참조 삽입**

외부 파일을 참조하는 BFILE 타입의 데이터를 삽입한다. 이때 BFILENAME 함수를 사용한다.

INSERT INTO doc_attachments (attach_id, doc_id, file_name, file_ref) VALUES ( 1, 20240501, 'approval_form.pdf', BFILENAME('DOC_DIR', 'approval_form.pdf') ); 

​

**4) PL/SQL로 파일 상태 확인 및 경로 출력**

아래는 PL/SQL을 사용하여 파일의 존재 여부를 확인하고, 디렉토리 오브젝트명과 파일 이름을 출력하는 예제이다.

DECLARE v_file BFILE; v_exists INTEGER; v_isopen INTEGER; v_dir VARCHAR2(100); v_name VARCHAR2(255); BEGIN SELECT file_ref INTO v_file FROM doc_attachments WHERE attach_id = 1; v_exists := DBMS_LOB.FILEEXISTS(v_file); IF v_exists = 1 THEN DBMS_OUTPUT.PUT_LINE('✅ 파일이 존재합니다.'); ELSE DBMS_OUTPUT.PUT_LINE('❌ 파일이 존재하지 않습니다.'); RETURN; END IF; v_isopen := DBMS_LOB.FILEISOPEN(v_file); IF v_isopen = 0 THEN DBMS_LOB.FILEOPEN(v_file); END IF; DBMS_LOB.FILEGETNAME(v_file, v_dir, v_name); DBMS_OUTPUT.PUT_LINE('디렉토리 오브젝트: ' || v_dir); DBMS_OUTPUT.PUT_LINE('파일 이름: ' || v_name); DBMS_LOB.FILECLOSE(v_file); END; / 

​

**5) 사용 시 유의사항**

  * Oracle은 BFILE에 대해 **읽기 전용** 액세스만 허용한다.

  * 파일이 삭제되거나 이름이 변경되면 Locator는 유효성을 잃게 된다.

  * 하나의 세션에서 열 수 있는 파일 수에는 제한이 있으므로, FILEOPEN 이후 반드시 FILECLOSE를 호출해야 한다.

  * 파일 내용은 필요시 DBMS_LOB.READ나 GETLENGTH, SUBSTR 등의 함수로 부분 읽기가 가능하다.

**​**

**6) 실무 활용 포인트**

**활용 예** |  **설명**  
---|---  
전자문서 시스템 |  결재 서식, PDF, 워드 문서 등의 외부 파일을 추적 및 확인  
의료영상 관리 |  CT, MRI 등 대용량 이미지 파일에 대한 참조 및 메타관리  
학사행정 시스템 |  학생 증명서, 성적표 PDF 저장 및 추적  
대용량 로그 분석 |  외부에서 수집된 로그 파일을 Oracle에서 참조하여 분석  
  
**​**

Oracle의 **BFILE** 은 외부 파일 시스템에 저장된 대용량 파일을 데이터베이스 내에서 효과적으로 관리하고자 할 때 유용한 도구이다. Oracle 데이터베이스가 외부 파일 시스템의 데이터를 읽기 전용으로 참조할 수 있다. 내부 공간을 절약하면서도 파일의 존재 여부나 메타 정보를 추적할 수 있어, 다양한 시스템에서의 문서 및 미디어 관리에 이상적인 방식이 될 수 있다. 다만, 트랜잭션 미지원, 읽기 전용 제약 등 몇 가지 주의할 점이 있으므로, 이러한 특성을 충분히 이해하고 사용하는 것이 바람직하다.

​

DBMS_LOB 패키지와의 연계 사용을 통해 파일 열기, 닫기, 길이 확인, 데이터 읽기 등 다양한 작업이 가능하며, 이를 통해 외부 미디어나 문서 파일을 효과적으로 관리할 수 있다.
