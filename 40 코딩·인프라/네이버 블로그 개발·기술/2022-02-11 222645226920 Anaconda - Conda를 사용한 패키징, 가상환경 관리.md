1\. Conda 개요

![](https://postfiles.pstatic.net/MjAyMjAyMTFfMTY5/MDAxNjQ0NTg0MDgyOTY4.Iyga5VvOIMn26vVyO1_EiGEOEiIg_UwVLMkjo35jWhAg.5evgN4bROvzjowg9s2K7MsQILTlmeHodz3tW_eN5lA8g.PNG.agapeuni/1.png?type=w80_blur)

파이썬, R, 루비, 루아, 스칼라, 자바, 자바스크립트, C/C++ 언어를 위한 패키지, 의존성 및 환경 관리 도구

​

Conda는 Window, Mac OS, Linux에서 실행되는 오픈소스 패키지 및 환경 관리 시스템이다. 파이썬 패키지를 빠르게 설치하고 업데이트 할 수 있다. Conda를 사용하면 파이썬 뿐만 아니라 다른 언어로 된 소프트웨어도 패키징하고 배포할 수 있다. Conda 패키지 및 환경 관리자는 Anaconda와 Miniconda의 모든 버전에 기본적으로 포함되어 있다. Conda는 Anaconda에서 구축, 검토 및 유지 관리하는 7,500 개 이상의 패키지를 설치하고 관리 할 수 있다.

2\. Conda 패키지

Conda 패키지는 플랫폼 간의 종속성(의존성)을 추적한다. Conda 패키지는 압축된 tarball 파일이나 ".conda" 파일이다.

conda 4.7 이상에서는 패키지의 .conda 파일 형식과 충돌하므로 ".conda"로 끝나는 패키지 이름을 사용할 수 없다. 

Conda 패키지 구조 . ├── bin │ └── pyflakes ├── info │ ├── LICENSE.txt │ ├── files │ ├── index.json │ ├── paths.json │ └── recipe └── lib └── python3.5

\- bin 디렉토리는 패키지에 대한 바이너리가 포함되어 있다.

\- lib 디렉토리는 관련 라이브러리 파일이 포함되어 있다.

\- info 디렉토리는 패키지에 대한 모든 메타 데이터가 포함되어 있다.

​

Noarch 패키지는 아키텍처에 특정한 패키지가 아니므로 한 번만 빌드하면된다.

Noarch 일반 패키지를 사용하면 사용자가 conda 패키지의 문서, 데이터 세트 및 소스 코드를 배포 할 수 있다.

​

​

3\. Conda 디렉토리

ROOT_DIR : Anaconda가 설치

/envs : conda 가상환경

/Lib : 라이브러리 설치

/Lib/site-packages : 패키지 설치

/pkgs : conda 환경에서 링크하는 패키지가 포함

/Scripts : 실행파일

​

​

4\. Conda 채널

Conda 채널은 패키지가 저장되는 위치이다. 패키지 호스팅 및 관리를 위한 기반 역할을 한다. Conda 패키지는 Conda 패키지를 포함하는 디렉토리에 대한 URL을 원격 채널에서 다운로드된다. 기본 채널 세트를 검색하고 패키지는 <https://repo.anaconda.com/pkgs/> 에서 자동으로 다운로드 및 업데이트된다.

​

명령 줄에서 --channel 사용

$ conda install mypkg -c c:/channel

$ conda install scipy --channel conda-forge

$ conda install scipy --channel conda-forge --channel bioconda

$ conda search scipy --channel file:/<path to>/local-channel --override-channels

​

​

5\. Conda 설치

conda 패키지를 설치하려면 터미널 또는 Anaconda 프롬프트에서 실행한다.

​

$ conda search 패키지명

$ conda install 패키지명

$ conda build 패키지명 (conda-build 설치필요)

​

​

**Conda 패키지 설치 순서**

1\. 설정된 각 채널에 대해 repodata를 가져온다.

​

2\. 요청한 패키지를 repodata와 일치하는지 시도한다.

2-1. 일치하지 않으면 패키지가 설치되지 않음

2-2. 일치하면 요청한 패키지의 의존성을 찾는다.

​

3\. 더 많은 의존성이 존재하는지 확인

3-1. 없으면 요청한 패키지를 다운로드하고 설치한다.

3-2. 있으면 repodata에서 의존성을 검색한다.

​

4\. 모든 의존성을 찾았나?

4-1. 아니면 설치하지 않고 에러메시지를 던진다.

4-2. 찾았으면 패키지를 다운로드 하고 설치한다.

​

오프라인 설치

conda install /path-to-package/package-filename.tar.bz2/

conda install -c numba/label/dev llvmlite=0.31.0dev0=py37_8

​

6\. Conda 가상환경

파이썬에서 작업하다 보면 패키지 의존성 문제 및 다양한 환경적인 문제가 생긴다. 간단한 작업으로 해결되는 경우도 있지만 때로는 많은 시간과 노력에도 불구하고 문제를 해결하지 못하는 경우가 있다. 그래서 파이썬에서는 패키지 버전관리 및 의존정 문제로 인해 독립적인 작업환경을 만들게 되는데 이것을 가상환경이라고 부른다. 

> 가상환경이란?
> 
> 파이선 프로젝트를 진행할 때 파이썬 버전과 라이브러리 버전들을 독립적으로 관리하여 시스템 개발시 버전으로 인한 충돌을 방지하는 격리된 실행 환경을 의미한다.

**6.1 Conda 가상환경 생성**

Conda에서는 conda 명령어로 새로운 Conda 가상환경을 만든다. --name 뒤에 가상환경 이름을 두고 Python 버전을 지정하면 된다.

$ conda create --name py39 python=3.9
