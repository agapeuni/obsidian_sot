**1\. XML 문서**

XML 스펙에 정의된 문법과 규칙에 대해 살펴보자. 

XML 문서를 작성할 때 문법과 규칙을 준수하는 것이 바람직하다. 

<?xml version="1.0" encoding="euc-kr"?> <birth> <!-- 월 --> <month>03</month> <!-- 일 --> <day>02</day> </birth>

**2\. XML의 문법**

2.1 XML 태그

'<'와 '>' 사이의 단어는 XML 태그이다. XML 태그는 짝을 이루고 있다. 요소의 시작 태그와 끝 태그 사이에 들어 있는 텍스트는 요소 콘텐츠(element content)라고 부른다. 태그 사이에 있는 콘텐츠는 대부분의 경우 데이터로 정보는 시작 태그와 끝 태그 사이에 담기게 된다. 요소 콘텐츠는 파싱 된 문자 데이터(Parsed Character DATA)라고 부른다. 줄여서 PCDATA라고 한다.

​

2.2 XML 요소 이름 작성규칙

\- 시작 문자 가능 ' 문자, '_'

\- 시작 문자 불가능 ' 숫자, xml

\- 첫 문자 뒤에는 '-'나 '.', 숫자를 사용할 수 있다.

\- 이름은 공백을 포함할 수 없다.

\- ':'를 포함하지 말자. 예약어이다.

\- 대소문자를 확실히 구분한다.

\- 여는 문자('<') 뒤에 공백을 두면 안 된다.

​

2.3 XML 선언

문서가 어떤 특정한 타입이라고 알려줄 수 있는 것은 종종 매우 유용하다. XML은 파서에게 몇 가지 정보를 알려줌으로써 XML이 어떤 문서인지를 알려 줄 수 있는 XML 선언을 제공한다.

<?xml version='1.0' encoding='euc-kr' standalone='yes'?>

​

위의 코딩은 전형적인 XML 선언이다. XML 선언은 "<?xml"문자로 시작해서 "?>"로 끝이 난다. 선언문에 반드시 version 속성을 표시해야 하지만 encoding과 standalone 속성은 선택적이다. 속성은 반드시 version, encoding, standalone 순으로 쓰여야 한다.

​

\- encoding : XML 파서에게 텍스트가 어떤 인코딩을 사용할 것인지 지정해 준다.

\- standalone : 이 속성의 값으로는 "yes"또는 "no"를 가져야만 한다.

\-- Yes : 이 문서가 외부 파일의 요소에 의존하고 있지 않다는 것을 알림.

\-- No : 이 문서가 다른 파일에 의존한다.(외부 파일의 그림, 개체 등을 참조)

​

2.4 빈 요소

아무 데이터도 갖지 않는 요소. 빈 요소가 자주 쓰이는 장소는 PCDATA를 전혀 갖지 않거나 요소에서 모든 정보를

속성으로 지정하는 경우에 많이 쓰인다.

﻿<name></name> // 다음과 같은 방법도 사용 가능 <name/>﻿

​

2.5 주석 사용

\- 주석은 '<!--'로 시작해서 '-->'로 끝난다

\- 주석은 XML 선언 이전에 표현할 수 없다.

\- 태그 안에는 주석을 쓸 수 없다. 예) <first></first <!--이름을 나타낸다-->>

\- 주석문 안에다 '--'를 사용할 수 없다. 예) <!-- 해석하지 않음 -- 주석이다 -->

<?xml version="1.0" encoding="euc-kr"?> <birth> <!-- 월 --> <month>03</month> <!-- 일 --> <day>02</day> </birth>

​

**3\. XML 요소 작성 규칙**

3.1 마침 태그(closing tag)

모든 XML 요소는 시작 태그 다음에는 반드시 마침 태그(closing tag)를 가져야 한다.

HTML에서는 마침 태그(closing tag)가 필요 없는 요소들도 있다.

﻿<p>이것은 하나의 문단이다</p> <p>이것은 또 다른 문단이다</p>﻿

하지만 XML에서는 다음과 같이 마침 태그를 반드시 가져야 한다.

﻿<p>이것은 하나의 문단이다</p> <p>이것은 또 다른 문단이다</p>﻿

​

3.2. 대소문자 구분

XML 태그들은 대소문자 구분을 한다. 

태그 <Memo>와 태그 <memo>는 서로 다르다. 그러므로 시작 태그와 마침 태그는 반드시 대소문자를 맞춰줘야 한다.

﻿<Memo>이렇게 하면 잘못된 것이다</memo> <memo>이렇게 해야 맞다</memo>

​

3.3 모든 XML 요소는 중첩 원리를 잘 지켜야 한다.

HTML에서 어떤 요소들은 다음과 같이 서로 부적절하게 중첩될 수 있다.

﻿<b><i>이 문장은 볼드체와 이탤릭체로 나타난다</i></b>﻿

​

하지만 XML에서는 다음과 같이 서로 중첩을 잘 시켜줘야 한다.

﻿<b><i>이 문장은 볼드체와 이탤릭체로 나타난다</i></b>﻿

​

3.4 모든 XML 문서는 반드시 최상위 요소를 하나만 가질 수 있다.

모든 XML 문서는 한 쌍의 최상위 요소 태그를 포함해야 한다. 모든 다른 요소들은 이 최상위 요소 하부로 중첩되어야 한다. 모든 요소들은 자신의 하부로 자식 요소들을 가질 수 있으며 모든 요소들은 시작 태그와 마침 태그의 쌍을 정확히 이뤄야 한다. 또한 모든 하위 요소들은 자신의 부모 밑에서 순서를 잘 지켜 중첩되어 있어야 한다.

<root> <child> <subchild> </subchild> </child> </root>

​

3.5 속성 값은 쿼테이션(' 또는 ")으로 감싸줘야 한다.

XML 요소들은 HTML에서와 마찬가지로 name과 value 속성을 가질 수 있다. XML에서 속성 값은 항상 쿼테이션(' 또는 ")으로 감싸줘야 한다.

<?xml version="1.0"?> <note date="12/11/99"> <to>앤드유저</to> <from>한길</from> <title>XML 문법과 규칙</title> <body>XML 문법과 규칙을 확실하게 알아두자!</body> </note>

​

3.6 XML은 텍스트 안에 들어 있는 공백을 유지한다.

HTML에서는 두 개 이상의 공백문자를 포함하기 위해서는 를 사용해야만 했다.

﻿<b>&nbsp; 텍스트 &nbsp;</b>﻿

​

하지만 XML에서는 태그 사이에 텍스트와 함께 사용된 공백문자는 그대로 유지된다.

﻿<b> 텍스트 </b>﻿

​

**4\. Well-formed XML**

4.1 XML 유효성 검사

잘 구성된 XML 문서는 DTD 또는 스키마에 대해 유효성을 검사할 수 있다. 올바른 형식의 XML 문서는 올바른 구문을 가진 XML 문서다. XML 유효성 검사를 알기 전에 유효한 XML 문서에 대해 아는 것이 매우 필요하다.

​

​

4.2 XML DTD

DTD는 XML 문서의 법적 요소를 정의한다. 간단히 말해 DTD는 법적 요소 및 속성 목록으로 문서 구조를 정의한다고 말할 수 있다. XML 스키마는 DTD에 대한 XML 기반 대안이다. 실제로 DTD와 XML 스키마는 모두 올바른 형식의 XML 문서를 형성하는 데 사용된다. XML 프로그램을 중단시키므로 XML 문서의 오류를 피해야 한다.

​

​

4.3 XML 스키마

XML 언어로 정의된다. 네임스페이스를 사용하여 기존 정의를 재사용할 수 있다.

많은 내장 데이터 유형과 파생 데이터 유형의 정의를 지원한다.

​

​

4.4 유효한 XML 문서

기본 조건을 모두 만족하고 잘 구성되어 있어야 한다. 미리 정의된 DTD 또는 XML 스키마에 따라 동작해야 한다.

XML 문서가 Well-formed를 준수하기 위해서는 아래와 같은 작성 규칙을 따라야 한다.

​

  * XML 선언으로 시작해야 한다.

  * 하나의 고유한 루트 요소가 있어야 한다.

  * XML 문서의 모든 시작 태그는 끝 태그와 일치해야 한다.

  * XML 태그는 대소문자를 구분한다.

  * 모든 요소는 닫아야 한다.

  * 모든 요소는 적절하게 중첩되어야 한다.

  * 모든 속성 값은 따옴표로 묶어야 한다.

  * XML 엔터티는 특수 문자에 사용해야 한다.
