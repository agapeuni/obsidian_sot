# 2025-05-03 223854491239 PL SQL - 예외와 예외 처리

- 원문: https://blog.naver.com/PostView.naver?blogId=agapeuni&logNo=223854491239&categoryNo=982
- 게시일: 2025. 5. 3. 23:50

## 본문

![](https://postfiles.pstatic.net/MjAyNTA1MDNfOTQg/MDAxNzQ2MjY2NTU0MTI0.KPru1KrFXTNJlRdVpSHpdObm7yDfiQPPDogEWyHlp0cg.C-jcSQwgOf-WOFW5jKn-Yf-UH7vWZNwIck3eTOFN-ukg.PNG/PL_SQL-001_\(14\).png?type=w80_blur)

​

Oracle PL/SQL에서 프로그램을 작성하다 보면, 예상치 못한 오류나 예외 상황이 발생하는 경우가 종종 있다. 이러한 상황에 대처하기 위해 PL/SQL은 예외 처리(Exception Handling)라는 구조를 제공하며, 이를 통해 실행 중 오류가 발생하더라도 프로그램을 안전하게 종료시키거나 적절한 대안을 수행할 수 있도록 한다.

​

PL/SQL의 예외는 크게 **사전 정의 예외** , **비사전 정의 예외** , **사용자 정의 예외** 로 분류되며, 각 유형에 따라 처리 방식이 조금씩 다르다. 본 글에서는 이들 예외의 개념과 처리 방법을 알아보자.

**​**

**​**

**1\. 예외 처리 구문의 기본 구조**

PL/SQL에서는 예외 처리를 위해 EXCEPTION 블록을 사용하며, 다음과 같은 형식으로 작성된다.

BEGIN \-- 실행 블록 EXCEPTION WHEN 예외명1 [OR 예외명2 ...] THEN \-- 예외 처리 로직 WHEN OTHERS THEN \-- 기타 모든 예외 처리 END; 

  * WHEN OTHERS는 명시적으로 지정되지 않은 모든 예외를 포괄적으로 처리할 때 사용한다.

  * 각 예외에 따라 적절한 로직을 정의함으로써, 프로그램의 신뢰성과 복원력을 향상시킬 수 있다.

**​**

**​**

**2\. 사전 정의 예외 (Predefined Exceptions)**

Oracle에서는 자주 발생할 수 있는 오류들에 대해 **미리 정의된 예외 이름** 을 제공하고 있으며, 이를 직접 사용할 수 있다.

**예외명** |  **설명**  
---|---  
DUP_VAL_ON_INDEX |  고유 제약조건을 위반하여 중복 값이 입력될 경우  
INVALID_NUMBER |  숫자 변환 중 유효하지 않은 문자열이 사용될 경우  
NO_DATA_FOUND |  SELECT INTO 문에서 데이터가 반환되지 않은 경우  
TOO_MANY_ROWS |  SELECT INTO 문에서 하나 이상의 행이 반환된 경우  
ZERO_DIVIDE |  0으로 나누기 연산을 수행한 경우  
VALUE_ERROR |  길이 초과 또는 잘못된 형 변환 등 일반적인 값 오류  
PROGRAM_ERROR |  PL/SQL 내부 오류가 발생했을 경우  
  
**예시**

BEGIN SELECT salary INTO v_salary FROM employees WHERE employee_id = 999; EXCEPTION WHEN NO_DATA_FOUND THEN DBMS_OUTPUT.PUT_LINE('해당 직원이 존재하지 않습니다.'); END; 

​

**3\. 비사전 정의 예외 (Non-Predefined Exceptions)**

Oracle에서 사전에 이름이 지정되어 있지 않은 예외에 대해서는 **사용자가 직접 예외명을 정의하고** , 해당 예외를 특정 오류 번호에 매핑하여 사용할 수 있다. 이때 PRAGMA EXCEPTION_INIT 문을 활용한다.

**사용 예시**

DECLARE cons_err EXCEPTION; PRAGMA EXCEPTION_INIT(cons_err, -2292); -- 제약조건 위반 예외 번호 BEGIN DELETE FROM departments WHERE department_id = 10; EXCEPTION WHEN cons_err THEN DBMS_OUTPUT.PUT_LINE('자식 레코드가 존재하여 삭제할 수 없습니다.'); END; 

  * PRAGMA는 컴파일러 지시어로, 예외명과 Oracle 에러 번호를 연결해주는 역할을 한다.

  * 위 예시는 참조 무결성 제약 조건 위반(-2292) 상황을 명시적으로 처리한 것이다.

**​**

**​**

**4\. 사용자 정의 예외 (User-Defined Exceptions)**

특정한 로직상에서 개발자가 정의한 조건을 만족하지 않을 경우 예외를 발생시키고자 할 때는, **사용자 정의 예외를 선언하고 RAISE 또는 RAISE_APPLICATION_ERROR** 를 통해 수동으로 예외를 발생시킬 수 있다.

**​**

**사용자 정의 예외 예시**

DECLARE salary_too_high EXCEPTION; BEGIN IF v_salary > 100000 THEN RAISE salary_too_high; END IF; EXCEPTION WHEN salary_too_high THEN DBMS_OUTPUT.PUT_LINE('급여가 허용된 범위를 초과하였습니다.'); END; 

​

**​**

**5\. 예외 발생 시 메시지 및 오류 코드 확인**

실행 중 발생한 오류에 대해 **에러 번호와 메시지를 동적으로 저장** 하고 싶을 때는 SQLCODE와 SQLERRM을 사용할 수 있다.

  * SQLCODE : 오류 번호 반환

  * SQLERRM : 해당 오류 번호의 메시지 반환

**예시**

DECLARE err_code NUMBER; err_msg VARCHAR2(400); BEGIN \-- 오류 발생 가능 코드 EXCEPTION WHEN OTHERS THEN err_code := SQLCODE; err_msg := SQLERRM; INSERT INTO error_log VALUES (err_code, err_msg, SYSDATE); DBMS_OUTPUT.PUT_LINE('에러 발생: ' || err_code || ' - ' || err_msg); END; 

단, SQLCODE와 SQLERRM은 SQL 내에서 직접적으로 사용할 수 없으며, PL/SQL 블록 내에서만 유효하다.

**​**

**​**

**6\. 시스템 예외를 사용자 정의 메시지로 대체**

시스템 예외 외에도, 사용자 정의 예외 메시지를 출력하고자 할 경우 RAISE_APPLICATION_ERROR를 사용할 수 있다. 이를 통해 20000번부터 20999 사이의 사용자 지정 오류 번호로 직접 메시지를 반환할 수 있다.

​

**예시**

BEGIN IF v_qty < 0 THEN RAISE_APPLICATION_ERROR(-20001, '수량은 음수가 될 수 없습니다.'); END IF; END; 

​

**7\. 결론**

PL/SQL에서의 예외 처리 구조는 단순히 오류를 잡아내는 기능을 넘어, **신뢰성 있는 프로그램 작성** , **정교한 로직 분기** , **데이터 무결성 유지** , **운영 안정성 확보** 등 다방면에서 필수적인 요소이다.

​

실제 업무 환경에서는 예상할 수 없는 오류가 언제든 발생할 수 있으므로, **사전 정의 예외와 사용자 정의 예외를 적절히 조합하여 철저한 예외 처리를 구현** 하는 것이 바람직하다. 예외가 발생하더라도 프로그램이 비정상 종료되지 않고, 적절한 메시지와 함께 정상 흐름을 유지하도록 설계하는 것이 안정적인 PL/SQL 코딩의 핵심이라 할 수 있다.
