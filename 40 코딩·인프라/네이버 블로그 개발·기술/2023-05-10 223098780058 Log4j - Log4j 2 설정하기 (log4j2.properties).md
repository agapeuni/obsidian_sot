1\. Log4j 개요

Log4j는 Apache Software Foundation에서 개발된 로그를 출력해 주는 자바 기반의 로깅 라이브러리이다. 로깅은 소프트웨어 디버깅 및 유지 보수에 중요한 역할을 하는데, 로그 메시지를 기록하고 저장하여 문제를 분석하고 해결하는 데 도움을 준다.

​

Log4j는 다양한 로깅 수준(debug, info, warn, error, fatal)을 지원하며, 로그 메시지를 다양한 형식으로 출력할 수 있다. 또한 로그를 파일이나 데이터베이스 등 다양한 저장소에 저장할 수 있다. Log4j는 매우 유연하고 확장성이 뛰어나며, 대규모 애플리케이션에서도 효과적으로 사용될 수 있다.

​

2\. Log4j 안정성

최근에는 Log4j 2 버전이 출시되었으며, 이전 버전과는 달리 성능과 안정성 면에서 큰 개선이 이루어졌다. 또한, Log4j 2는 Java 8 이상을 지원하며, 최신의 기능과 라이브러리를 사용할 수 있다. 그러나 최근에 Log4j의 취약점이 발견되어 보안 이슈가 논의되고 있다.

​

로깅 구성 파일을 수정할 권한이 있는 공격자가 악의적인 구성을 할 수 있는 원격 코드 실행 공격에 취약했는데 이 문제는 JNDI 데이터 소스 이름을 Java 프로토콜로 제한하여 해결되었다. Log4j 2.3.2(Java 6), 2.12.4(Java 7) 또는 2.17.1(Java 8 이상)로 업그레이드하면 된다.

4\. 프로퍼티 설정

클래스 경로에 유효한 파일이 존재해야 한다. (log4j2.xml, log4j2.properties, log4j2.json, log4j2.yaml)

5\. Appender 종류

Appender는 로그를 목적지까지 전달한다. 

<https://logging.apache.org/log4j/2.x/manual/appenders.html>

[ **Log4j – Log4j 2 Appenders** Appenders Appenders are responsible for delivering LogEvents to their destination. Every Appender must implement the Appender interface. Most Appenders will extend AbstractAppender which adds Lifecycle and Filterable support. Lifecycle allows components to finish initialization after confi... logging.apache.org ](https://logging.apache.org/log4j/2.x/manual/appenders.html)

**1) ConsoleAppender**

로그를 콘솔에 출력한다. 

ConcoleAppender는 System.out 이나 System.err 에 로그를 출력한다.

​

**2) FileAppender**

로그를 파일에 출력한다. 

FileAppender는 OutputStreamAppender로 지정한 파일에 로그를 기록한다.

​

**3) RollingFileAppender**

Policy와 Strategy에 따라 로그를 파일에 출력

​

**4) JDBCAppender**

로그를 관계형 데이터베이스에 출력한다.

JDBCAppender는 JDBC를 사용하여 RDB 테이블에 로그를 기록한다.

​

**4) SMTPAppender**

특정 로그가 발생하면 이메일을 보낸다.

​

6\. 로그 레벨

설정한 단계보다 같거나 높은 경우에는 출력된다. 예를 들면 INFO 단계로 값을 설정하면 INFO, WARN, ERROR, FATAL은 로깅이 되지만 INFO보다 낮은 단계인 TRACE와 DEBUG 로그는 로깅되지 않는다.

설정값 |  TRACE |  DEBUG |  INFO |  WARN |  ERROR |  FATAL |  OFF  
---|---|---|---|---|---|---|---  
ALL |  YES |  YES |  YES |  YES |  YES |  YES |  NO  
TRACE |  YES |  NO |  NO |  NO |  NO |  NO |  NO  
DEBUG |  YES |  YES |  NO |  NO |  NO |  NO |  NO  
INFO |  YES |  YES |  YES |  NO |  NO |  NO |  NO  
WARN |  YES |  YES |  YES |  YES |  NO |  NO |  NO  
ERROR |  YES |  YES |  YES |  YES |  YES |  NO |  NO  
FATAL |  YES |  YES |  YES |  YES |  YES |  YES |  NO  
OFF |  NO |  NO |  NO |  NO |  NO |  NO |  NO  
  
  * TRACE : 상세한 정보를 나타낼 때 사용.

  * DEBUG : 디버그 정보를 나타낼 때 사용.

  * INFO : 일반 정보를 나타낼 때 사용.

  * WARN : 에러는 아니지만 주의할 필요가 있을 때 사용.

  * ERROR : 일반 에러가 일어났을 때 사용.

  * FATAL : 치명적인 에러가 일어났을 때 사용.

7\. 패턴 변수

패턴 변수 |  설명  
---|---  
%p |  debug, info, warn, error, fatal 등의 단계가 출력된다.   
%m |  로그 내용이 출력된다.  
%n |  플랫폼 종속적인 개행문자가 출력된다.  
%d |  로깅 이벤트가 발생한 시간을 기록한다.d{HH:mm:ss, SSS}, %d{yyyy MMM dd HH:mm:ss, SSS} 같은 형태로 사용한다.  
%t  |  로그이벤트가 발생된 스레드의 이름을 출력한다.  
%% |  % 표시를 출력하기 위해 사용한다.   
%c  |  카테고리를 표시한다. 카테고리가 a.b.c처럼 되어있다면 %c{2}는 b.c가 출력된다.  
%C |  클래스명을 표시한다. 클래스 구조가 org.apache.xyz.SomeClass처럼 되어있다면 %C{2}는 xyz.SomeClass 가 출력된다.  
%F |  로깅이 발생한 프로그램 파일명을 나타낸다.  
%l  |  로깅이 발생한 caller의 정보를 나타낸다.  
%L |  로깅이 발생한 caller의 라인수를 나타낸다.  
%M  |  로깅이 발생한 method 이름을 나타낸다.  
%r |  애플리케이션 시작 이후부터 로깅이 발생한 시점의 시간(milliseconds)  
%x |  로깅이 발생한 thread와 관련된 NDC(nested diagnostic context)를 출력한다.  
%X |  로깅이 발생한 thread와 관련된 MDC(mapped diagnostic context)를 출력한다.  
  
​

예를 들면 패턴을 다음과 같이 설정한 경우에는 

[%d{yyyy-MM-dd HH:mm:ss}] %5p %t(), %C:%M(%L) - %m%n

다음과 같이 로그가 출력된다.

﻿[2023-05-10 23:33:59] DEBUG main(), LoggerTest:main(10) - debug [2023-05-10 23:33:59] INFO main(), LoggerTest:main(11) - info [2023-05-10 23:33:59] WARN main(), LoggerTest:main(12) - warn [2023-05-10 23:33:59] ERROR main(), LoggerTest:main(13) - error [2023-05-10 23:33:59] FATAL main(), LoggerTest:main(14) - fatal﻿

[%d{yyyy-MM-dd HH:mm:ss}] 패턴이 날짜와 시간을 표시해 주고 %5p %t(), 패턴이 로깅 단계와 스레드 이름을 출력한다.

%C:%M(%L) 패턴이 클래스명:메소드명(라인수)를 출력하고 - %m%n 패턴이 로깅 메시지와 개행문자를 출력한다.
