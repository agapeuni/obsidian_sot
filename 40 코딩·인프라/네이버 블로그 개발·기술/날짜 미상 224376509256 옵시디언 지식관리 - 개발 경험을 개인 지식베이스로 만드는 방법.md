# 날짜 미상 224376509256 옵시디언 지식관리 - 개발 경험을 개인 지식베이스로 만드는 방법

## 본문

![](https://postfiles.pstatic.net/MjAyNjA4MTJfMjY2/MDAxNzg2NTIwMzA5NDY5.FuZ8y1lO_EDkusNFTZ9E-OSCkLCbVK0l0XeHot8n1qAg.b2Gcz7KNJAELeFo8KteCh8JufMPM7w0HruTxzXs3LBIg.PNG/%EB%8D%B0%EC%9D%B4%ED%84%B0-%EA%B3%BC%ED%95%99-001.png?type=w80_blur)

​

개발을 하다 보면 수많은 정보를 접하게 된다. 프로그래밍 문법, 라이브러리 사용법, 에러 해결 방법, 프로젝트 구조, 서버 설정, 새로운 AI 도구까지 계속 새로운 내용을 배우게 된다. 문제는 시간이 지나면 “분명 예전에 공부했는데 어디에 적어두었지?”라는 상황이 자주 생긴다는 점이다. 이런 문제를 해결하는 데 유용한 도구가 바로 옵시디언(Obsidian)이다.

​

옵시디언은 무엇인가?

옵시디언은 쉽게 말하면 내 컴퓨터 안에 만드는 개인용 지식 관리 시스템이다. 옵시디언 서적에는 세컨드 브레인이라는 문구가 적혀있다.

일반적인 메모 프로그램처럼 글을 작성할 수 있지만, 단순히 메모를 저장하는 것에서 끝나지 않는다. 여러 문서를 서로 연결하면서 자신만의 지식 구조를 만들 수 있다는 점이 가장 큰 특징이다.

​

예를 들어 다음과 같은 문서를 작성했다고 생각해 보자.

* Python * FastAPI * REST API * Docker * PostgreSQL

옵시디언에서는 이러한 문서들을 서로 연결할 수 있다. 예를 들어 FastAPI 문서에서 Python, REST API, PostgreSQL 문서를 연결해 두면 관련 내용을 쉽게 이동하면서 확인할 수 있다. 결국 옵시디언은 단순한 메모장이 아니라 서로 연결된 개인 지식 데이터베이스에 가깝다.

​

​

옵시디언이 유용한 이유

요즘 개발자는 많은 것을 배우고 활용한다. Git 명령어를 공부하고, Docker를 배우고, Spring Boot나 FastAPI를 익히고, 데이터베이스와 서버 설정까지 공부해야 한다. 하지만 공부한 내용을 기억에만 의존하면 시간이 지나면서 대부분 잊어버리게 된다.

​

옵시디언에 다음과 같이 기록해 둘 수 있다.

Docker ├─ Docker 설치 ├─ Dockerfile 작성법 ├─ Docker Compose ├─ 자주 사용하는 명령어 └─ Docker 오류 해결 기록

몇 달 뒤 Docker 관련 문제가 다시 발생하더라도 처음부터 검색할 필요 없이 자신의 기록을 확인하면 된다.

이렇게 쌓인 기록은 시간이 지나면서 자신만의 개발 문서가 된다.

​

Markdown으로 작성한다

옵시디언의 문서는 기본적으로 Markdown 형식으로 저장된다. Markdown은 개발자들이 GitHub README나 기술 문서를 작성할 때 많이 사용하는 간단한 문서 작성 문법이다.

​

예를 들어 다음과 같이 작성할 수 있다.

# Docker ## Docker란? Docker는 애플리케이션을 컨테이너 환경에서 실행할 수 있도록 도와주는 도구다. ## 자주 사용하는 명령어 docker ps docker compose up -d

복잡한 워드프로세서 기능을 사용할 필요 없이 텍스트 중심으로 빠르게 기록할 수 있다. 또한 Markdown 파일은 `.md` 파일이기 때문에 옵시디언이 없어도 다른 편집기에서 열 수 있다.

​

문서와 문서를 연결할 수 있다

옵시디언의 가장 중요한 기능 중 하나는 링크 기능이다.

​

예를 들어 Python 문서에서 FastAPI 내용을 언급하고 싶다면 다음과 같이 작성할 수 있다.

Python 기반 웹 API 개발에는 [[FastAPI]]를 사용할 수 있다.

`[[FastAPI]]`를 클릭하면 FastAPI 문서로 이동한다.

​

또 다른 문서에서는 다음처럼 연결할 수 있다.

FastAPI 프로젝트에서 데이터베이스는 [[PostgreSQL]]을 사용할 수 있다.

이렇게 문서들이 서로 연결되기 시작하면 단순한 폴더 구조를 넘어 지식의 관계를 만들 수 있다.

​

​

폴더보다 연결이 중요하다

처음 옵시디언을 사용하면 폴더를 어떻게 만들어야 할지 고민하게 된다.

​

예를 들어 다음처럼 만들 수 있다.

Programming ├─ Python ├─ Java ├─ Database └─ Docker

이런 구조도 필요하지만 옵시디언에서는 폴더보다 문서 간 연결이 더 중요하다. Python과 Docker는 서로 다른 폴더에 있을 수 있지만 실제 프로젝트에서는 함께 사용될 수 있다. 따라서 문서를 너무 복잡하게 분류하기보다는 필요한 문서끼리 링크로 연결하는 방식이 효과적이다.

​

​

개발하면서 발생한 문제도 기록할 수 있다 

옵시디언은 공부한 내용을 정리하는 용도로만 사용할 필요는 없다. 실제 개발 과정에서 발생한 문제와 해결 방법을 기록해 두면 매우 유용하다.

​

예를 들어 다음과 같이 작성할 수 있다.

# Docker Permission Denied 오류 ## 문제 docker 명령 실행 시 permission denied 발생 ## 원인 현재 사용자가 docker 그룹에 포함되지 않음 ## 해결 sudo usermod -aG docker $USER 로그아웃 후 다시 로그인

이런 기록이 쌓이면 나중에는 자신의 경험을 검색할 수 있는 개인 개발 지식베이스가 된다. 구글에서 찾은 정보보다 자신이 직접 겪고 해결한 기록이 훨씬 빠르게 문제 해결에 도움이 되는 경우도 많다.

​

프로젝트 문서 관리에도 사용할 수 있다

옵시디언은 개발 프로젝트 문서를 관리하는 데도 적합하다.

​

예를 들어 하나의 프로젝트에 대해 다음과 같은 문서를 만들 수 있다.

프로젝트 A ├─ 프로젝트 개요 ├─ 요구사항 ├─ 시스템 아키텍처 ├─ 데이터베이스 설계 ├─ API 설계 ├─ 개발 일정 ├─ 오류 해결 기록 └─ 회고

프로젝트가 끝난 뒤에도 이러한 기록은 다음 프로젝트에서 다시 참고할 수 있는 중요한 자산이 된다. 특히 여러 프로젝트를 경험할수록 이런 기록의 가치가 커진다.

​

그래프 뷰로 지식 연결을 확인할 수 있다

옵시디언에는 Graph View라는 기능도 있다. 작성한 문서를 점으로 표시하고, 문서 사이의 링크를 선으로 보여주는 기능이다.

​

예를 들어 다음과 같은 관계가 있을 수 있다.

Python │ ├── FastAPI │ │ │ └── REST API │ └── 데이터 분석 │ └── Pandas

문서가 많아질수록 자신이 어떤 분야를 많이 공부했는지, 어떤 기술들이 서로 연결되어 있는지를 시각적으로 확인할 수 있다.

​

플러그인으로 기능을 확장할 수 있다

옵시디언은 기본 기능도 강력하지만 다양한 플러그인을 설치해 기능을 확장할 수 있다.

​

예를 들어 다음과 같은 기능을 추가할 수 있다.

* 일정 관리 * 할 일 관리 * 템플릿 * 데이터베이스 형태의 문서 관리 * Git을 이용한 백업 * AI 연동 * 자동 문서 생성

그래서 단순한 메모 프로그램에서 시작해 개인 업무 관리 시스템이나 개발 지식 플랫폼으로 확장할 수도 있다.

​

다만 처음부터 플러그인을 많이 설치하는 것은 권장하지 않는다. 우선 Markdown 문서 작성과 링크 기능에 익숙해진 뒤 필요한 기능을 하나씩 추가하는 것이 좋다.

​

옵시디언과 노션은 어떻게 다를까?

옵시디언을 처음 접하면 노션과 비교하는 경우가 많다. 노션은 협업과 온라인 문서 관리에 강점이 있다. 반면 옵시디언은 개인 지식 관리와 문서 연결에 강점이 있다.

​

쉽게 표현하면 다음과 같다.

​

노션 - 팀과 함께 사용하는 온라인 업무 공간

옵시디언 - 내가 오랫동안 축적하는 개인 지식 저장소

​

물론 두 도구 모두 다양한 용도로 사용할 수 있기 때문에 어느 것이 더 좋다고 단정하기보다는 목적에 따라 선택하면 된다.

​

AI 시대에 옵시디언이 더 중요해지는 이유

최근에는 ChatGPT, Claude, Codex 같은 AI 도구를 활용해 개발하는 경우가 많아지고 있다. 하지만 AI에게 좋은 답변을 얻으려면 프로젝트 정보와 자신의 지식이 잘 정리되어 있어야 한다.

​

옵시디언에 다음과 같은 자료가 축적되어 있다고 생각해 보자.

개발 지식 프로젝트 기록 회의 내용 아이디어 문제 해결 기록 학습 노트 업무 문서

이 자료를 AI와 연결하면 단순히 인터넷 지식을 알려주는 AI가 아니라 자신의 자료를 이해하는 AI 도우미로 발전시킬 수 있다. 그래서 최근에는 Obsidian을 Claude Code, AI Agent, RAG 같은 기술과 연결해 개인 지식 시스템을 구축하려는 시도도 늘어나고 있다.

​

처음에는 이렇게 시작하면 된다

처음부터 복잡한 지식 관리 시스템을 만들 필요는 없다.

​

우선 세 가지 정도만 시작해도 충분하다.

첫째, 새롭게 배운 내용을 하루에 하나씩 기록한다.

둘째, 관련 문서가 있다면 `[[문서 이름]]` 방식으로 연결한다.

셋째, 개발하면서 해결한 오류나 문제를 반드시 기록한다.

​

예를 들어 다음과 같은 문서부터 시작할 수 있다.

Python Git Docker Linux Database AI 프로젝트 오류 해결

몇 달 동안 꾸준히 기록하면 단순한 메모가 아니라 자신만의 개발 지식 데이터베이스가 만들어진다.

​

옵시디언의 핵심은 기록보다 연결이다

옵시디언을 단순한 메모 프로그램으로 사용해도 충분히 유용하다. 하지만 진짜 장점은 문서들이 서로 연결되기 시작할 때 나타난다.

​

오늘 공부한 Python 내용이 다음 달 FastAPI 프로젝트와 연결되고, 프로젝트에서 발생한 Docker 오류가 다시 Docker 지식 문서와 연결된다. 이런 관계가 계속 쌓이면 옵시디언은 단순한 노트가 아니라 자신의 경험과 지식을 축적하는 두 번째 기억 공간이 된다.

​

개발자라면 모든 것을 외우려고 하기보다, 배운 것을 기록하고 다시 찾을 수 있는 시스템을 만드는 것이 더 중요하다.

옵시디언은 바로 그 시스템을 만들기 좋은 도구다.
