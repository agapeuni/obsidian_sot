# 2025-05-03 223854113646 PL SQL - 패키지(Package)의 개념과 활용법

- 원문: https://blog.naver.com/PostView.naver?blogId=agapeuni&logNo=223854113646&categoryNo=982
- 게시일: 2025. 5. 3. 11:00

## 본문

![](https://postfiles.pstatic.net/MjAyNTA1MDNfMjkg/MDAxNzQ2MjM0Mzc2NzI4.-kBEYaWEEUpjruUqyLcsacslpYuX1L8QXu6m4mtX_fwg.zeA8gu30Bp67lnM2JA9NsJpvTj0oEjOz6qp1D9e8miYg.PNG/PL_SQL-001_\(1\).png?type=w80_blur)

​

데이터베이스 개발 및 유지 보수의 효율성을 높이기 위한 방법으로, PL/SQL에서는 **패키지(Package)**라는 강력한 구조를 제공하고 있다. 패키지는 여러 관련 오브젝트들을 하나의 논리적인 단위로 묶어 관리할 수 있도록 하며, 코드의 모듈화, 재사용성, 성능 측면에서 많은 이점을 제공한다.

​

​

**1\. 패키지란 무엇인가?**

패키지란 **서로 관련된 스키마 오브젝트들을 하나로 묶어 캡슐화한 구조** 를 말한다. 주로 관련된 **프로시저(Procedure)** , **함수(Function)** , **변수** , **커서(Cursor)** 등을 함께 정의하여 하나의 단위로 구성한다. 패키지는 컴파일된 후 스키마 오브젝트로서 데이터 딕셔너리에 저장되며, 직접적으로 호출할 수는 없다. 대신, 패키지 내부에 포함된 개별적인 서브 프로그램(예: 프로시저나 함수)을 호출하여 사용하게 된다. 이때 호출 형식은 패키지명.서브프로그램명의 형태를 따른다.

​

**​**

**2\. 패키지의 구조**

패키지는 두 부분으로 구성된다.

**​**

**1) 패키지 명세(Specification)**

외부에서 접근 가능한 서브 프로그램의 이름, 파라미터, 데이터형 등을 정의하는 영역이다. 명세는 패키지의 "인터페이스" 역할을 하며, 실제 구현 없이도 어떤 기능이 제공되는지를 파악할 수 있다.

​

**2) 패키지 본문(Body)**

명세에서 정의한 서브 프로그램의 실제 구현 내용이 포함되는 영역이다. 명세에 정의된 각 오브젝트의 동작을 이곳에 상세히 작성한다.

**​**

**​**

**3\. 패키지를 사용하는 이유**

패키지를 활용함으로써 얻을 수 있는 이점은 다음과 같다.

  * 관련 기능들을 하나의 모듈로 구성함으로써 **코드의 가독성과 유지보수성 향상**

  * 패키지에 선언된 **Public 변수 및 커서** 는 세션이 유지되는 동안 계속 사용 가능하므로, 상태 유지를 필요로 하는 작업에 유리

  * 여러 오브젝트를 동시에 메모리에 적재함으로써 **실행 성능 향상**

  * 공통적으로 사용되는 서브 프로그램을 패키지 형태로 관리하여 **코드 재사용** 을 극대화할 수 있음

**​**

**​**

**4\. 패키지 명세 작성법**

패키지 명세는 아래와 같은 형태로 작성된다.

CREATE [OR REPLACE] PACKAGE 패키지이름 [AUTHID {CURRENT_USER | DEFINER}] AS \-- 서브 프로그램 선언 END 패키지이름; 

  * AUTHID는 패키지를 실행할 때의 권한을 정의하며, CURRENT_USER는 호출자의 권한, DEFINER는 생성자의 권한을 의미한다.

  * 이 영역에서는 단순히 프로그램 오브젝트의 "선언"만 수행하며, 실제 구현은 포함되지 않는다.

**​**

**​**

**5\. 패키지 본문 작성법**

패키지 본문에는 명세에서 선언한 서브 프로그램의 구현 내용이 작성된다.

CREATE [OR REPLACE] PACKAGE BODY 패키지이름 AS \-- 서브 프로그램 구현 BEGIN \-- 초기화 코드 (선택사항) END 패키지이름; 

패키지 명세가 수정되면 해당 패키지를 참조하고 있는 모든 스토어드 오브젝트들은 **재컴파일이 필요** 하다. 반면, 패키지 본문만 변경된 경우에는 참조 오브젝트에 영향을 미치지 않으므로 자동 재컴파일이 필요하지 않다.

**​**

**​**

**6\. 패키지 서브 프로그램 호출 과정**

패키지에 포함된 프로시저 또는 함수 등을 호출할 때에는 다음의 절차를 따른다.

  1. 호출자가 해당 서브 프로그램에 대한 **실행 권한을 보유하고 있는지 확인**

  2. 데이터 딕셔너리에서 해당 오브젝트가 **VALID 상태** 인지 확인 (INVALID일 경우 자동 재컴파일 수행)

  3. 서브 프로그램 실행

  4. 패키지명.서브프로그램명 형식으로 호출

EXEC change_pkg.change_ages('id10'); 

**​**

**​**

**7\. 패키지 작성 예제**

아래는 사용자 ID가 'id10'인 회원의 나이와 마일리지를 각각 변경하는 두 개의 프로시저를 포함한 패키지의 예제이다.

**1단계: 패키지 명세 작성**

CREATE OR REPLACE PACKAGE change_pkg AS PROCEDURE change_ages(i_id IN VARCHAR2); PROCEDURE change_mileage(i_id IN VARCHAR2); END change_pkg; / 

​

**2단계: 패키지 본문 작성**

CREATE OR REPLACE PACKAGE BODY change_pkg AS PROCEDURE change_ages(i_id IN VARCHAR2) IS BEGIN UPDATE member SET age = 100 WHERE userid = i_id; END change_ages; PROCEDURE change_mileage(i_id IN VARCHAR2) IS BEGIN UPDATE member SET mileage = 777 WHERE userid = i_id; END change_mileage; END change_pkg; / 

​

**3단계: 패키지 프로시저 호출**

EXEC change_pkg.change_ages('id10'); EXEC change_pkg.change_mileage('id10'); 

이 예제에서는 ‘id10’이라는 사용자에 대해 나이는 100세로, 마일리지는 777로 변경된다.

**​**

패키지는 PL/SQL에서 제공하는 매우 유용한 모듈화 기능으로, 관련된 서브 프로그램을 논리적으로 묶고 효율적으로 관리할 수 있게 한다. 이를 통해 코드의 재사용성을 높이고, 유지 보수를 간편하게 만들며, 실행 성능 또한 개선할 수 있다. 패키지를 잘 활용하면 대규모 데이터베이스 시스템에서도 구조적이고 안정적인 프로그램 개발이 가능하며, 특히 다수의 프로시저와 함수를 체계적으로 관리하고자 할 때 탁월한 선택이 될 수 있다.
