**1\. 표준스트림**

리눅스에서는 3가지의 표준 스트림을 사용한다. 3가지의 표준 스트림은 리눅스에서 매우 중요한 역할을 한다. 예를 들어, 여러 명령어들은 이러한 스트림을 이용하여 표준 입출력을 처리한다.

​

**1) 표준 입력 스트림 (Standard Input Stream)**

입력을 받는 스트림이다. 주로 키보드나 마우스 같은 사용자 입력 장치에서 데이터를 받아들인다. 이 스트림은 STDIN (Standard Input)으로 불리며, 파일 디스크립터 번호로는 0번을 갖는다.

​

**2) 표준 출력 스트림 (Standard Output Stream)**

출력을 하는 스트림이다. 이 스트림은 콘솔(Console)이나 터미널(Terminal)에 출력된다. 이 스트림은 STDOUT (Standard Output)으로 불리며, 파일 디스크립터 번호로는 1번을 갖는다.

​

**3) 표준 오류 스트림 (Standard Error Stream)**

오류 메시지를 출력하는 스트림이다. 이 스트림은 보통 콘솔(Console)이나 터미널(Terminal)에 출력된다. 이 스트림은 보통 STDERR (Standard Error)으로 불리며, 파일 디스크립터 번호로는 2번을 갖는다.

리눅스는 연결된 입출력 장치도 파일로 추상화를 했다. 장치에 접근하는 것을 파일을 다루는 것과 같도록 했다. 장치에 입력되고 출력되는 데이터는 데이터의 흐름(스트림)으로 오고 간다. 키보드와 모니터와 같은 물리적 장치를 표준 스트림으로 추상화했다.

​

**2\. /dev/null**

`/dev/null`은 리눅스에서 매우 유용한 파일 중 하나이며 특별한 장치로 복구 가능성이 없는 블랙홀이다. 해당 경로로 보내지는 모든 것은 없어진다. `/dev/null`은 리눅스에서 표준 출력 스트림을 비롯한 모든 입력 스트림과 출력 스트림을 버리는 특수한 파일이다. 

​

이 파일에 데이터를 쓰면 그 데이터는 디스크에 저장되지 않고, 그냥 버려집니다. 이 파일은 특정 명령어나 프로그램의 출력을 무시하고 싶을 때 유용하게 사용된다. 

​

또한, 이 파일은 프로세스를 백그라운드로 실행시키는 경우에도 유용하다. 백그라운드로 실행시킨 프로세스가 어떤 출력을 내놓더라도, 그 출력을 `/dev/null` 파일에 리다이렉트하면 콘솔에는 출력이 나타나지 않는다. 

​

cmd 1> /dev/null

\- 표준 출력을 표시하지 않음.

​

cmd 2> /dev/null

\- 표준 에러를 표시하지 않음.

​

cmd > cmd.log 2>$1

\- 표준 출력을 cmd.log 파일로 지정

\- 표준 에러를 표준 출력으로 리다이렉션.

\- 에러가 발생해도 표준 출력으로 보내고 계속 실행하라는 의미.

​

cmd > /dev/null 2>$1

\- 출력도 에러도 블랙홀에 던짐.
