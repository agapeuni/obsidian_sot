1\. 소프트웨어 테스트 개요

소프트웨어 테스트는 소프트웨어 제품이 요구 사항과 일치하는지 확인하고 소프트웨어 제품에 결함이 있는지 확인하는 방법이다. 하나 이상의 기능을 평가하기 위해 수동 또는 자동화 도구를 사용하여 소프트웨어 구성 요소를 실행하는 작업이 포함된다. 

​

소프트웨어 테스트의 목적은 요구 사항과 대조하여 오류, 차이 또는 누락된 요구 사항을 찾아내는 것이다. 예상대로 작동하는지 검증하는 과정이다. 이를 통해 소프트웨어 제품의 품질을 향상시키고 사용자에게 더 나은 경험을 제공할 수 있고 개발자와 사용자 모두에게 신뢰성과 성능을 보장할 수 있다.

​

​

2\. 소프트웨어 테스트 유형

소프트웨어 테스트는 크게 수동과 자동, 기능과 비기능으로 구분할 수 있다.

​

**1) 수동 테스트 (Manual Testing)**

수동으로 테스트 케이스를 작성하고 실행하는 방법으로 테스트 케이스를 각각 작성하고 실행하는데 시간과 인적자원이 많이 소요된다. 그러나 이 방법은 테스트 과정에서 개발자가 특정 테스트 케이스에 대한 주의를 집중하게 해줌으로써 유용하다.

​

**2) 자동화 테스트 (Automated Testing)**

프로그램이 자동으로 테스트 케이스를 실행하고 결과를 분석하는 방법으로 시간과 비용을 절약할 수 있습니다. 자동화된 테스트 케이스를 실행하면 개발자는 일일이 결과를 확인할 필요가 없으므로 개발자가 시간을 절약할 수 있다. 또한 자동화된 테스트 케이스는 수동으로 테스트하는 것보다 정확한 결과를 얻을 수 있다.

​

**3) 기능 테스트 (Functional Testing)**

소프트웨어가 기능적 요구사항을 올바르게 수행하는지 테스트하는 것이다. 이 테스트는 사용자가 소프트웨어를 어떻게 사용해야 하는지에 대한 시나리오를 작성하고, 이를 기반으로 소프트웨어의 기능을 검증한다. 기능 테스트는 보통 단위 테스트, 통합 테스트, 시스템 테스트 및 인수 테스트 단계에서 수행된다.

​

**4) 비기능 테스트 (Non-Functional Testing)**

소프트웨어의 비기능적 요구사항을 검증하는 것이다. 이러한 요구사항은 보안, 성능, 안정성, 호환성, 사용성 등이다. 비기능 테스트는 사용자가 소프트웨어를 사용할 때 발생할 수 있는 다양한 문제점을 찾아내고 예방하기 위해 수행된다. 이 테스트는 성능 테스트, 보안 테스트, 호환성 테스트, 사용성 테스트 등으로 구분될 수 있다.

​

​

3\. 소프트웨어 테스트 종류

**1) 단위 테스트 (Unit Testing)**

하나의 프로그램, 모듈 또는 Unit 코드의 기능이 설계를 따르는지 검증한다. 소프트웨어의 각 구성 요소가 개별적으로 테스트된다. 테스트의 중심은 코드 블록이며, 개발자가 작성한 코드의 구문과 구조를 검증한다.

​

**2) 통합 테스트 (Integration Testing)**

두 개 이상의 애플리케이션, 데이터베이스, 관련 프로그램, 모듈, Unit이 설계를 따르는지 검증한다. 개별 단위 테스트를 통합하여 전체 소프트웨어 시스템이 예상대로 작동하는지 확인한다. 이 단계에서는 소프트웨어의 다양한 구성 요소가 결합되고 통합되는 방식을 테스트한다.

​

**3) 시스템 테스트 (System Testing)**

모든 시스템의 조작을 모의 실험하고 정확히 실행되는지 확인, 요구사항을 만족하는지 검증한다. 통합된 소프트웨어 시스템의 전반적인 기능을 검증한다. 이 단계에서는 시스템이 사용자 요구 사항을 충족시키는지 여부를 확인한다.

​

**4) 인수 테스트 (Acceptance Testing)**

소프트웨어가 사용자의 요구 사항을 충족시키는지 여부를 검증한다. 이 단계에서는 사용자가 소프트웨어를 사용하여 일상적인 작업을 수행할 수 있다.

​

​

4\. 테스트 대상에 따른 종류

  * 긍정 단위 테스트 (positive unit test) : 의도대로 코드를 실행해서 결과를 검증

  * 부정 단위 테스트 (negative unit test) : 고의적으로 코드를 잘못 사용해서 안정성과 오류 처리 상태를 확인

  * 오류 삽입 테스트 (fault injection test) : 코드가 비정상적인 상황을 일관성 있게 처리하는지 확인

  * 스트레스 테스트 (stress test) : 코드를 한계까지 밀어붙여 자원, 성능, 재진입 오류를 찾기

​

​

5\. 테스트에 관한 여담

프로그래머는 코딩을 잘하고 기능을 구현하는 것도 중요하지만 오류나 버그가 없는 품질이 높은 코드를 만드는 것이 더 중요하다. 오랜 시간 프로젝트를 진행하면서 다양한 사람들을 만나보면 어떤 사람은 기능 구현은 참 잘하는데 코드의 품질은 너무 낮다. 나중에 그 부분에서 문제가 발생할 경우에는 그 복잡하고 정리되어 있지 않은 코드로 인해 수정 및 유지보수 하는데 시간과 비용이 더 소모된다.

​

기능만 어떻게든 구현되면 세세한 것은 그냥 무시하고 넘기는 사람들이 많다. 네이밍룰이나 컨벤션도 지켜지지 않고 로직도 스파게티 코드로 작성한다. 정리가 덜된 것처럼 보이고 코드 품질도 형편없다. 코드가 다른 사람이 보기 어렵게 되어 있고 여기저기 수정해야 할 곳이 눈에 보인다.

​

품질이 좋고 안정적인 코드는 기능을 돌리기 전에 코드와 주석만 보아도 어느 정도 알 수 있다. 남들이 신경 쓰지 못하는 디테일한 부분까지 잘 대응이 되어 있고 다른 사람을 위한 배려까지 느껴질 정도로 잘 정리되어 있다. 프로그램을 만드는 사람이라면 자신이 작성한 코드가 기본적인 테스트를 통과할 수 있는 품질은 유지해야 한다고 본다. 코드의 외형이 품질을 보장하는 것은 아니지만 주석이 잘되어 있고 코드가 간결하고 깔끔해 보이면 코드의 품질이 높은 경우가 많다.
