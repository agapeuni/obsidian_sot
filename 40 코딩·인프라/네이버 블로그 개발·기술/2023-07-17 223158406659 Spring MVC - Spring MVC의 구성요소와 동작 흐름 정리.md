​

**Spring MVC** 는 스프링 프레임워크(Spring Framework)에서 제공하는 웹 애플리케이션 개발 모듈로, **MVC는 Model-View-Controller** 아키텍처 패턴을 기반으로 하고 있다. 해당 모듈은 웹 애플리케이션의 구조를 명확하게 분리하고, 유지보수성과 확장성을 높이는 데 도움을 준다.

​

**1\. 주요 구성요소**

**① 컨트롤러 (Controller)**

컨트롤러는 클라이언트로부터 전달된 요청을 처리하고 애플리케이션 로직을 수행하는 핵심 구성요소이다. 처리된 결과는 DispatcherServlet에 전달되며, 스프링에서는 @Controller 어노테이션을 통해 정의한다. 각 요청은 @RequestMapping 등의 어노테이션을 통해 특정 메서드와 매핑된다.

​

**② 모델 (Model)**

모델은 애플리케이션의 비즈니스 로직을 처리하고, 데이터와 관련된 기능을 담당한다. 데이터베이스와의 연동, 외부 API 호출, 내부 로직 처리를 포함하며, 사용자 인터페이스와는 분리되어 독립적으로 동작한다.

**​**

**③ 뷰 (View)**

뷰는 사용자에게 처리 결과를 시각적으로 출력하는 역할을 수행한다. JSP(JavaServer Pages)가 대표적이며, 최근에는 Thymeleaf, FreeMarker, Mustache 등의 다양한 템플릿 엔진도 널리 활용되고 있다. 뷰는 모델 데이터를 참조하여 동적으로 콘텐츠를 생성하고 클라이언트에게 응답을 전송한다.

**​**

**④ 디스패처 서블릿 (DispatcherServlet)**

DispatcherServlet은 클라이언트로부터의 모든 요청을 중앙에서 처리하는 조정자(Front Controller) 역할을 한다. 요청을 적절한 컨트롤러에 전달하고, 이후의 처리 결과를 뷰로 전달하는 기능을 수행한다. 이는 web.xml 또는 Java 기반 구성 클래스에서 설정된다.

**​**

**⑤ 핸들러 매핑 (Handler Mapping)**

핸들러 매핑은 요청 URL과 해당 요청을 처리할 컨트롤러를 연결해주는 구성요소이다. 스프링은 @RequestMappingHandlerMapping, SimpleUrlHandlerMapping, BeanNameUrlHandlerMapping 등 다양한 매핑 전략을 제공하여 유연한 구성 방식이 가능하다.

**​**

**⑥ 뷰 리졸버 (View Resolver)**

뷰 리졸버는 컨트롤러로부터 반환된 뷰 이름을 실제 뷰로 변환하는 역할을 한다. 일반적으로 InternalResourceViewResolver가 사용되며, JSP 등과 연동하여 최종 HTML 응답을 생성한다.

​

이 외에도 Spring MVC는 폼 처리, 데이터 바인딩, 유효성 검증(Validation), 예외 처리, 파일 업로드, 국제화 등 다양한 기능을 내장하고 있어 실무 개발에서 강력한 웹 프레임워크로 평가받고 있다.

**​**

**​**

**스프링 MVC의 요청 처리 흐름**

스프링 MVC는 다음과 같은 흐름을 통해 클라이언트의 요청을 처리한다.

1\. 클라이언트의 요청이 **DispatcherServlet** 에 전달된다.

2~3. DispatcherServlet은 **HandlerMapping** 을 통해 클라이언트 요청을 처리할 적절한 컨트롤러를 찾는다.

4\. 선택된 컨트롤러의 handleRequest() 메서드가 호출되어 비즈니스 로직이 수행된다.

5\. 컨트롤러는 처리 결과를 담은 **ModelAndView** 객체를 반환한다.

6~7. DispatcherServlet은 **ViewResolver** 를 통해 해당 결과를 출력할 뷰(View) 객체를 찾는다.

8~9. 최종적으로 뷰는 모델 데이터를 바탕으로 HTML 등 결과를 생성하여 클라이언트에게 응답을 전송한다.

​

Spring MVC는 위와 같은 구조적 설계와 처리 흐름을 통해 웹 애플리케이션 개발을 보다 체계적이고 효율적으로 지원한다. 각 구성요소의 역할과 처리 단계를 명확히 이해하면, 더욱 안정적이고 확장성 높은 애플리케이션을 구현할 수 있다.
