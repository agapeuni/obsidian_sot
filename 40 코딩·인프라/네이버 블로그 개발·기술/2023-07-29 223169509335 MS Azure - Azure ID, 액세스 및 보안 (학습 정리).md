​

Azure 디렉터리 서비스

Azure AD는 Microsoft 클라우드 애플리케이션에 로그인하고 액세스할 수 있는 디렉터리 서비스다. 

Azure AD에서 온-프레미스 Active Directory 배포를 유지 관리하는 데도 도움이 된다.

Azure AD는 Microsoft의 클라우드 기반 ID 및 액세스 관리 서비스다.

Azure AD를 사용해 ID 계정을 관리하며 해당 서비스를 전역적으로 사용할 수 있도록 지원한다.

​

Azure AD가 제공하는 기능

  * 인증: 애플리케이션 및 리소스에 액세스하기 위한 ID 확인이 포함. 

  * Single Sign-On: SSO를 사용하면 한 가지 사용자 이름과 한 가지 암호만 기억하면 여러 애플리케이션에 액세스할 수 있다.

  * 애플리케이션 관리: Azure AD를 사용하여 클라우드 및 온-프레미스 앱을 관리할 수 있다. 

  * 디바이스 관리: Azure AD는 개별 사용자의 계정뿐만 아니라 디바이스 등록도 지원한다.

​

온-프레미스 AD를 Azure AD에 연결할 수 있나?

Active Directory를 Azure AD에 연결하여 클라우드와 온-프레미스 간에 일관된 ID 환경을 사용할 수 있다.

온-프레미스 AD와 Azure AD에 연결하는 방법은 Azure AD Connect를 사용하는 것이다. 

Azure AD Connect는 두 ID 시스템 간에 변경 내용을 동기화한다. 

​

Azure Active Directory Domain Services란?

Azure AD DS(Domain Services)는 도메인 조인, 그룹 정책, LDAP 및 Kerberos/NTLM 인증과 같은 관리되는 도메인 서비스를 제공한다.

Azure AD DS를 사용하면 클라우드에서 DC(도메인 컨트롤러)를 배포, 관리 및 패치할 필요 없이 도메인 서비스의 이점을 얻을 수 있다.

​

**Azure AD DS의 작동 방식**

Azure AD DS 관리되는 도메인을 만들 때 고유한 네임스페이스를 정의한다.

그런 다음, 두 개의 Windows Server 도메인 컨트롤러가 선택한 Azure 지역에 배포된다. 

Azure 플랫폼은 Azure Disk Encryption을 사용한 저장 데이터 백업 및 암호화를 포함하여 관리되는 도메인의 일부로 DC를 처리한다.

​

**정보가 동기화되었나요?**

관리되는 도메인은 Azure AD에서 Azure AD DS로 단방향 동기화를 수행하도록 구성된다.

​

Azure 인증 방법

인증은 신원이 맞는지 증명하는 것이다. 

사람, 서비스 또는 디바이스에 자신이 누구인지 증명하기 위한 자격 증명 유형을 제공하도록 요구한다.

Azure는 표준 암호, SSO, MFA(다단계 인증) 및 암호 없는 인증을 비롯한 여러 인증 방법을 지원합니다.

​

Single Sign-On 이란?

SSO을 사용하면 사용자가 한 번 로그인하고 해당 자격 증명을 사용하여 여러 공급자의 여러 리소스 및 애플리케이션에 액세스할 수 있다. 

SSO를 사용하는 경우 애플리케이션 전반에 걸친 액세스 권한이 사용자와 연결된 단일 ID에 부여되므로 보안 모델이 간소화된다. 

​

다단계 인증이란?

다단계 인증은 로그인 프로세스 중에 사용자에게 식별의 추가 양식을 요청하는 프로세스다. 

다단계 인증은 인증 완료에 2개 이상의 요소를 요구하여 ID를 추가로 보호한다.

MFA는 암호가 손상되었지만 두 번째 요소는 손상되지 않은 경우 암호 손상으로부터 보호해 준다.

다단계 인증은 자격 증명 노출(예: 도난당한 사용자 이름 및 암호)의 영향을 제한하여 ID 보안을 강화합니다. 

​

**Azure AD Multi-Factor Authentication 이란?**

Azure AD Multi-Factor Authentication은 다단계 인증 기능을 제공하는 Microsoft 서비스다. 

​

암호 없는 인증이란?

암호 없는 인증 방법 사용 시 암호가 제거되고 사용자가 소유하고 있거나 알고 있는 인증 수단으로 대체되기 때문에 더 편리하다.

Microsoft 글로벌 Azure 및 Azure Government는 Azure AD와 통합되는 세 가지 암호 없는 인증 옵션을 제공한다.

​

**1) 비즈니스용 Windows Hello**

비즈니스용 Windows Hello는 지정된 고유 Windows PC가 있는 정보 근로자에게 적합하다.

생체 인식 및 PIN 자격 증명은 사용자 PC에 직접 연결되기 때문에 소유자 이외의 사용자가 액세스하지 못한다.

​

**2) Microsoft Authenticator 앱**

Authenticator 앱으로 iOS 또는 Android 휴대폰이 암호 없는 자격 증명으로 바뀐다.

암호 외에도 편리한 다단계 인증 옵션으로 Microsoft Authenticator 앱을 이미 사용하고 있을 수도 있습니다. 

​

**3) FIDO2 보안 키**

FIDO는 암호 없는 인증을 위한 공개 표준이고 WebAuthn(웹 인증) 표준을 통합하는 최신 표준이다.

FIDO(Fast IDentity Online) Alliance는 공개 인증 표준을 알리고 암호를 인증 형태로 사용하는 것을 줄이도록 지원한다.

​

Azure 외부 ID

Azure Active Directory for External Identities는 조직 외부 사용자와 안전하게 상호 작용할 수 있는 모든 방법을 나타낸다. 

Azure AD(Azure Active Directory)를 사용하면 Azure AD B2B 기능을 통해 조직의 경계를 넘나들며 협업을 쉽게 수행할 수 있다. 

파트너, 배포자, 공급자 또는 공급업체와 협업하려는 경우 리소스를 공유하고 내부 사용자가 외부 조직에 액세스할 수 있는 방법을 정의할 수 있다.

​

Azure 조건부 액세스

조건부 액세스는 ID 신호에 따라 리소스에 대한 액세스를 허용하기 위해 Azure Active Directory에서 사용하는 도구다. 

조건부 액세스를 사용하면 사용자에게 보다 세분화된 다단계 인증 환경을 제공할 수 있다.

​

조건부 액세스를 언제 사용할 수 있나?

요청자의 역할, 위치 또는 네트워크에 따라 애플리케이션에 액세스하려면 MFA(다단계 인증)가 필요하다.

승인된 클라이언트 애플리케이션을 통해서만 서비스에 액세스하도록 요구한다.

알 수 없거나 예기치 않은 위치에서의 액세스와 같이 신뢰할 수 없는 소스로부터의 액세스를 차단한다.

​

Azure 역할 기반 액세스 제어

최소 권한 원칙은 작업을 완료하는 데 필요한 수준까지만 액세스 권한을 부여해야 한다고 말한다. 개인에 대한 자세한 액세스 요구 사항을 정의한 다음, 새 리소스가 생성되거나 새 사람이 팀에 합류할 때 액세스 요구 사항을 업데이트하는 대신 Azure를 사용하면 Azure RBAC(역할 기반 액세스 제어)를 통해 액세스를 제어할 수 있다.

​

리소스에 역할 기반 액세스 제어는 어떻게 적용되나?

역할 기반 액세스 제어는 이 액세스가 적용되는 리소스 또는 리소스 세트인 ‘범위’에 적용된다.

Azure RBAC는 계층 구조입니다. 부모 범위에서 액세스 권한을 부여할 때 해당 권한은 모든 자식 범위에서 상속된다.

​

Azure RBAC는 어떻게 적용되나?

Azure RBAC는 Azure Resource Manager를 전달되는 Azure 리소스에 대해 시작되는 모든 작업에 적용된다.

Resource Manager는 클라우드 리소스를 구성하고 보호하는 방법을 제공하는 관리 서비스다.

일반적으로 Azure Portal, Azure Cloud Shell, Azure PowerShell 및 Azure CLI에서 Resource Manager에 액세스한다.

​

제로 트러스트 모델

제로 트러스트는 최악의 시나리오를 가정하고 해당 기대 수준에 따라 리소스를 보호하는 보안 모델이다.

제로 트러스트는 처음부터 위반을 가정한 다음, 제어되지 않은 네트워크에서 시작된 것처럼 각 요청을 확인한다.

​

심층 방어

심층 방어의 목적은 정보를 보호하고 무단 접근을 통한 도난을 방지하는 것이다.

심층 방어는 데이터에 무단으로 액세스하기 위한 공격 진행 속도를 늦추는 여러 메커니즘을 사용하는 전략이다.

​

심층 방어 계층

각 레이어가 보호를 제공하므로 한 레이어에서 침해 사고가 발생하더라도 후속 레이어가 이미 작동하고 있기 때문에 추가 노출을 방지한다.

중앙에서 보호할 데이터와 중앙 데이터 계층을 보호하기 위해 작동하는 다른 모든 계층을 사용하여 심층 방어를 계층 집합으로 시각화할 수 있다.

![](https://postfiles.pstatic.net/MjAyMzA3MjlfMjA0/MDAxNjkwNjI5Nzk4ODM2.BF02Rc6hn8gfz6x7AImVzjRW8JIseoi7yWzXNydR5C8g.mZAYE2Xy_MB2uk6L12sm_R2P_a7y0a6EuyzjGRCa5jsg.PNG.agapeuni/defense-depth-486afc12.png?type=w80_blur)

물리적 보안 계층 : 물리적으로 컴퓨팅 하드웨어를 보호하기 위한 첫 번째 방어선.

ID 및 액세스 계층 : ID를 안전하게 보호, 필요한 것에만 액세스 권한을 부여, 이벤트 및 변경 내용 기록. 인프라에 대한 접근 및 제어 변경을 통제.

경계 계층 : 리소스에 대한 네트워크 기반 공격으로부터 보호, 최종 사용자에게 서비스 거부가 발생하기 전에 대규모 공격을 필터링.

네트워크 계층 : 모든 리소스에 대한 네트워크 연결을 제한하여 필요한 것만 허용, 구분 및 액세스 제어를 통해 리소스 간의 통신을 제한.

컴퓨팅 계층 : 컴퓨팅 리소스를 안전하게 보호하고 보안 문제를 최소화하여 가상 머신에 대한 액세스를 보호.

애플리케이션 계층 : 애플리케이션을 보호하고 보안 취약점을 제거, 중요한 애플리케이션 비밀을 안전한 저장 매체에 저장.

데이터 계층 : 보호해야 하는 비즈니스 및 고객 데이터에 대한 액세스를 제어.

​

Microsoft Defender for Cloud

클라우드용 Defender는 보안 태세 관리 및 위협 방지를 위한 모니터링 도구다.

클라우드, 온-프레미스, 하이브리드, 다중 클라우드 환경을 모니터링하여 보안 태세를 강화하기 위한 지침 및 알림을 제공한다.

​

배포된 모든 곳에서 보호

Defender for Cloud는 Azure 네이티브 서비스로 배포 없이도 Azure 서비스를 모니터링하고 보호한다.

Defender for Cloud는 Log Analytics 에이전트를 자동으로 배포하여 보안 관련 데이터를 수집할 수 있다. 

​

**Azure 네이티브 보호**

Defender for Cloud를 사용하면 무차별 암호 대입 공격(brute force attack)에 대한 노출을 제한할 수 있다. 

Azure SQL 및 Storage 서비스 전체의 잠재적 취약성 평가 및 취약성을 완화하는 방법에 대한 권장 사항을 확인할 수도 있다.

권한 있는 사용자, 허용된 원본 IP 주소 범위 또는 IP 주소에 대해서만, 제한된 시간 동안 선택한 포트에 보안 액세스 정책을 설정할 수 있다.

Azure App Service, Azure SQL, Azure Storage 계정 및 기타 데이터 서비스를 포함한 Azure 서비스를 대상으로 하는 위협을 탐지한다.

​

**하이브리드 리소스 방어**

Azure 환경을 방어하는 것 외에도 Defender for Cloud 기능을 하이브리드 클라우드 환경에 추가하여 비 Azure 서버를 보호할 수 있다. 

보호를 온-프레미스 컴퓨터로 확장하려면 Azure Arc를 배포하고 Defender for Cloud의 향상된 보안 기능을 사용하도록 설정한다.

​

**다른 클라우드에서 실행되는 리소스 방어**

클라우드용 Defender는 다른 클라우드(예: AWS 및 GCP)의 리소스를 보호할 수도 있다.

서버용 Microsoft Defender는 위협 탐지 및 고급 방어를 Windows 및 Linux EC2 인스턴스로 확장한다.

컨테이너용 Microsoft Defender는 컨테이너 위협 탐지 및 고급 방어를 Amazon EKS Linux 클러스터로 확장한다.

​

평가, 보안 및 방어

Defender for Cloud는 클라우드 및 온-프레미스에서 리소스 및 워크로드의 보안을 관리할 때 세 가지 중요한 요구 사항을 충족한다.

​

**1) 지속적인 평가**

보안 태세를 파악합니다. 취약성을 식별하고 추적합니다.

Defender for Cloud를 사용하면 환경을 지속적으로 평가할 수 있다.

클라우드용 Defender에는 가상 머신, 컨테이너 레지스트리 및 SQL 서버에 대한 취약성 평가 솔루션이 포함되어 있다.

서버용 Microsoft Defender에는 엔드포인트용 Microsoft Defender와의 자동 네이티브 통합이 포함되어 있다.

​

**2) 보안**

Azure Security Benchmark를 사용하여 리소스 및 서비스를 강화한다.

Defender for Cloud의 정책은 Azure Policy 제어를 기반으로 빌드 된다.

Defender for Cloud에서 관리 그룹, 구독 및 테넌트 전체에 대해 실행되는 정책을 설정할 수 있다.

​

**3) 방어**

리소스, 워크로드 및 서비스에 대한 위협을 탐지하고 해결한다.

클라우드용 Defender는 보안 경고 및 고급 위협 방지 기능을 제공하여 환경을 방어한다.

​

**보안 경고**

클라우드용 Defender가 환경의 모든 영역에서 위협을 탐지하면 보안 경고가 생성됩니다. 

클라우드용 Defender에서 경고를 생성하거나 클라우드용 Defender가 통합 보안 제품에서 경고를 수신하는 경우 내보낼 수 있다. 

​

**Advanced Threat Protection**

클라우드용 Defender는 가상 머신, 데이터베이스, 컨테이너, 웹 애플리케이션 및 네트워크에 배포된 리소스에 고급 위협 방지 기능을 제공한다. 

Just-In-Time 액세스 및 머신에서 앱의 허용 목록을 작성하는 적응형 애플리케이션 제어를 사용하여 VM의 관리 포트를 보호한다.
