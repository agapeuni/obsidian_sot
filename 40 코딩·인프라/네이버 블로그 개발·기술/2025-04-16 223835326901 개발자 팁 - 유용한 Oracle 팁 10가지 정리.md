**1\. SQL 튜닝: 실행계획(Explain Plan) 적극 활용**

  * EXPLAIN PLAN FOR [SQL 문] 또는 DBMS_XPLAN.DISPLAY를 이용해 SQL 실행 계획을 분석한다.

  * 인덱스를 타고 가는지, Full Table Scan이 일어나는지 확인할 수 있어 성능 개선에 매우 유리하다.

EXPLAIN PLAN FOR SELECT * FROM employees WHERE department_id = 10; SELECT * FROM TABLE(DBMS_XPLAN.DISPLAY);

**​**

**2\. 바인드 변수 사용으로 파싱 비용 줄이기**

  * SQL에서 **바인드 변수**(:변수)를 사용하면 Soft Parsing으로 공유 Pool 재사용률이 올라가고 성능도 향상된다.

\-- SQL Developer에서 테스트 시에는 변수 선언 필요 VARIABLE dept_id NUMBER EXEC :dept_id := 10; SELECT * FROM employees WHERE department_id = :dept_id;

**​**

**3\. 인덱스 유무와 상태 점검하기**

  * 사용 중인 테이블의 인덱스 정보를 확인하고 필요 없는 인덱스는 제거하자.

SELECT index_name, table_name, uniqueness, status FROM user_indexes WHERE table_name = 'EMPLOYEES'; CREATE INDEX idx_employees_deptid ON employees(department_id);

​

**4\. Autotrace로 성능 측정**

  * SQL*Plus나 SQL Developer에서 AUTOTRACE 기능을 활용하면 실행 통계를 함께 볼 수 있어 좋다.

SET AUTOTRACE ON SELECT * FROM employees WHERE salary > 5000; \-- 종료 후 다시 끌 때는 \-- SET AUTOTRACE OFF

​

**5\. Rownum vs Fetch First: 오라클 버전에 따른 페이징 방식**

  * Oracle 12c 이상에서는 FETCH FIRST n ROWS ONLY로 페이징이 깔끔하게 된다.

  * 이전 버전에서는 ROWNUM이나 ROW_NUMBER() 윈도우 함수를 사용해야 한다.

\-- Oracle 12c 이상 SELECT * FROM employees ORDER BY employee_id FETCH FIRST 5 ROWS ONLY; \-- Oracle 11g 이하 SELECT * FROM ( SELECT e.*, ROWNUM AS rn FROM (SELECT * FROM employees ORDER BY employee_id) e WHERE ROWNUM <= 10 ) WHERE rn >= 6; 

​

**6\. WITH 절 (공통 테이블 표현식, CTE) 로 복잡한 쿼리 간결하게**

  * 가독성 향상 및 서브쿼리 재사용에 유리하다.

WITH dept_counts AS ( SELECT department_id, COUNT(*) AS emp_count FROM employees GROUP BY department_id ) SELECT * FROM dept_counts WHERE emp_count > 5;

**​**

**7\. PL/SQL 디버깅 도구 활용**

  * DBMS_OUTPUT.PUT_LINE으로 디버깅 메시지를 출력하거나, Oracle SQL Developer에서 디버깅 기능을 사용해 로직 오류를 쉽게 찾을 수 있다.

BEGIN DBMS_OUTPUT.ENABLE; DBMS_OUTPUT.PUT_LINE('디버깅 시작'); \-- 비즈니스 로직 DBMS_OUTPUT.PUT_LINE('로직 실행 완료'); END; 

**​**

**8\. 임시 테이블 vs 글로벌 임시 테이블**

  * 자주 사용하는 중간 처리 데이터는 글로벌 임시 테이블(GTT)을 활용하자.

  * 세션 또는 트랜잭션 단위로 데이터가 유지된다.

CREATE GLOBAL TEMPORARY TABLE temp_sales ( product_id NUMBER, amount NUMBER ) ON COMMIT DELETE ROWS; \-- 사용 예 INSERT INTO temp_sales VALUES (101, 5000); SELECT * FROM temp_sales; 

**​**

**9\. 자료형 명확히 지정하기 (특히 숫자형!)**

  * NUMBER만 쓰면 부정확한 범위가 설정된다. NUMBER(10,2)처럼 정확하게 정의해야 오류와 성능 저하를 피할 수 있다.

\-- 비추 CREATE TABLE bad_example ( price NUMBER ); \-- 추천 CREATE TABLE good_example ( price NUMBER(10, 2) -- 최대 10자리 중 소수 2자리 );

**​**

**10\. 테스트 환경에서 TRACE 활용**

  * ALTER SESSION SET SQL_TRACE = TRUE;로 트레이스를 켜고, tkprof 유틸리티로 성능 분석이 가능하다.

  * 고난도 SQL 튜닝 시 유용하다.

ALTER SESSION SET SQL_TRACE = TRUE; \-- 테스트할 쿼리 SELECT * FROM employees WHERE job_id = 'IT_PROG'; ALTER SESSION SET SQL_TRACE = FALSE; \-- 이후 tkprof로 trace 파일 분석 가능 (서버 측 접근 필요)
