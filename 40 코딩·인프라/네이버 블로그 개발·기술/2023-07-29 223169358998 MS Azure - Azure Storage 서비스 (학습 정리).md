Azure Storage 계정

스토리지 계정은 Azure Storage 데이터에 고유한 네임스페이스를 제공한다.

HTTP 또는 HTTPS를 통해 전 세계 어디에서나 액세스할 수 있다.

​

스토리지 계정을 만들 때 먼저 스토리지 계정 유형을 선택한다.

  * LRS(로컬 중복 스토리지)

  * GRS(지역 중복 스토리지)

  * RA-GRS(읽기 액세스 지역 중복 스토리지)

  * ZRS(영역 중복 스토리지)

  * GZRS(지역 영역 중복 스토리지)

  * RA-GZRS(읽기 액세스 지역 영역 중복 스토리지)

​

Storage 계정 엔드포인트

Azure Storage 계정을 사용할 경우의 데이터에 대해 Azure에 고유한 네임스페이스를 갖는다. 

계정 이름과 Azure Storage 서비스 엔드포인트의 조합이 스토리지 계정의 엔드포인트가 된다.

​

  * Blob Storage - https://<storage-account-name>.blob.core.windows.net

  * Data Lake Storage Gen2 - https://<storage-account-name>.dfs.core.windows.net

  * Azure 파일 - https://<storage-account-name>.file.core.windows.net

  * Queue storage - https://<storage-account-name>.queue.core.windows.net

  * Table Storage - https://<storage-account-name>.table.core.windows.net

​

Azure 스토리지 중복성

Azure Storage는 데이터를 보호하기 위해 항상 여러 복사본을 저장한다. 

중복성은 스토리지 계정이 오류 발생 시에도 가용성 및 내구성을 충족한다.

중복성 옵션을 결정할 때에는 저렴한 비용과 높은 가용성 간의 균형을 고려한다. 

​

기본 지역의 중복성

Azure Storage 계정의 데이터는 항상 기본 지역에서 세 번 복제된다. 

Azure Storage는 LRS(로컬 중복 스토리지) 및 ZRS(영역 중복 스토리지)를 제공한다.

​

**1) LRS(로컬 중복 스토리지)**

LRS(로컬 중복 스토리지)는 기본 지역의 단일 데이터 센터 내에서 데이터를 세 번 복제한다.

LRS는 가장 저렴한 중복성 옵션이며 다른 옵션에 비해 내구성이 가장 낮다. 

![](https://postfiles.pstatic.net/MjAyMzA3MjlfMjU5/MDAxNjkwNjA1OTM0NjI3.JVYzDj1zx2jNJ_vo72p9HF3ifrhgy3SNccn2XPtnzPkg.ay4FM4U9KPwiEJWB9MOtl_1ShVMO8mbHtDmOdIfBmNkg.PNG.agapeuni/locally-redundant-storage-37247957.png?type=w80_blur)

​

**2) ZRS(영역 중복 스토리지)**

ZRS(영역 중복 스토리지)는 주 지역의 세 가지 Azure 가용성 영역에서 Azure Storage 데이터를 동기적으로 복제한다.

ZRS를 사용하면 영역을 사용할 수 없게 되는 경우에도 읽기 및 쓰기 작업에 모두 액세스할 수 있다. 

![](https://postfiles.pstatic.net/MjAyMzA3MjlfODkg/MDAxNjkwNjA1OTQzNjk1.5UuZyT58oTO5dNFNjo4pNUoBnlS5NQhEoKWiFFXXKAkg.K8SWYVfhwYlLBp4MB84efJiQuyxWFndZZ83OGaLvxs8g.PNG.agapeuni/zone-redundant-storage-6dd46d22.png?type=w80_blur)

​

보조 지역의 중복성

높은 내구성이 필요한 경우 스토리지 계정의 데이터를 주 지역에서 수백 킬로미터 떨어진 보조 지역에 추가로 복사하도록 선택할 수 있다. 

Azure Storage는 보조 지역에 데이터를 복사하는 옵션으로 GRS(지역 중복 스토리지) 및 GZRS(지역 영역 중복 스토리지)를 제공한다.

GRS는 두 지역에서 LRS를 실행하는 것과 유사하며 GZRS는 주 지역에서 ZRS를 실행하고 보조 지역에서 LRS를 실행하는 것과 유사하다.

​

**1) 지역 중복 스토리지**

GRS는 LRS를 사용하여 주 지역의 단일 물리적 위치 내에서 데이터를 동기적으로 세 번 복사한다.

그런 다음 LRS를 사용하여 보조 지역(지역 쌍)의 단일 물리적 위치에 데이터를 비동기적으로 복사한다.

![](https://postfiles.pstatic.net/MjAyMzA3MjlfMjY3/MDAxNjkwNjA2MTYxMzk0.aiZl5hWIuEpOkBTvyzGt7VPKxl54rkmE6PierJZDVo8g.rGf9_Bzh5kjjnJTM_x199cIwm8J_uMGvCwddaMCDAXAg.PNG.agapeuni/geo-redundant-storage-3432d558.png?type=w80_blur)

**​**

**2) 지역 영역 중복 스토리지**

GZRS 스토리지 계정의 데이터는 주 지역의 Azure 가용성 영역에 복사된다. 

또한 지역 재해로부터 보호하기 위해 LRS를 사용하여 보조 지리적 지역에도 복제된다. 

![](https://postfiles.pstatic.net/MjAyMzA3MjlfMjM0/MDAxNjkwNjA2MTc0ODUw.TyGyrOw6Mk9Ixeopa7EspuUX4wn-5sLLfCMJQu2kK80g.iu-3b8S9jLTXB5KLIg0c2BoCsFGCEI-9jDKrQ0jwf58g.PNG.agapeuni/geo-zone-redundant-storage-138ab5af.png?type=w80_blur)

​

보조 지역의 데이터에 대한 읽기 액세스

지역 중복 저장소(GRS 또는 GZRS 사용)는 지역 중단을 방지하기 위해 보조 지역의 다른 물리적 위치로 데이터를 복제한다. 

단, 기본 지역에서 보조 지역으로 장애 조치(failover)를 시작하는 경우에는 해당 데이터를 읽을 수 있다. 

​

Azure Storage 서비스 설명

Azure Storage 플랫폼에는 다음과 같은 데이터 서비스가 포함된다.

  * Azure Blob: 텍스트 및 이진 데이터에 대한 확장성이 뛰어난 개체 저장소.

  * Azure Files: 클라우드 또는 온-프레미스 배포에 대한 관리되는 파일 공유.

  * Azure Queue: 애플리케이션 구성 요소 간에 안정적인 메시징을 위한 메시징 저장소.

  * Azure Disk: Azure VM용 블록 수준 스토리지 볼륨.

​

Azure Storage의 이점

  * 내구성 및 고가용성 : 일시적인 하드웨어 오류가 발생하면 데이터를 안전하게 보호. 또한 로컬 재해 또는 자연 재해로 인한 장애를 방지.

  * 보안 : Azure Storage 계정에 기록된 모든 데이터는 서비스에 의해 암호화. Azure Storage는 데이터에 액세스할 수 있는 사용자를 제어.

  * 스케일링 가능 : Azure Storage는 애플리케이션에 대한 데이터 저장소 및 성능 요구 사항을 충족하기 위해 대규모로 확장할 수 있도록 설계.

  * 관리됨 : 하드웨어 유지 관리, 업데이트 및 중요한 문제를 Azure에서 처리.

  * 액세스 가능 : Azure Storage의 데이터는 HTTP 또는 HTTPS를 통해 전 세계 어디에서든 액세스할 수 있다.

​

Blob 스토리지

Azure Blob Storage는 클라우드용 개체 스토리지 솔루션이다. 

Azure Blob Storage는 비정형이므로 보관할 수 있는 데이터의 종류에 제한이 없다. 

방대한 양의 데이터를 저장할 수 있다. Blob은 일반적인 파일 형식으로 제한되지 않는다. 

​

**Blob Storage 액세스**

Blob Storage의 개체는 HTTP 또는 HTTPS를 통해 전 세계 어디에서든 액세스할 수 있다. 

스토리지 클라이언트 라이브러리는 .NET, Java, Node.js, Python, PHP 및 Ruby를 비롯한 여러 언어에서 사용할 수 있다.

​

**Blob Storage 계층**

클라우드에 저장된 데이터가 기하급수적으로 증가할 수 있다. 

클라우드에 저장된 데이터는 생성, 처리 및 액세스하는 방법에 따라 다르게 처리될 수 있다. 

Azure에서는 액세스 요구 사항에 따라 스토리지 비용의 균형을 맞추는 데 사용할 수 있는 액세스 계층을 제공한다.

​

Azure Storage는 Blob Storage에 대해 서로 다른 액세스 계층을 제공한다. 

  * 핫 액세스 계층: 자주 액세스하는 데이터를 저장.

  * 쿨 액세스 계층: 자주 액세스하지 않고 30일 이상 저장.

  * 보관 액세스 계층: 거의 액세스하지 않고 180일 이상 보관하며 장기 백업이 있는 데이터.

​

Azure 파일

Azure Files는 SMB 프로토콜 또는 NFS를 통해 액세스할 수 있는, 완전 관리형 파일 공유를 클라우드에서 제공한다.

SMB Azure 파일 공유는 Windows, Linux, macOS 클라이언트에서 액세스할 수 있다. 

NFS Azure Files 공유는 Linux 또는 macOS 클라이언트에서 액세스할 수 있다. 

​

​

**Azure Files 주요 이점:**

  * 공유 액세스: Azure 파일 공유는 산업 표준 SMB 및 NFS 프로토콜을 지원한다.

  * 완전 관리형: Azure 파일 공유는 하드웨어 또는 OS를 관리할 필요 없다.

  * 스크립팅 및 도구 : PowerShell 및 Azure CLI를 사용. Azure Portal 및 Azure Storage Explorer를 사용.

  * 복원력: Azure Files는 처음부터 항상 사용할 수 있도록 빌드 되었다.

  * 친숙한 프로그래밍 기능: Azure에서 실행 중인 애플리케이션은 파일 시스템 I/O API를 통해 공유 데이터에 액세스할 수 있다.

​

Queue Storage

Azure Queue Storage는 대량의 메시지를 저장하기 위한 서비스다. 

전 세계 어디서나 인증된 호출을 통해 HTTP 또는 HTTPS를 사용하여 메시지에 액세스할 수 있다. 

큐는 비동기적으로 처리할 작업의 백로그를 만드는 데 일반적으로 사용된다.

​

디스크 스토리지

디스크 스토리지 또는 Azure 관리 디스크는 Azure VM에서 사용하기 위해 Azure에서 관리하는 블록 수준 스토리지 볼륨이다.

개념적으로 실제 디스크와 동일하지만 가상화되어 실제 디스크보다 더 높은 복원력과 가용성을 제공한다.

​

Azure Migrate

  * 통합 마이그레이션 플랫폼: Azure로의 마이그레이션을 시작, 실행 및 추적하는 단일 포털이다.

  * 도구 범위: 검색 및 평가, 서버 마이그레이션에 사용할 도구다.

  * 평가 및 마이그레이션: Azure Migrate 허브에서 온-프레미스 인프라를 평가하고 Azure로 마이그레이션할 수 있다.

​

통합 도구

  * Azure Migrate 검색 및 평가 : VMware, Hyper-V 및 물리적 서버가 실행되는 온-프레미스 서버를 검색하고 평가한다.

  * Azure Migrate 서버 마이그레이션 : VMware VM, Hyper VM, 기타 가상화된 서버 및 퍼블릭 클라우드 VM을 Azure로 마이그레이션한다.

  * Data Migration Assistant : Data Migration Assistant는 SQL Server를 평가하는 독립 실행형 도구다.

  * Azure Database 마이그레이션 서비스 : 온-프레미스 데이터베이스를 Azure VM으로 마이그레이션한다.

  * 웹앱 Migration Assistant : Azure App Service으로 마이그레이션하기 위한 온-프레미스 웹 사이트를 평가하는 독립 실행형 도구다. 

  * Azure Data Box : Azure Data Box 제품을 사용하여 대량의 오프라인 데이터를 Azure로 이동한다.

​

Azure Data Box

Azure Data Box는 빠르고 저렴하며 신뢰할 수 있는 방식으로 대량의 데이터 전송을 지원하는 물리적 마이그레이션 서비스다. 

Data Box는 지역 이동 통신 사업자를 통해 데이터 센터와 송수신한다. 전송 중에 Data Box가 손상되는 것을 방지하고 보호한다.

​

Azure Portal을 통해 Data Box 디바이스를 주문하여 Azure에서 데이터를 가져오거나 내보낼 수 있다. 

Azure로의 데이터 송수신이 완료되면 Data Box를 반환하면 된다.

​

사용 사례

Data Box는 네트워크 연결에 제한이 없는 환경에서 40TB 이상 데이터 크기를 전송하는 데 아주 적합하다.

데이터 이동은 일회성 전송, 정기적 전송 또는 초기 대량 데이터 전송 후의 정기적 전송일 수 있다.

가져오기 순서의 데이터가 Azure에 업로드되면 디바이스의 디스크는 완전히 초기화된다.

내보내기 순서의 경우 디바이스가 Azure 데이터 센터에 도달하면 디스크가 지워진다.

​

AzCopy

AzCopy는 스토리지 계정에서 또는 스토리지 계정으로 BLOB 또는 파일을 복사하는 데 사용할 수 있는 명령줄 유틸리티다. 

AzCopy를 사용하면 파일을 업로드하고, 파일을 다운로드하고, 스토리지 계정 간에 파일을 복사하고, 파일을 동기화할 수도 있다.

​

Azure Storage Explorer

Azure Storage Explorer는 Azure Storage 계정에서 파일 및 BLOB을 관리하는 그래픽 인터페이스를 제공하는 독립 실행형 앱이다.

Windows, macOS 및 Linux 운영 체제에서 작동하며 백 엔드에서 AzCopy를 사용하여 모든 파일 및 BLOB 관리 작업을 수행한다.

​

Azure 파일 동기화

Azure Files에서 파일 공유를 중앙 집중화하고 Windows 파일 서버의 유연성, 성능 및 호환성을 유지하게 해주는 도구다. 

로컬 Windows 서버에 Azure 파일 동기화를 설치하면 Azure의 파일과 양방향 동기화가 자동으로 유지된다.
