1\. CVS

프로젝트에서 형상관리를 처음 사용한 것은 2003년도 CVS (Concurrent Versions System)였다. 이전에는 프로젝트에 참여하고 있는 인원이 적어 별다른 불편함 없이 로컬에서 작업하거나 에디터에서 FTP 접속을 하여 서버 파일에 작업을 하였다. 그러다가 프로젝트 규모가 커지고 하나의 파일을 여러 명이 작업하는 상황이 되어 CVS를 사용하게 되었다.

​

CVS는 소스 코드의 변경 사항을 중앙 서버에 저장하고, 개발자들은 중앙 서버에서 소스 코드를 받아와 작업을 진행했다. 이러한 방식은 간단하고 직관적이었지만, 여러 개발자가 동시에 작업할 때 충돌이 발생할 수 있었다. 또한 CVS는 디렉터리 단위의 버전 관리나 복잡한 브랜치 관리를 지원하지 않았다.

​

​

2\. SVN

그렇게 시간이 흐른 뒤 SVN (Subversion)이 등장했고 2009년에 SVN을 접하게 되었다. CVS와 마찬가지로 소프트웨어 개발에서 사용되는 버전 관리 시스템으로, 코드 변경 이력을 추적하고 팀 협업을 도와주는 도구이다. SVN은 CVS의 단점을 보완하면서 중앙 집중식 버전 관리 시스템의 개선된 형태였다. SVN은 CVS와 유사한 인터페이스를 제공하지만, 디렉터리 단위의 버전 관리와 원자적 커밋을 가능하게 했다. 또한 SVN은 복잡한 브랜치와 병합 관리를 강화하여 프로젝트의 유연성을 높였다.

​

그러나 SVN도 중앙 서버와의 네트워크 의존성이 있었습니다. 중앙 서버가 다운되거나 네트워크에 문제가 생기면 작업이 어려워지는 단점이 있었다. 요즘에는 Git과 같은 분산 버전 관리 시스템이 CVS와 SVN을 대체하고 있다. Git은 네트워크 연결 없이도 로컬에서 작업할 수 있고, 복잡한 브랜치와 병합을 효과적으로 다룰 수 있다. CVS와 SVN은 과거의 유산이지만, 그 기반과 아이디어는 현대의 버전 관리 시스템 발전에 큰 영향을 주었다.

​

​

3\. Git

Git은 분산 버전 관리 시스템(Distributed Version Control System, DVCS)의 하나로, 파일이나 소스 코드의 변경 사항을 추적하고 여러 명의 개발자가 협업하여 작업할 수 있는 도구이다. Git은 프로젝트의 히스토리를 기록하고 변경 사항을 추적하여 특정 시점으로 이동하거나 다른 브랜치에서 작업할 수 있는 유용한 기능을 제공한다. Git은 로컬 환경에서 작업하고 GitHub을 통해 원격 저장소와 협업하며 프로젝트를 관리할 수 있는 강력한 툴이다.

​

이제는 프로젝트를 시작하면 바로 Git부터 설치한다. Git이 너무 익숙해져 그렇게 오랫동안 사용해 왔던 SVN이 낯설어졌다. 약간의 의미 있는 작업에도 바로 커밋 로그와 함께 Git에 저장한다. Git과 함께 아틀라시안에서 제작한 소스트리(SourceTree)를 사용하고 있는데 GUI 화면으로 관리할 수 있어 더 직관적이고 편리하다.

​

​

4\. Github

Github는 Git을 기반으로 한 코드 호스팅 플랫폼 중 하나로, Git 저장소를 온라인으로 호스팅하고 여러 사용자가 협업할 수 있는 환경을 제공한다. Github를 통해 개발자들은 프로젝트를 관리하고 다른 사람과 소통하며 버전 관리를 할 수 있다. private 저장소로 무료로 사용할 수가 있어 작업하는 코드나 학습하는 코드를 저장해 두고 어디서나 쉽게 참고한다.
