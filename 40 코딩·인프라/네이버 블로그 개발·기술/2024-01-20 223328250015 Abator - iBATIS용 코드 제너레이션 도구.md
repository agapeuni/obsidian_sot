프로젝트에서 iBATIS를 사용할 때 Abator 코드 생성기를 활용했다. Aabator는 iBATOR로 명칭이 변경된다. 그리고 나중에 iBATIS Abator는 MyBatis Generator로 되었다. Abator를 사용함으로써 개발 효율이 높아졌느냐고 물어본다면, 직접 써보고 판단하라고 얘기하고 싶다. 크게 얻는 것도 잃을 것도 없는 듯 하다. 

​

​

**1\. Abator 개요**

iBATIS Abator는 자바 기반의 오픈 소스 개발 도구로, 데이터베이스와 상호 작용하는 데 사용되는 코드 생성 도구이다. Abator는 데이터베이스의 테이블에 접근하기 위한 iBatis 연관 코드들인 Object와 환경 설정 파일(configuration file)을 생성하며, 기본적인 CRUD (Create, Retrieve, Update, Delete) 쿼리를 포함한다. iBATIS Abator를 사용하면 개발자는 데이터베이스와의 상호 작용을 처리하는 코드를 직접 작성할 필요가 없으며, 자동 생성된 코드를 통해 생산성을 향상시킬 수 있다. 

​

iBATIS Abator는 데이터베이스 스키마를 기반으로 자동으로 Java 모델 객체, MyBatis SQL 매핑 파일, DAO (Data Access Object) 등을 생성한다. 이를 통해 개발자는 반복적이고 일상적인 작업에서 자유로워지고, 효율적인 개발을 할 수 있다. iBATIS Abator는 다양한 데이터베이스에 대한 지원을 제공한다. 주요 관계형 데이터베이스 시스템과 연동하여 사용할 수 있다.

​

Abator가 생성하는 코드(파일) 목록은 다음과 같다. 

  * 테이블 구조에 매치되는 자바 POJOs

  * iBator호환 SQL Map XML 파일들

  * DAO 인터페이스와 구현 클래스들

​

**2) Abator 실행(Run)**

커맨드 라인을 열고 다음과 같이 입력하여 Abator를 실행할 수 있다. 

단, 설정 파일에 정의된 targetProject의 대상 디렉터리는 반드시 미리 존재해야 한다.

java -jar abator.jar abatorConfig.xml false java -jar abator.jar abatorConfig.xml true java -cp abator.jar org.apache.ibatis.abator.api.AbatorRunner abatorConfig.xml false java -cp abator.jar org.apache.ibatis.abator.api.AbatorRunner abatorConfig.xml true

여기서 파라미터의 의미는 다음과 같다. 

  * 첫번째 파라미터: 환경 파일의 경로

  * 두번째 파라미터: 파일이 이미 존재할 경우 overwrite 여부

abator 실행을 위한 배치 파일을 만들어 놓으면 편하다. 다음과 같이 “abator.bat” 파일을 만든다.

java -jar abator.jar abatorConfig.xml true
