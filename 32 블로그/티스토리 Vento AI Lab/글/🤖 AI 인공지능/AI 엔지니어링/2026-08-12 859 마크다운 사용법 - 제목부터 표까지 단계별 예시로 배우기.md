# 마크다운 사용법 - 제목부터 표까지 단계별 예시로 배우기

- 원문: https://agapeuni.tistory.com/859
- 게시일: 2026-08-12T00:42:22+09:00
- 분류: 🤖 AI 인공지능/AI 엔지니어링

## 본문

![[03 Attachments/티스토리 Vento AI Lab/859/859-001-인공지능-텍스트-001.png]]

마크다운 문법은 처음 접하면 기호가 많아 어렵게 느껴질 수 있지만, 몇 가지 기본 규칙만 익히면 문서를 훨씬 빠르고 깔끔하게 작성할 수 있다. 특히 개발 문서, README, 블로그 초안, Obsidian 같은 지식관리 도구를 사용할 때 마크다운은 가장 자주 접하게 되는 문서 작성 방식 중 하나다. 복잡한 편집 기능을 배우지 않아도 텍스트만으로 제목, 목록, 링크, 표, 코드 등을 표현할 수 있다는 점이 가장 큰 장점이다.

마크다운 문법은 텍스트 앞뒤에 간단한 기호를 붙여 서식을 지정하는 가벼운 문서 작성 방식으로, 커밋 메시지 본문, 이슈, PR 설명, 팀 위키까지 개발자의 일상 곳곳에서 쓰인다. 처음에는 기호가 낯설게 느껴질 수 있지만, 아래 단계를 순서대로 따라 하며 직접 입력해 보면 하루면 충분히 익힐 수 있다.

## 마크다운이란 무엇인가

마크다운의 기본 원리는 간단하다. 문장 앞이나 주변에 특정 기호를 붙이면 해당 부분에 의미와 형식이 부여된다. 별도의 편집 도구 없이도 글의 구조를 표현할 수 있기 때문에 문서 작성 속도가 빠르고, 다양한 서비스와 개발 도구에서 폭넓게 활용된다.

처음부터 모든 문법을 외울 필요는 없다. 제목, 강조, 목록처럼 자주 사용하는 기능부터 익힌 뒤 필요한 문법을 하나씩 추가하는 방식이 가장 효율적이다.

## 제목은 # 기호로 구분한다

가장 먼저 익혀야 할 것은 제목이다. 제목은 # 기호를 사용하며, 기호의 개수가 많아질수록 제목의 단계가 낮아진다.

예를 들어 # 마크다운 문법은 가장 큰 제목이고, ## 기본 문법, ### 제목 작성 방법처럼 단계별로 구분할 수 있다. 긴 문서를 작성할 때 제목 단계를 일정하게 유지하면 글의 전체 구조를 한눈에 파악하기 쉬워진다.

HTML의 h1, h2, h3, h4 태그와 정확히 대응한다고 생각하면 이해가 빠르다. 주의할 점은 # 뒤에 반드시 공백을 한 칸 넣어야 한다는 것이다. 공백이 없으면 일부 환경에서 제목으로 인식되지 않고 서직으로 인식된다.

```
# 프로젝트 이름
## 설치 방법
### 사전 준비물
#### 파일명
```

## 중요한 내용은 굵게 강조한다

문장에서 특정 내용을 강조할 때는 굵게 표시하거나 기울임을 사용할 수 있다.

**중요한 내용**처럼 별표 두 개로 감싸면 굵은 글씨가 되고, *강조할 내용*처럼 별표 하나로 감싸면 기울임으로 표현된다. 두 가지를 함께 사용하려면 ***매우 중요한 내용***처럼 작성할 수 있다.

다만 강조 표현을 지나치게 많이 사용하면 오히려 핵심이 잘 보이지 않을 수 있다. 중요한 개념이나 주의해야 할 부분에 제한적으로 사용하는 것이 좋다.

기울임은 별표 하나, 굵게는 두 개, 둘을 합치면 세 개다. 밑줄(_)로도 같은 효과를 낼 수 있지만, 파일명이나 변수명에 밑줄이 자주 들어가는 개발 문서에서는 별표를 쓰는 편이 충돌을 피하기 좋다.

```
*기울임* 또는 _기울임_
**굵게** 또는 __굵게__
***굵은 기울임***
```

## 목록은 정보를 정리할 때 유용하다

순서가 필요 없는 목록은 - 또는 * 기호를 이용한다.

예를 들어 - 마크다운, - HTML, - Python처럼 작성하면 글머리표 목록으로 표시된다. 여러 개념이나 준비물, 참고 사항을 정리할 때 유용하다.

순서가 중요한 경우에는 1. 설치, 2. 설정, 3. 실행과 같이 숫자와 마침표를 사용한다. 작업 절차나 학습 순서처럼 단계가 중요한 내용을 설명할 때 적합하다.

하위 항목은 앞에 공백 두 칸 또는 네 칸을 넣어 들여쓰기하면 된다. 숫자 목록은 실제 숫자가 틀려도 렌더링될 때 자동으로 순서가 매겨지므로, 모두 1로 써 두면 나중에 항목을 추가하거나 순서를 바꿀 때 수정할 필요가 없다.

```
- 사과
- 배
  - 배 하위 항목

1. 저장소를 클론한다
2. 의존성을 설치한다
3. 서버를 실행한다
```

## 링크와 이미지는 비슷한 방식으로 작성한다

다른 문서나 웹페이지로 이동할 수 있는 링크도 간단하게 만들 수 있다.

[OpenAI]([https://openai.com)](https://openai.com))처럼 대괄호 안에 화면에 표시할 문구를 넣고, 바로 뒤 괄호 안에 주소를 입력하면 된다.

이미지는 구조가 비슷하지만 앞에 느낌표를 추가한다. ![이미지 설명](image.jpg)와 같은 형태다. 문서 안에서 참고 자료를 연결하거나 설명용 이미지를 삽입할 때 자주 사용된다.

이미지는 링크와 구조가 같고 앞에 느낌표(!) 하나만 추가된다. 대괄호 안의 텍스트는 이미지가 로드되지 않을 때 표시되는 대체 텍스트 역할을 하므로 비워 두지 않는 것이 좋다.

```
[공식 문서](https://example.com)
![로고 이미지](./images/logo.png)
```

## 인용문은 > 기호를 사용한다

다른 사람의 말이나 참고할 문장을 별도로 표시하고 싶다면 문장 앞에 > 기호를 붙이면 된다.

예를 들어 > 좋은 기록은 다시 활용할 수 있는 지식이 된다.처럼 작성하면 일반 문장과 구분된 인용 형식으로 표시된다.

책의 문장을 기록하거나 회의에서 나온 중요한 발언, 참고 문구를 정리할 때 활용하기 좋다.

```
> 이 프로젝트는 간단한 API를 구현한다.
> Node.js 18 이상이 필요하다.

---
```

## 코드와 명령어는 백틱으로 구분한다

프로그래밍 코드나 명령어를 작성할 때는 백틱을 사용한다.

문장 안에서 python이나 git status처럼 짧은 코드를 표현하려면 백틱 하나로 감싸면 된다. 이렇게 하면 일반 문장과 명령어나 코드가 명확하게 구분된다.

여러 줄의 코드를 작성할 때는 백틱 세 개를 코드 앞뒤에 배치한다. 여기에 python, javascript, bash 같은 언어 이름을 함께 적으면 이를 지원하는 편집기에서는 코드가 더욱 읽기 쉽게 표시된다. 여는 백틱 세 개 바로 뒤에 javascript, python처럼 언어 이름을 적으면 해당 언어에 맞는 문법 강조가 적용되어 코드 가독성이 크게 좋아진다. 습관처럼 언어 이름을 붙이는 것을 권한다.

```
`npm install` 명령어를 실행한다

```javascript
const greeting = "hello";
console.log(greeting);
```
```

## 표는 여러 정보를 비교할 때 유용하다

표는 여러 항목을 한눈에 비교해야 할 때 유용하다.

| 항목 | 설명 |처럼 세로 막대 기호로 열을 구분하고, 두 번째 줄에 | --- | --- | 형태의 구분선을 넣으면 표가 만들어진다. 이후 같은 형식으로 데이터를 추가하면 된다.

프로그램 비교, 기능 정리, 일정 관리, 작업 현황처럼 여러 정보를 일정한 기준으로 비교해야 할 때 특히 효과적이다.

## 체크리스트로 작업 상태를 관리한다

마크다운에서는 간단한 체크리스트도 작성할 수 있다.

- [ ] 해야 할 일은 완료하지 않은 항목을 의미하고, - [x] 완료한 일은 끝난 작업을 나타낸다.

개인 할 일이나 프로젝트 작업 목록을 관리할 때 별도의 복잡한 도구 없이도 진행 상태를 간단하게 확인할 수 있다.

## 마크다운은 외우기보다 직접 사용해 보는 것이 좋다

마크다운 문법을 익힐 때 모든 규칙을 한 번에 외울 필요는 없다. 제목, 강조, 목록, 링크, 코드 정도의 기본 문법부터 사용하고 필요에 따라 표나 체크리스트를 추가하는 방식이 효율적이다.

중요한 것은 문법 자체보다 정보를 어떤 구조로 정리할 것인가에 있다. 마크다운은 화려한 편집 도구라기보다 내용의 구조를 단순한 기호로 표현하는 방법에 가깝다.

기본 문법에 익숙해지면 메모부터 기술 문서, 블로그 초안, 프로젝트 기록까지 하나의 방식으로 관리할 수 있다. 처음에는 몇 가지 기호를 확인하면서 작성해야 하지만 반복해서 사용하다 보면 자연스럽게 익숙해진다. 결국 마크다운을 배우는 가장 좋은 방법은 문법을 외우는 것이 아니라 실제 문서를 직접 작성하면서 필요한 기능을 하나씩 적용해 보는 것이다.
