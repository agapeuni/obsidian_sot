# OpenClaw - SOUL·IDENTITY·USER·AGENTS 역할 정리

- 원문: https://agapeuni.tistory.com/857
- 게시일: 2026-08-04T15:52:03+09:00
- 분류: 🧠 AI 자동화/AI 에이전트

## 본문

![[03 Attachments/티스토리 Vento AI Lab/857/857-001-AI-Agent-001.png]]

OpenClaw의 SOUL.md, IDENTITY.md, USER.md, AGENTS.md는 모두 workspace 시작 시 컨텍스트로 주입되는 핵심 부트스트랩 파일입니다. 다만 담당 영역이 다릅니다. 공식 문서 기준으로 AGENTS.md는 운영 지침, SOUL.md는 성격·경계·말투, IDENTITY.md는 에이전트의 이름과 외형적 정체성, USER.md는 사용자의 프로필과 선호를 담당합니다.

```
~/.openclaw/workspace/
├── AGENTS.md
├── HEARTBEAT.md
├── IDENTITY.md
├── MEMORY.md
├── SOUL.md
├── TOOLS.md
└── USER.md
```

핵심 구분은 다음 한 문장으로 정리할 수 있습니다.

> IDENTITY.md는 “나는 누구인가”, SOUL.md는 “나는 어떤 태도로 행동하는가”, AGENTS.md는 “업무를 어떻게 수행하는가”, USER.md는 “누구를 위해 일하는가”를 정의합니다.

## 1. SOUL.md

SOUL.md는 에이전트의 성격, 가치관, 말투, 행동 경계와 금지 원칙을 정의합니다. OpenClaw 공식 문서에서는 이를 에이전트의 persona, boundaries, tone을 담당하는 파일로 설명합니다. 일반 세션에 직접 주입되므로 응답 스타일과 판단 방식에 실제로 큰 영향을 줍니다.

주요 역할은 다음과 같습니다.

- 응답 말투와 분위기

- 사용자를 대하는 태도

- 적극성, 신중성, 유머 사용 수준

- 불확실할 때의 행동 방식

- 개인정보 및 보안 경계

- 절대 수행하지 말아야 할 행동

- 에이전트가 중요하게 여기는 가치

예를 들어 SOUL.md에는 다음과 같은 내용이 들어갈 수 있습니다.

```
# SOUL.md

나는 사용자의 업무 자동화를 지원하는 신중하고 실행 중심적인 AI 에이전트다.

## 기본 태도

- 설명보다 실행 가능한 결과를 우선한다.
- 명령 실행 전 영향 범위를 확인한다.
- 삭제, 덮어쓰기, 외부 게시 작업은 보수적으로 처리한다.
- 불확실한 정보는 추측하지 않고 확인한다.
- 사용자의 승인 없이 민감정보를 외부로 전송하지 않는다.

## 커뮤니케이션

- 한국어로 명확하고 간결하게 답변한다.
- 실행 결과, 실패 원인, 다음 조치를 구분해 보고한다.
- 과도한 감정 표현이나 불필요한 농담을 사용하지 않는다.

## 보안 경계

- API 키, 토큰, 비밀번호를 응답에 그대로 출력하지 않는다.
- 삭제 작업은 백업 또는 사용자 확인 후 수행한다.
- 블로그·SNS 게시 전 최종 산출물을 검증한다.
```

실무적으로 SOUL.md에는 업무 절차를 너무 많이 넣지 않는 것이 좋습니다. “어떤 성향과 원칙으로 판단할 것인가”에 집중하고, 상세 실행 절차는 AGENTS.md에 분리하는 편이 유지보수에 유리합니다.

## 2. IDENTITY.md

IDENTITY.md는 에이전트의 표시 정체성을 정의합니다. 공식 템플릿에서는 이름, 존재 유형, 분위기, 대표 이모지, 아바타를 저장하도록 되어 있습니다.

주요 역할은 다음과 같습니다.

- 에이전트 이름

- 에이전트 유형 또는 역할 이미지

- 대표 분위기

- 시그니처 이모지

- 아바타 경로

- 사용자에게 자신을 어떻게 소개할지에 대한 기본 정보

예시는 다음과 같습니다.

```
# IDENTITY.md

- Name: OneWay
- Creature: AI 업무 자동화 오케스트레이터
- Vibe: 차분하고 정확하며 실행 중심
- Emoji: 🧭
- Avatar: avatars/oneway.png
```

공식 형식에서는 - Label: value 형태의 필드가 파싱되며, 라벨은 대소문자를 구분하지 않습니다. 아바타는 workspace 기준 상대 경로, URL 또는 데이터 URI를 사용할 수 있습니다.

IDENTITY.md와 SOUL.md의 차이는 다음과 같습니다.

| 구분 | IDENTITY.md | SOUL.md |
| --- | --- | --- |
| 중심 질문 | 나는 누구인가 | 나는 어떻게 생각하고 행동하는가 |
| 내용 | 이름, 유형, 분위기, 이모지, 아바타 | 말투, 가치, 태도, 판단 원칙, 경계 |
| 변경 빈도 | 낮음 | 운영 경험에 따라 조정 가능 |
| 영향 | 자기소개 및 정체성 표현 | 실제 답변 방식과 행동 판단 |

IDENTITY.md에는 긴 업무 규칙을 넣지 않는 것이 좋습니다. 이 파일은 짧고 안정적으로 유지하는 편이 적절합니다.

## 3. USER.md

USER.md는 에이전트가 지원하는 사용자 또는 책임자의 프로필을 정의합니다. 공식 문서에서는 사용자 프로필과 선호 호칭을 담는 파일로 설명합니다.

주요 역할은 다음과 같습니다.

- 사용자 이름과 호칭

- 언어와 시간대

- 직무와 전문 수준

- 주요 관심 분야

- 현재 목표

- 선호하는 응답 형식

- 피해야 할 설명 방식

- 자주 사용하는 시스템과 환경

- 장기적으로 유효한 작업 맥락

다음과 같이 구성할 수 있습니다.

```
# USER.md

## 기본 정보

- 이름: [사용자이름]
- 선호 호칭: 한길
- 언어: 한국어
- 시간대: Asia/Seoul
- 역할: 프로젝트 관리자, AI 엔지니어, 작가, 1인 기업 운영

## 전문 배경

- 웹 프로그래밍 실무 경험 26년 이상
- 대기업 프로젝트 관리 및 시스템 구축 경험
- Java, Spring Boot, Python, Vue.js, Docker, Linux 사용
- LLM, RAG, MCP, AI Agent를 집중적으로 학습 및 적용 중

## 주요 목표

- Telegram을 통한 OpenClaw 원격 명령
- MSI 노트북과 내담 GPU 서버 연계
- 콘텐츠 생성, 검수, 이미지 생성, 블로그·SNS 배포 자동화
- 사내 AI 서비스와 기술 자산 구축

## 응답 선호

- 초급 개념 설명보다 실무 적용 중심으로 답변
- 실행 절차, 명령어, 검증 방법을 포함
- 보안, 장애 대응, 운영 관점을 함께 고려
- 불확실한 내용은 명시적으로 구분
```

주의할 점은 USER.md가 세션 컨텍스트에 들어간다는 것입니다. 여러 사람이 동일한 Telegram Bot이나 OpenClaw 에이전트에 접근할 경우, USER.md의 개인정보가 다른 사용자 응답에 노출될 위험이 있습니다. 실제로 다중 사용자 환경에서 소유자 정보가 다른 발신자에게 노출될 수 있다는 이슈가 보고된 바 있습니다.

따라서 다음 정보는 USER.md에 직접 넣지 않는 것이 좋습니다.

- 비밀번호

- API 키

- Telegram Bot Token

- 주민등록번호

- 상세 주소

- 개인 이메일 인증정보

- 서버 접속 비밀번호

- 금융정보

- 외부에 노출되면 문제가 되는 회사 내부정보

## 4. AGENTS.md

AGENTS.md는 에이전트의 업무 운영 규칙과 실행 절차를 정의합니다. 공식 문서에서는 operating instructions, role, responsibilities, standing orders를 담당한다고 설명합니다.

네 파일 중 실제 업무 수행 방식에 가장 직접적인 영향을 주는 파일입니다.

주요 역할은 다음과 같습니다.

- 에이전트의 역할과 책임

- 세션 시작 시 확인할 항목

- 작업 수행 순서

- 도구 사용 원칙

- 파일 생성·수정·삭제 규칙

- 명령 실행 전후 검증 절차

- 실패 시 처리 방식

- 결과 보고 형식

- 장기 메모리 기록 기준

- 서브에이전트 또는 외부 시스템 연계 규칙

예시는 다음과 같습니다.

```
# AGENTS.md

## 역할

이 에이전트는 사용자의 개인 업무 자동화 오케스트레이터다.

주요 책임:

1. Telegram 명령을 해석한다.
2. 노트북에서 로컬 작업을 수행한다.
3. 필요한 경우 내담 GPU 서버에 원격 작업을 요청한다.
4. 생성된 결과물을 수집하고 검증한다.
5. 승인된 콘텐츠를 블로그와 SNS에 배포한다.

## 작업 원칙

- 먼저 요청 목적과 영향 범위를 확인한다.
- 읽기 작업은 즉시 수행할 수 있다.
- 파일 수정 전 원본을 백업한다.
- 삭제, 덮어쓰기, 외부 게시 작업은 사전 확인한다.
- 명령 실패 시 반복 실행 전에 원인을 분석한다.
- 성공 여부는 명령 종료 코드와 산출물로 검증한다.

## 파일 작업 규칙

- 핵심 workspace 파일을 임의 삭제하지 않는다.
- 기존 파일을 덮어쓸 경우 타임스탬프 백업을 생성한다.
- 임시 파일은 tmp/에 저장한다.
- 최종 산출물은 outputs/에 저장한다.
- 비밀정보는 Markdown 파일에 기록하지 않는다.

## 원격 서버 작업

- GPU 작업은 내담 서버에서 수행한다.
- 원격 작업 요청 시 입력값, 출력 경로, 타임아웃을 명시한다.
- 결과 파일의 존재 여부와 크기를 검증한다.
- 실패 로그를 MSI 노트북에 저장한다.

## 외부 게시

- 게시 전 제목, 본문, 이미지, 해시태그를 검증한다.
- 중복 게시 여부를 확인한다.
- 게시 결과 URL 또는 게시 ID를 기록한다.
- 실패 시 자동 재게시하지 않고 오류를 보고한다.

## 결과 보고 형식

1. 수행한 작업
2. 성공 또는 실패 상태
3. 생성·수정된 파일
4. 주요 로그
5. 후속 조치
```

기본 AGENTS.md 템플릿은 세션 시작 시 SOUL.md, USER.md, 최근 메모리 및 MEMORY.md를 참고하도록 구성되기도 합니다. 다만 최근 버전에서는 일부 파일이 이미 런타임 컨텍스트에 주입되므로 다시 읽는 작업은 토큰과 도구 호출을 낭비할 수 있습니다. 공식 최신 템플릿도 런타임이 제공한 시작 컨텍스트를 우선 사용하고, 필요한 경우에만 파일을 다시 읽도록 안내합니다.

## 각각의 md 파일의 관계

각각의 md 파일은 독립 문서가 아니라 하나의 에이전트 설정 체계를 구성합니다.

```
USER.md
  └─ 누구를 지원하는가

IDENTITY.md
  └─ 에이전트가 누구인가

SOUL.md
  └─ 어떤 가치와 태도로 행동하는가

AGENTS.md
  └─ 실제 업무를 어떤 절차로 수행하는가
```

예를 들어 사용자가 “블로그 글을 작성하고 게시해”라고 명령했을 때 처리 방식은 다음과 같습니다.

```
USER.md
→ 사용자가 한국어 실무형 콘텐츠와 퍼스널 브랜딩을 선호함을 확인

IDENTITY.md
→ OneWay라는 업무 자동화 오케스트레이터 정체성 적용

SOUL.md
→ 신중하고 정확하게 작업하며 무단 외부 게시를 피함

AGENTS.md
→ 초안 생성 → 검수 → 이미지 확인 → 사용자 승인 → 게시 → 결과 기록
```

## 작성 시 중복을 피하는 기준

같은 내용을 여러 파일에 반복하면 서로 충돌하거나 토큰을 낭비할 수 있습니다.

| 내용 | 적합한 파일 |
| --- | --- |
| 에이전트 이름이 OneWay다 | IDENTITY.md |
| 차분하고 정확하게 답한다 | SOUL.md |
| 사용자는 한국어를 선호한다 | USER.md |
| 삭제 전에 백업한다 | AGENTS.md |
| API 키를 노출하지 않는다 | SOUL.md 또는 AGENTS.md |
| 결과 파일은 outputs에 저장한다 | AGENTS.md |
| 사용자는 LLM과 RAG에 관심이 있다 | USER.md |
| 에이전트 대표 이모지는 🧭이다 | IDENTITY.md |

보안 원칙처럼 행동 철학에 해당하는 내용은 SOUL.md, 구체적인 실행 절차는 AGENTS.md에 두는 방식이 좋습니다.

예를 들어 다음과 같이 나눕니다.

```
# SOUL.md
민감정보와 사용자 데이터를 보호한다.
```

```
# AGENTS.md
API 키, 토큰, 비밀번호가 포함된 출력은 마스킹한다.
로그 저장 전 Authorization 헤더를 제거한다.
```

## 운영 권장 기준

IDENTITY.md는 10줄 안팎, SOUL.md는 30~80줄, USER.md는 30~100줄, AGENTS.md는 50~200줄 정도가 관리하기 편합니다. 절대 제한은 아니지만, 이 파일들은 기본 컨텍스트에 주입되므로 너무 길어지면 매 세션 토큰 사용량이 증가합니다. OpenClaw는 이들 workspace 파일을 기본 컨텍스트로 주입합니다.

파일별 변경 주기는 다음이 적절합니다.

- IDENTITY.md: 에이전트 이름이나 역할이 바뀔 때

- SOUL.md: 말투, 판단 태도, 보안 경계를 개선할 때

- USER.md: 사용자 환경이나 장기 목표가 바뀔 때

- AGENTS.md: 작업 흐름, 도구, 승인 절차, 운영 정책이 바뀔 때

또한 workspace 파일을 수정하기 전에는 Git 또는 별도 백업을 사용하는 것이 안전합니다. 과거 일부 버전에서 설정이나 진단 명령 수행 과정에서 workspace Markdown 파일이 덮어써졌다는 이슈 보고도 있습니다.

최종적으로는 다음 원칙으로 관리하면 됩니다.
