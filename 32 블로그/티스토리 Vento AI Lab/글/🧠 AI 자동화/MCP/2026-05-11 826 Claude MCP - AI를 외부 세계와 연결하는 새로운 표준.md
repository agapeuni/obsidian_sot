# Claude MCP - AI를 외부 세계와 연결하는 새로운 표준

- 원문: https://agapeuni.tistory.com/826
- 게시일: 2026-05-11T02:53:09+09:00
- 분류: 🧠 AI 자동화/MCP

## 본문

![[03 Attachments/티스토리 Vento AI Lab/826/826-001-인공지능-에이전트-001_(2).png]]

오늘날의 인공지능은 더 이상 단일 모델의 성능만으로 평가되지 않는다. 외부에 위치한 시스템과 데이터를 얼마나 잘 통합하고, 다양한 도구와 유기적으로 작동할 수 있는지가 AI의 실질적 역량을 좌우한다. 이러한 맥락에서 등장한 것이 바로 Model Context Protocol(이하 MCP)이다. AI의 외부 세계와 연결하는 새로운 표준인 MCP의 개념과 구조와 통신 방식 등을 살펴보자.

## 1. MCP 등장배경

LLM의 갖고 있는 여러 가지 한계를 보완하기 위해 다양한 기술들이 등장했다. 파인튜닝(Fine-Tuning), 프롬프팅(Prompting), RAG(Retrieval-Argumented Generation, 검색-증강 생성) 등의 기술로 몇 가지 한계를 보완하였지만, 실제 무언가를 행동하거나 수행할 수 있는 능력은 없었다. 그런 이유로 2023년 중반부터 OpenAi의 Function Calling, Anthropic의 Tool Use, Langchain의 Tool Calling이라는 기능을 도입하여 LLM이 외부 세계와 연동할 수 있는 방안을 마련했다.

참고로 OpenAI의 Function Calling은 GPT 모델이 사전에 정의된 함수의 인자를 예측하고 반환하는 방식으로 외부 기능을 사용할 수 있도록 하는 메커니즘이다. Anthropic의 Claude 모델이 사용하는 Tool Use는 LLM이 상호작용 가능한 외부 도구의 사용을 스스로 결정하고 요청하는 기능이다. LangChain은 다양한 LLM(OpenAI, Anthropic 등)에 도구 호출 기능을 통합적으로 연결·제어할 수 있도록 설계된 오픈소스 프레임워크이다.

LLM을 핵심으로 하여 사용자의 요청을 이해하고, 그 요청에 해당하는 기능을 수행하기 위해 별도로 AI Agent를 구현하였다. AI Agent를 활용하면 사용자의 한 번의 요청으로 여러 단계의 작업도 유기적으로 수행할 수 있다. 그러나 표준화가 이루어지지 않아 개발자들에게 상당한 부담을 주고 있었다.

## 2. MCP란 무엇인가?

2024년 11월, Anthropic은 MCP라는 표준화된 프로토콜을 발표했다. Anthropic은 MCP를 오픈소스로 공개하며 이를 “AI 어시스턴트를 데이터가 존재하는 외부 세계에 연결하는 새로운 표준”이라고 소개하였다. 드디어 표준화된 방식으로 AI와 외부 세계 간의 상호 작용하기 위한 방법이 마련되어 AI Agent 개발자는 구현하는 기능에만 집중할 수 있게 되었다.

MCP는 대형 언어 모델(LLM) 기반의 AI 시스템이 외부 데이터 소스와 도구에 일관된 방식으로 연결될 수 있도록 설계된 개방형 표준 프로토콜이다. 쉽게 말해, USB-C처럼 어떤 모델이든 다양한 시스템과 통신할 수 있도록 만들어주는 인터페이스 역할을 수행한다. MCP라는 개방형 표준으로 AI 생태계의 상호운용성을 높이고, AI가 외부 지식과 도구를 안전하게 활용할 수 있는 길을 열었다. MCP를 통해 AI 모델은 실시간 뉴스 API, 사내 문서 저장소, 내부 데이터베이스 등 다양한 실시간 소스에 직접 연결할 수 있다.

MCP는 AI가 최신 정보에 접근하고 외부 도구를 안전하게 활용함으로써 환각(hallucination) 문제를 완화하고 응답 품질을 향상시키는 역할을 수행한다. 이를 통해 AI 모델이 서로 다른 데이터베이스, 파일 시스템, 업무 도구 등에 일관된 방법으로 접속할 수 있게 해준다. 이를 통해 향상된 성능의 AI 에이전트, 더 풍부한 맥락을 가진 응답, 그리고 다양한 응용 분야에서 확장성 있는 활용이 가능해졌다.

> MCP는 AI 애플리케이션을 위한 USB-C 포트와 같다.

## 3. MCP 구성요소

MCP은 대형 언어 모델(LLM)과 외부 세계를 안정적이고 유연하게 연결할 수 있도록 정교하게 설계된 클라이언트-서버 아키텍처 기반 시스템이다. 여기에 ‘호스트(Host)’라는 중심 개념이 추가되면서, MCP는 뛰어난 확장성과 높은 보안성을 동시에 확보할 수 있게 되었다.

MCP의 전체 구조는 MCP 호스트(Host), MCP 클라이언트(Client), MCP 서버(Server)라는 세 가지 핵심 요소로 구성되며, 이들 간의 분명한 역할 분담과 격리 구조는 복잡한 통합 환경에서도 신뢰성 있는 운영을 가능하게 한다.

### 1) MCP Host: AI의 중심 제어 허브

MCP 호스트(Host)는 MCP 아키텍처에서 사용자와 직접 상호작용하는 주 애플리케이션으로, 전체 MCP 통신의 중심이 되는 역할을 수행한다. Claude Desktop이나 AI 기반 도구 애플리케이션, IDE의 AI 플러그인과 같은 인터페이스가 대표적인 호스트에 해당한다.

호스트는 단순한 UI 이상의 기능을 수행한다. 내부적으로 다수의 MCP 클라이언트를 생성하고 이를 관리하며, 각 클라이언트가 어떤 MCP 서버에 연결할 것인지, 어떤 작업에 대해 어떤 권한을 부여할 것인지를 조율하는 제어 역할을 한다. 호스트가 동시에 여러 MCP 서버와 연결될 수 있으며, 각 연결에 대해 사용자의 명시적 승인, 보안 정책 적용, AI 모델 통합 설정 등을 독립적으로 관리함으로써 전체 시스템의 신뢰성과 통제력을 확보한다.

### 2) MCP Client: 연결과 세션의 관리자

MCP 클라이언트(Client)는 호스트 내부에 존재하며, 각각 하나의 MCP 서버와 1:1로 연결되는 역할을 수행하는 구성 요소이다. 호스트는 필요에 따라 특정 서버용 클라이언트를 생성하고, 해당 클라이언트는 서버와의 상태 유지(stateful) 세션을 관리하며, 프로토콜 초기 협상, 메시지 라우팅 등 MCP 통신의 핵심을 담당한다.

MCP 클라이언트의 가장 중요한 기능 중 하나는 서버 간 격리(isolation)를 보장하는 것이다. 예를 들어, 사용자가 파일 시스템 MCP 서버와 데이터베이스 MCP 서버를 동시에 사용할 경우, 각 서버가 다른 서버의 세션이나 사용자의 대화 내용을 참조하지 못하도록 클라이언트 수준에서 완벽히 분리된다. 이는 보안성과 개인정보 보호 측면에서 매우 중요한 설계 요소이다.

### 3) MCP Server: 외부 기능과 데이터에 대한 인터페이스

MCP 서버(Server)는 외부 또는 로컬에 위치하는 독립 실행 프로세스로, 특정 기능이나 데이터 접근을 담당한다. 각 서버는 하나의 책임 있는 도메인에 집중하여 설계된다.

서버는 MCP 표준에 따라 자신이 제공하는 기능을 명시적으로 선언하며, 주로 다음 세 가지 기능을 중심으로 구성된다.

- Tools (도구 호출): 검색 실행, 데이터 처리, API 호출 등의 외부 행동을 모델이 수행할 수 있도록 지원

- Resources (리소스/데이터): 문서, 파일, DB 레코드 등 AI가 참조할 수 있는 외부 콘텐츠를 제공

- Prompts (프롬프트 템플릿): 사전에 정의된 텍스트 템플릿을 제공하여 워크플로우 자동화를 돕는 기능

![[03 Attachments/티스토리 Vento AI Lab/826/826-003-4d25a162-5cc0-42cb-a7d9-a63a3210279a_1086x1280.gif]]

MCP 서버는 이처럼 독립적인 마이크로서비스 형태로 동작하며, 복잡한 로직 처리나 AI 제어는 모두 호스트 측에서 이루어진다. 즉, 서버는 단일 기능을 책임지고, 그 외의 복잡성은 시스템 중심인 호스트가 담당함으로써 전체 아키텍처의 유지보수성과 확장성을 높이는 구조를 갖는다.

## 4. JSON-RPC 통신

MCP는 통신 프로토콜로 JSON-RPC 2.0 표준을 채택하고 있다. JSON-RPC는 요청(Request)과 응답(Response), 오류(Error), 알림(Notification)을 JSON 형식으로 주고받는 경량 통신 규약이다. 가볍고(stateless) 단순한 구조를 갖춘 원격 프로시저 호출(Remote Procedure Call, RPC) 방식으로 별도의 설정 없이도 구조화된 메시지 교환이 가능합니다. 이러한 방식으로 인해 MCP 클라이언트와 MCP 서버는 동일한 메시지 형식으로 상호 간의 명확한 소통이 가능하며, 다양한 언어와 플랫폼 간의 호환성도 뛰어나다.

### 1) 전송 계층

MCP 메시지는 다양한 전송 방식으로 주고받을 수 있다. 로컬 MCP 서버의 경우 표준 입출력(STDIO) 파이프를 통해 JSON-RPC 메시지를 교환하고, 원격 MCP 서버의 경우 HTTP(S) 연결이나 Server-Sent Events (SSE) 스트림을 통해 통신한다. 즉, 동일한 JSON-RPC 내용을 TCP/IP 상의 HTTP로 주고받을 수도 있고, 로컬 프로세스 간에는 파이프로 통신할 수도 있게 유연하게 설계되어 있다.

### 2) 메시지 유형

MCP에서 주고받는 JSON 메시지에는 요청, 응답, 알림 세 가지 타입이 있다. 각 메시지 타입은 다음과 같은 JSON 구조를 가진다.

a) 요청(Request)

어떤 동작을 개시할 때 사용된다. method 필드에 수행할 작업 이름을, params 필드에 해당 작업에 필요한 인자들을 담는다. 모든 요청에는 고유한 id가 부여되어 응답과 매칭된다.

b) 응답(Response)

요청에 대한 결과를 전달한다. id 필드로 어떤 요청에 대한 응답인지 표시하며, 성공 시 result 객체에 결과 데이터를, 실패 시 error 객체에 오류 코드를 포함한 메시지를 넣는다. 응답에는 result 또는 error 둘 중 하나만 있어야 하며, id는 요청의 것과 동일하게 맞춰야 한다.

c) 알림(Notification)

단방향 통지에 사용된다. 예컨대 상대에게 알려줄 이벤트가 있을 때 보내며, id가 없고 method와 params만 포함한다. 알림에는 대응하는 응답이 오지 않으며, 가령 서버에서 “새 데이터가 업데이트되었다”는 통지를 보내는 용도로 사용한다.

## 5. MCP 통신방식

MCP는 LLM과 외부 도구를 연결하는 구조화된 인터페이스를 제공하기 위해 고안된 통신 프로토콜이다. 이 프로토콜은 JSON-RPC 메시지를 기반으로 동작하는데, 클라이언트와 서버 간 메시지를 주고받는 형식만을 표준화하고 있을 뿐, 그 실제 통신 자체는 여러 가지 방식을 허용하는 유연한 구조를 갖고 있다.

MCP는 로컬 통신과 원격 통신이라는 두 가지 주요 시나리오를 모두 포괄할 수 있도록, 다음과 같은 두 가지 통신 방식을 정의하고 있다.

### 1) STDIO 방식: 로컬 환경에 적합한 간단한 구현

STDIO(Standard Input/Output) 방식은 MCP 클라이언트가 MCP 서버(또는 툴)를 동일한 시스템 내에서 자식 프로세스로 실행할 때 사용된다. 이 경우 클라이언트는 MCP 요청을 해당 프로세스의 표준 입력(stdin)으로 전달하고, 서버는 응답을 표준 출력(stdout) 을 통해 반환한다.

네트워크 설정 없이도 쉽게 구현할 수 있어 개발 초기나 테스트 환경에서 유용하고 동일 머신에서 동작하기 때문에 네트워크 지연이 없으며, 빠른 요청-응답이 가능하다. 하지만 단방향 스트리밍이나 네트워크 기반 원격 연동에는 적합하지 않아, 고도화된 시나리오에는 한계가 있다. STDIO는 개발 중인 로컬 툴을 MCP와 연동하거나, LLM 기반 애플리케이션을 로컬에서 시범적으로 테스트할 때 유용하게 활용된다.

### 2) SSE 방식: 실시간 스트리밍에 최적화된 원격 통신

SSE(Server-Sent Events)는 HTTP 기반의 단방향 스트리밍 프로토콜로, 서버가 클라이언트에게 지속적으로 데이터를 푸시 할 수 있도록 한다. 클라이언트는 서버에 한 번 연결한 후, 별도의 요청 없이도 서버로부터 실시간 데이터를 받아볼 수 있다.

LLM이 툴의 실행 상황을 실시간으로 모니터링하거나, 중간 결과를 순차적으로 받아 분석할 수 있다. 클라우드 기반 데이터 분석 도구나 백엔드 서버와 연결할 때 유용하다. WebSocket과 유사한 기능을 제공하지만, HTTP 표준을 기반으로 하여 브라우저 호환성과 구현의 간단함에서 이점을 가진다.

## 6. 단계별 프로세스

MCP는 아래와 같은 단계별 프로세스로 인해 확장성, 보안성, 모듈성을 갖춘 컨텍스트 통합 프레임워크로 기능할 수 있다. 필요에 따라 새로운 서버를 유연하게 추가하거나 제거할 수 있으며, 데이터 접근도 개별적으로 통제할 수 있다.

### 1) 사용자 쿼리 입력

사용자는 Claude Desktop과 같은 MCP 호스트 애플리케이션을 통해 AI Agent에게 질문이나 요청을 제기한다.

"오늘 일정을 알려주고 어제 수신한 메일 내용을 정리해줘"

### 2) AI의 컨텍스트 판단

AI 모델은 현재 요청에 대해 스스로 답변할 수 있는지, 아니면 외부 도구가 필요한지를 판단한다. 더 많은 정보가 필요해서 외부 도구가 필요하다고 판단하면, MCP 서버에 사용가능한 함수 목록과 관련 데이터를 보유하고 있는지를 식별한다.

### 3) 호스트의 MCP 서버 쿼리

호스트 애플리케이션은 MCP 클라이언트를 통해 함수 목록을 분석하여 적절한 함수를 식별하고 해당 요청을 관련된 MCP 서버로 전달한다.

### 4) MCP 서버의 요청 처리

각 MCP 서버는 자신이 연결된 데이터 소스에 접근하여 요청을 처리한 후, 관련된 정보를 응답으로 생성한다.

### 5) 응답 집계 및 전달

MCP 클라이언트는 여러 서버로부터 받은 응답을 수집하고, 이를 정리하여 AI 모델에게 전달한다.

### 6) 최종 AI 응답 생성

AI는 MCP 서버들로부터 얻은 맥락 정보를 바탕으로, 사용자에게 더욱 정확하고 풍부한 응답을 생성하여 제공한다.
