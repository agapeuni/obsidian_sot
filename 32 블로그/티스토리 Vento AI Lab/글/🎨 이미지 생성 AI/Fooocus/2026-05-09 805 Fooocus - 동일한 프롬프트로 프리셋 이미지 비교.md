## 1. Fooocus 등장 배경

AI 이미지 생성 도구가 대중화되면서 많은 사용자가 공통적으로 느낀 불편이 있다. 설정이 너무 많다는 점이다. Stable Diffusion은 강력하지만, 수많은 슬라이더와 옵션을 이해하고 조정해야 원하는 결과에 도달할 수 있었다. 초보자에게는 진입 장벽이 꽤 높았다.

이 지점에서 등장한 것이 "**Fooocus**"다. Fooocus는 Stable Diffusion, 특히 Stable Diffusion XL을 기반으로 하면서도, 사용자가 복잡한 세부 설정을 일일이 조정하지 않아도 되도록 설계된 로컬 오픈소스 UI다. 목표는 명확하다. 미드저니처럼 “프롬프트만 입력하면” 고품질 이미지를 안정적으로 생성하는 환경을 제공하는 것이다.

내부 구조는 비교적 단순하다. 웹 인터페이스 프레임워크인 Gradio 위에 구현되어 있어 브라우저에서 바로 사용할 수 있다. 복잡한 백엔드 설정 없이도 실행 가능하도록 구성되어 있으며, 설치와 실행 과정 역시 최대한 단순화되어 있다. 공식적으로는 ‘3클릭 이하’를 지향할 정도로 사용자 경험을 간결하게 다듬었다.

하드웨어 요구 사항도 비교적 현실적이다. 최소 사양은 NVIDIA 그래픽카드 4GB VRAM부터 시작하며, 6GB 이상을 권장한다. 고사양 GPU가 아니더라도 충분히 테스트와 실험이 가능하도록 설계되었다는 점이 특징이다.

정리하면, Fooocus는 “설정의 자유도”보다 “결과의 일관성과 접근성”에 무게를 둔 도구다. Stable Diffusion의 강력함을 유지하면서도, 사용자는 복잡한 기술적 조정 대신 창의적인 프롬프트 작성에 집중하도록 방향을 전환했다는 점이 이 도구의 등장 배경이라 할 수 있다.

기술은 점점 더 강력해지고 있지만, 결국 사용성을 어떻게 설계하느냐에 따라 대중화의 속도가 달라진다. Fooocus는 그 지점을 겨냥한 실험이자, “복잡함을 감추는 디자인”이 얼마나 중요한지 보여주는 사례다.

## 2. Fooocus 설치

Ubuntu 24.04 (Python 3.10 전제)

**1) 소스 받기**

git clone [https://github.com/lllyasviel/Fooocus.git](https://github.com/lllyasviel/Fooocus.git)

cd Fooocus

**2) 요구 라이브러리 설치**

pip install -r requirements_versions.txt

**3) 실행**

python entry_with_update.py

초기 실행 시 SDXL 계열 모델이 자동 다운로드

**4) 프리셋 실행**

Anime 프리셋: --preset anime

Realistic 프리셋: --preset realistic

**5) 원격 접속이 필요시**

python entry_with_update.py --listen --port 17860

## 3. Fooocus 아키텍처

Stable Diffusion을 조금이라도 써본 사람이라면 안다. "이미지 한 장" 뒤에는 생각보다 많은 작업과 계층이 숨어 있다는 사실을. Fooocus는 이 복잡한 구조를 최대한 감추면서도, 내부적으로는 꽤 정교한 아키텍처를 갖추고 있다. 겉은 단순하지만 속은 공학적이다.

UI → 프롬프트 확장 → SDXL 생성 파이프라인 → 이미지 조작 모듈

이 구조 덕분에 사용자는 복잡성을 체감하지 않으면서도, 내부적으로는 꽤 정교한 AI 시스템을 활용하게 된다.

기술적으로 보면 일종의 철학이다.

“**복잡한 것을 제거하는 것이 아니라, 복잡함을 보이지 않게 감추는 것.**”

### 1) UI 계층 – 사용자는 단순하게, 내부는 구조적으로

가장 바깥에는 웹 인터페이스가 있다. Fooocus는 Gradio 기반 WebUI로 구성되어 있다. 사용자는 여기에서 프롬프트를 입력하고, 몇 가지 옵션을 선택하고, 결과를 미리보기 하면 된다. 복잡한 샘플러 설정이나 세부 파라미터를 전면에 드러내지 않는다.

“사용자는 창작에 집중하고, 세부 튜닝은 내부에서 처리한다.”

### 2) 프롬프트 엔진 – 짧은 문장을 그럴듯하게

Fooocus에는 오프라인 GPT-2 기반의 “프롬프트 확장” 엔진이 내장되어 있다. 여기서 사용하는 모델은 GPT-2다. 사용자가 짧게 “1girl, office look” 정도만 입력해도, 내부적으로 문장을 보정하고 확장해 보다 풍부한 설명으로 바꾼다.

이 확장 시스템은 스타일 프리셋과 결합된다. 세 요소가 결합되어 최종 프롬프트가 구성된다.

- 사용자의 의도

- 선택한 스타일

- 내부 확장 알고리즘

짧은 입력이 자연스럽게 “미드저니스러운 완성도”로 변환되는 이유가 여기에 있다.

### 3) 생성 파이프라인 – SDXL 중심 구조

이미지 생성의 핵심은 Stable Diffusion XL 기반 파이프라인이다.

기본 흐름은 다음과 같다.

샘플러 단계에서 노이즈를 점진적으로 정제 →

잠재 공간(latent space)에서 이미지를 형성 →

VAE(Variational AutoEncoder) 디코딩으로 실제 이미지로 변환

흥미로운 점은 기본 프리셋에서 Refiner 모델을 사용하지 않는 구성이 기본값이라는 것이다. Refiner를 추가하면 품질은 조금 더 올라가지만, VRAM 사용량과 처리 시간이 증가한다. Fooocus는 기본적으로 “가성비 좋은 품질”을 택한다.

### 4) 이미지 조작 계층 – 단순 생성 그 이상

Fooocus는 단순 텍스트→이미지 생성에 머무르지 않는다.

- 전용 인페인트/아웃페인트 알고리즘과 모델을 사용한다.

- 표준 SDXL 인페인트보다 사용자 만족도를 높이는 방향으로 설계되어 있다.

- Image Prompt 기능에서는 일반적으로 쓰이는 IP-Adapter 대신 자체 알고리즘을 적용한다.

- ControlNet 지원

- InsightFace 기반 FaceSwap

- 이미지→텍스트 변환(Describe 기능)

즉, 구조적으로 보면 Fooocus는 “라이트한 UI를 가진 풀스택 이미지 생성 환경”에 가깝다.

## 4. Fooocus 기능

Fooocus는 단순한 UI 도구가 아니다. 모든 기능이 하나의 흐름으로 연결된다.

스타일 안정화 → 스마트 프롬프트 확장 → 디테일 보정 → CFG 안정화 → 고급 제어 기능 → 원격 공유

복잡한 옵션을 드러내기보다, 필요한 순간에만 보여준다. 기술은 깊지만 경험은 가볍다. 좋은 설계는 기능을 많이 넣는 것이 아니라, 사용자의 사고 에너지를 아껴주는 것이다. Fooocus는 그 방향으로 설계된 도구다.

### 1) Style Freeset – 스타일을 섞어도 무너지지 않도록

Fooocus의 Style Freeset은 여러 스타일을 동시에 조합해도 품질 저하가 크게 발생하지 않도록 설계되어 있다. 일반적으로 스타일을 많이 얹으면 구조가 흐트러지거나 색감이 과포화되는 문제가 생긴다. Fooocus는 내부 가중치 조정과 프롬프트 확장을 통해 이런 충돌을 완화한다. 결과적으로 사용자는 “실험”에 더 자유로워진다. 스타일을 겹친다고 해서 결과가 쉽게 붕괴하지 않는다.

****

### 2) Fooocus V2 – 스마트 프롬프트 확장

Fooocus V2에서는 GPT-2 기반의 가변 스타일 키워드 확장이 동작한다. 짧은 프롬프트라도 내부적으로 보강하여 더 풍부한 설명으로 확장한다. 이 과정은 단순한 키워드 추가가 아니라, 스타일 맥락을 고려한 보정에 가깝다. 프롬프트를 잘 쓰지 못해도 결과가 평균 이상으로 유지되는 이유가 여기에 있다.

****

### 3) Sampling Sharpness – 선명도만 올리고 구조는 유지

Sampling Sharpness는 디테일 선명도만 높이고 구조 왜곡은 최소화하는 옵션이다. 많은 샘플러에서 디테일을 과하게 올리면 얼굴이 비정상적으로 변형되거나 “플라스틱 피부”처럼 보이는 현상이 나타난다. 이 옵션은 그 문제를 줄이는 데 특화되어 있다. 결과는 더 또렷하지만 과도하게 매끈하지 않은 이미지다.

****

### 4) Guidance(CFG) 개선 – Adaptive TSNR Rescaling

Guidance, 즉 CFG(Classifier-Free Guidance)는 프롬프트를 얼마나 강하게 따를지 결정하는 값이다. 높은 CFG에서는 이미지가 “타는 현상”(과포화, 경계 깨짐)이 생기기 쉽다. Fooocus는 Adaptive TSNR Rescaling을 적용해 이런 왜곡을 완화한다. 쉽게 말해, 프롬프트를 강하게 적용하면서도 노이즈 대비 신호 균형을 자동 조정하는 방식이다.

****

### 5) Inpaint / Outpaint – 영역 수정과 캔버스 확장

특정 영역만 수정하거나(인페인트), 캔버스를 확장하는(아웃페인트) 기능을 기본 지원한다. 첫 사용 시 전용 인페인트 모델이 자동 다운로드된다. 사용자는 별도 설정 없이 바로 활용 가능하다.

****

### 6) Image Prompt / ControlNet / FaceSwap

Advanced 탭에서는 고급 기능을 통합 사용할 수 있다.

- 참고 이미지 기반 생성(Image Prompt)

- ControlNet으로 구도·포즈 제어

- InsightFace 기반 FaceSwap

텍스트 중심 생성에서 한 단계 더 나아간 제어 환경이다.

****

### 7) 멀티 프롬프트·가중치·임베딩·와일드카드

줄바꿈을 이용한 멀티 프롬프트 입력이 가능하다. 형태 가중치 조정, embedding 적용, 와일드카드 기능도 지원한다. 이 부분은 Stable Diffusion 숙련자에게 특히 유용하다. 단순 UI 뒤에 “고급 사용자용 도구”가 숨겨져 있는 셈이다.

****

### 8) 프리셋 전환 및 원격 공개

2.3.0 이후 버전에서는 브라우저에서 프리셋 전환이 가능하다. 필요 시 모델이 자동 다운로드된다.

로컬 실험 환경에서 팀 공유 환경까지 확장할 수 있다. 원격 접속도 지원한다.

- --listen : 외부 접속 허용(포트 지정 가능)

- --share : gradio.live 엔드포인트 공개

- 기본 인증은 루트 폴더의 auth.json 파일로 설정

##  5. Fooocus 장점

Fooocus의 장점은 단순히 “잘 나온다”가 아니다.

시작은 쉽고, 데이터는 안전하며, 사양 부담은 낮고, 기본 품질은 안정적이며, 워크플로는 한 화면에 통합된다.

복잡한 기술을 드러내 자랑하기보다, 사용자의 인지 에너지를 아껴주는 방향.

도구가 창작자의 집중력을 방해하지 않도록 설계하는 것.

그 점에서 Fooocus는 단순한 UI가 아니라, “사용자를 배려한 구조 설계”에 가깝다.

좋은 도구는 기능을 많이 가진 것이 아니라, 계속 쓰게 만드는 것이다.

### 1) 진입장벽이 낮다 – 옵션보다 프롬프트에 집중

많은 Stable Diffusion UI는 처음 실행하는 순간부터 설정 창이 쏟아진다. 샘플러, 스텝, CFG, 해상도, 시드 값…. 초보자는 어디부터 건드려야 할지 모른다.

Fooocus는 방향이 다르다.

“옵션보다 프롬프트.”

사용자는 문장에 집중한다. 내부 튜닝은 기본값으로 안정화되어 있다. 감성은 미드저니처럼 간결하지만, 실제 실행은 로컬 오픈소스 기반이다. 자유도와 간결함을 동시에 잡은 구조다.

### 2) 로컬·오프라인 환경

Fooocus는 로컬에서도 실행된다. 데이터가 외부 서버로 전송되지 않는다. 기업 프로젝트, 상업 이미지, 개인 사진 등 민감한 데이터 작업에 유리하다. 또한 모델 교체, LoRA 적용, 스타일 확장 등 커스터마이즈 자유도가 높다. 로컬 환경은 번거롭지만 주도권이 사용자에게 있다. 클라우드 기반 서비스는 편하지만 통제권은 제한적이다.

### 3) 저사양에서도 시작 가능

최소 NVIDIA 4GB VRAM 환경에서도 동작한다. 물론 VRAM이 높을수록 속도와 품질은 올라간다. 8GB 이상이면 훨씬 안정적이다. 그러나 “최소한 시작은 가능하다”는 점이 중요하다. AI 실험은 고사양 장비가 있어야만 가능한 영역이 아니다. 입문 허들이 낮다는 것은 생태계 확장과 직결된다.

### 4) 기본 탑재된 품질 보정 장치

Fooocus는 품질을 자동으로 보정하는 장치를 기본 제공한다.

사용자가 일일이 튜닝하지 않아도 평균 이상의 결과를 유지한다.

- GPT-2 기반 프롬프트 확장

- Sampling Sharpness로 디테일 선명도 강화

- Adaptive TSNR Rescaling으로 높은 CFG에서도 왜곡 완화

핵심은 “품질은 올리고, 파라미터 피로는 줄인다.”

****

### 5) 실전 워크플로 통합

실무에서는 텍스트 생성만 하지 않는다.

- ControlNet으로 구도 제어

- InsightFace 기반 FaceSwap

- Describe 기능으로 이미지→텍스트 변환

- Image Prompt로 참고 이미지 반영

## 7. Fooocus 폴더 구조

```
Fooocus
├── models               # 모델 관련 폴더 (주요 저장소)
│   ├── checkpoints      # SD 모델 체크포인트(.safetensors, .ckpt)
│   ├── clip             # CLIP / 텍스트 인코더
│   ├── clip_vision      # CLIP 비전 모델 (태그 분류기 등)
│   ├── configs          # 모델 설정 파일(.yaml)
│   ├── controlnet       # ControlNet 모델
│   ├── embeddings       # 텍스트 임베딩 (예: TI)
│   ├── loras            # LoRA 모델
│   ├── upscale_models   # 업스케일러 모델 (4x-UltraSharp 등)
│   ├── vae              # VAE 모델
│   └── ...              # 기타 (hypernetworks, onnx 등)
├── outputs              # 생성된 이미지 저장 폴더
├── presets              # Fooocus 프리셋 파일
├── entry_with_update.py # Fooocus 실행 파일
├── fooocus_version.py   # 버전 정보
├── launch.py            # 실행 스크립트
├── requirements.txt     # 의존성 패키지 목록
└── webui.py             # Gradio 기반 실행 파일
```

- 기본 모델은 자동으로 Fooocus/models/checkpoints 등에 내려받는다.

- 인페인트 첫 사용 시 models/inpaint/inpaint_v26.fooocus.patch(~1.28GB)가 추가된다.
