# 2023-06-13 223127692347 SW 테스트 - SW 품질을 높이는 단계, 실전 전략

![](https://postfiles.pstatic.net/MjAyNTA0MTNfMjQ3/MDAxNzQ0NDc4NDc4NDc1.VyMWVtTGcShrqQ1YKv5CBcfDFyRM4EkasSTaQhQ3cS8g.WzOPFmLScT1pkyrOoDkSouPUrvSgF2hi-AgJNf1CM94g.PNG/%EC%86%8C%ED%94%84%ED%8A%B8%EC%9B%A8%EC%96%B4_%EA%B3%B5%ED%95%99-001_\(10\).png?type=w80_blur)

​

소프트웨어 테스트란 프로그램에 있는 오류를 찾기 위해 프로그램을 실행하여 실행 결과와 예상 결과를 비교하고 검토하는 과정이다. 응용 프로그램 또는 시스템의 동작과 성능, 안정성이 요구 수준을 만족하는지 확인하는 과정이며, 시스템의 결함을 발견하기 위한 방법이다.

일반적으로 테스트는 개발된 SW에 포함된 결함을 찾아내고 이를 수정하거나 제거하여 SW의 품질을 개선하려는 목적으로 수행된다. SW 테스트는 SW에 존재하는 결함을 찾아내는 것을 주목적으로 하며, 그 외에도 SW 테스트를 바라보는 SW 결함의 관점, 전체 시스템의 관점, SW 품질의 관점, 마케팅의 관점에 따라 각각의 필요성과 목적에 의해 테스트를 수행한다. 

![](https://postfiles.pstatic.net/MjAyMzA2MTNfMjAy/MDAxNjg2NjM1MTI5NjA2.u71teS-gw_9eE7zEhQPWnXupTg_2VD-fLev61XmESKog.4IHcATnEBThFB0S_1S9NjRMge-_uroT2_3Kqr4gnDmUg.JPEG.agapeuni/img.jpg?type=w80_blur)

​

소프트웨어 공학에서 테스트는 소프트웨어의 품질을 보장하기 위해 중요한 단계다. 테스트는 소프트웨어의 기능, 성능, 안정성 등을 평가하고 결함을 발견하고 수정하는 프로세스로 일반적으로 다음과 같은 단계로 이루어진다.

​

**1) 테스트 계획**

테스트 목표와 범위를 설정하고, 테스트 전략과 방식을 계획한다. 

이 단계에서는 테스트 리소스, 일정, 테스트 환경 등을 고려한다.

​

**2) 테스트 설계**

테스트 케이스를 설계한다. 

특정 입력에 대한 예상 결과를 정의하고, 테스트 데이터를 선택하고, 테스트 절차를 작성한다.

​

**3) 테스트 환경 구축**

테스트를 수행하기 위한 테스트 환경을 구축한다. 

이는 테스트를 수행하는 데 필요한 하드웨어, 소프트웨어, 네트워크 등을 포함한다.

​

**4) 단위 테스트**

소프트웨어의 가장 작은 단위인 모듈이나 함수를 개별적으로 테스트한다. 

이를 통해 개별 모듈이 정확하게 동작하는지 확인한다.

​

**5) 통합 테스트**

개별 모듈이 통합되어 전체 시스템이 예상대로 작동하는지 테스트한다.

이 단계에서는 모듈 간의 인터페이스, 데이터 흐름 등을 확인한다.

​

**6) 시스템 테스트**

전체 시스템의 기능, 성능, 안정성 등을 평가한다.

이 단계에서는 사용자 시나리오를 기반으로 테스트를 수행하고, 예상되는 결과와 실제 결과를 비교한다.

​

**7) 인수 테스트**

최종 사용자가 소프트웨어를 테스트하고 승인하는 단계다. 

소프트웨어가 요구 사항을 충족시키는지 확인하고, 사용자의 요구 사항을 충족시키는지 검증한다.

​

**8) 회귀 테스트**

소프트웨어에 변경 사항이 발생한 경우, 해당 변경이 다른 부분에 영향을 주지 않았는지 확인하기 위해 이전에 통과한 테스트를 다시 실행한다.

​

테스트는 소프트웨어 개발 프로세스의 일부로 반복적으로 수행되며, 테스트 결과에 따라 소프트웨어의 품질을 향상시키는 작업이 이루어진다. 효과적인 테스트는 소프트웨어의 신뢰성과 안정성을 향상시키고, 결함을 최소화하는 데 도움이 된다.

​

ISO/IEC 29119 Software Testing Standard는 SW 테스트 국제 표준으로서 SW 테스트 체계를 수립하고 테스트와 품질에 대한 인식을 개선함으로써 높은 품질 수준을 확보할 수 있도록 하기 위해 개발 중인 표준이다.
