소프트웨어는 단순히 기능을 구현한 결과물이라기보다는 살아있는 유기체와 같아 지속적으로 관리를 해주어야 한다. 시간이 흐르면서 작성한 코드는 계속 변경을 하여 한참의 시간이 지나고 나면 처음과 많이 달라지는 경우도 있다. 그리고 소프트웨어를 만들기 위해 자신이 직접 코딩을 하지만 때로는 다른 사람이 작성한 코드를 분석하는 경우가 생각보다 많다. 

​

최근에 진행하고 있는 프로젝트는 Anaconda 오픈소스를 기반으로 기능을 커스터마이징하는 일이라 이미 작성되어 있는 코드를 분석하고 이해하고 적용해야 한다. 지난주에는 Conda Constructor를 분석하였고 이번 주는 Anaconda Navigator를 분석하고 있다. 

​

※ anaconda_navigator 폴더의 구성

· api - 아나콘다 API를 감싸고 있는 넌 블로킹 스레드 워커.

· app - 메인 응용 프로그램 진입점.

· config - 구성 설정을 담당하는 모듈.

· external - 파이썬을 사용한 범용 분석.

· static - 글꼴, 이미지, 스타일, 사용자 정의 콘텐츠가 포함.

· utils - Anaconda Navigator 패키지에 대한 여러 유틸리티가 포함.

· widgets - 위젯

· widgets/dialogs - 대화 상자 정의 및 스타일링에 사용되는 사용자 지정 위젯.

· widgets/lists - 리스트.

· widgets/manager - 패키지 관리자 위젯.

· widgets/tabs - 탭.
