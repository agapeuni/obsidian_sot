**내담씨앤씨 인터뷰 후 시작된 또 다른 여정**

판교에 위치한 "내담씨앤씨"에서 인터뷰를 본 후, 다시 화성 DSR에서 프로젝트를 진행하게 되었다. 이번 프로젝트는 바로 전에 진행했던 프로젝트와 같은 건물에서 진행되었으며, 업무 공간도 한 층 위인 21층에 자리를 잡게 되었다.​

​

프로젝트 시작과 동시에 다른 모듈에서 인력 변경이 발생하면서, 계획과 다르게 난도가 높은 모듈을 담당하게 되었다. 예정에 없던 어려운 작업을 맡게 되어 부담이 컸지만, 새로운 도전을 통해 성장할 기회라고 생각하며 프로젝트를 진행하였다. 이전 프로젝트에서의 경험을 바탕으로, 보다 체계적으로 문제를 해결하며 작업을 진행하는 과정에서 또 한 번 실력을 쌓을 수 있는 시간이 되었다.

**기술보다 도메인 지식이 중요했던 프로젝트**

이번 프로젝트는 Spring 기반의 Java 환경에서 개발이 이루어져, 서버 측 기술 자체에는 큰 어려움이 없었다. 다만, 프로젝트 특성상 업무에 사용되는 용어 대부분이 영문 약어로 구성되어 있었기 때문에, 초기에는 각 용어의 의미를 정확히 이해하고 업무에 적응하는 데 일정한 시간이 필요하였다.

​

기술적인 문제를 해결하는 것보다는, 프로젝트의 도메인 지식을 빠르게 습득하는 것이 더욱 중요한 과제였다. 새로운 업무 용어들을 익히고, 이를 실제 작업에 적용해 나가는 과정을 통해 점차 프로젝트에 적응해 갈 수 있었다.

**스케줄러 모듈 개발 - 7가지 옵션, 3개의 프로토타입**

이번에 구현해야 할 모듈은 경우의 수가 다양하고 계산식도 복잡해 보여 쉽지 않은 작업처럼 보였다. 몇 차례 업무 설명회를 통해 큰 개념은 이해했지만, 다양한 경우의 수에 대한 구체적인 로직은 막연하게 느껴졌다. 다행히도 SDS 담당자가 로컬 환경에서 개념 알고리즘을 적용하여 일부 기능을 구현해 놓은 코드가 있어, 이를 참고하면서 개발을 진행할 수 있었다.

​

이번 프로젝트에서는 스케줄러 엔진에 적용해야 할 7개의 옵션이 존재했으며, 3~4개의 프로토타입 소스 코드를 전달받았다. 출퇴근 시간에 객체지향적인 형태로 모델링을 머릿속으로 구상한 뒤, 구현하려는 객체와 모델을 정의하고 새로운 구조로 개발을 시작하였다. 웹과 배치 모듈에서 사용할 기능이지만, 먼저 로컬 실행 모듈 형태로 개발하여 빠르게 테스트하고 반복 가능하도록 구성하였다. 또한, 입력과 출력을 쉽게 비교하고 분석할 수 있도록 구조화된 텍스트 형식을 활용하여 데이터 검증을 간편하게 처리할 수 있도록 했다.

​

​

**불가능해 보였던 7개의 옵션, 작은 단위로 나누어 단계별 완성**

각 단계별 코드마다 로그를 남겨, 복잡한 로직을 쉽게 추적하고 디버깅할 수 있도록 구성하였다. 이를 통해 트레이스가 어렵지 않도록 설계하여, 엔진에 필요한 옵션 기능을 수평적으로 하나씩 구현할 수 있었다.

​

처음 전체 구조를 설명 들었을 때는 매우 막연하고 난해한 작업처럼 보였지만, 적절한 단위로 나누어 개별적으로 접근하니 각각의 기능을 따로 생각하는 것은 어렵지 않았다. 이처럼 단계별로 하나씩 해결해 나가니, 처음에는 불가능해 보이기까지 했던 7개의 기능 옵션을 모두 성공적으로 구현할 수 있었다. 복잡한 시스템을 설계할 때, 전체를 한 번에 해결하려 하지 않고 적절한 단위로 나누어 하나씩 접근하는 것이 얼마나 중요한지 다시 한번 실감하는 프로젝트였다.
