# 2024-12-08 223686701908 UML - 유즈케이스 다이어그램(Use Case Diagram)

- 원문: https://blog.naver.com/PostView.naver?blogId=agapeuni&logNo=223686701908&categoryNo=1123
- 게시일: 2024. 12. 8. 23:30

## 본문

![](https://postfiles.pstatic.net/MjAyNDEyMDhfMTMx/MDAxNzMzNjYxOTcwOTg5.ZzQ6HW0quld4wPc_zgmPctuZuvqhBhus-jVnUTS4MCog.QBzIu_oxC0VmptOBA7q3ht8gJxNwLA0vFQT0uyJu1EMg.PNG/%EC%84%A4%EA%B3%84_%EB%AA%A8%EB%8D%B8%EB%A7%81-001_\(1\).png?type=w80_blur)

​

UML(Unified Modeling Language)은 시스템 요구사항을 효과적으로 모델링하고 소프트웨어 설계를 시각적으로 표현하기 위한 강력한 도구다. 시스템의 복잡한 관계와 구조를 명확히 나타낼 수 있어, 개발자와 이해관계자 간의 원활한 의사소통을 돕는다. UML 다이어그램은 시스템의 동작, 데이터 흐름, 그리고 요구사항을 직관적으로 보여주어 소프트웨어 개발 과정에서 필수적인 설계 언어로 자리 잡았다.

​

**1\. Actor**

![](https://postfiles.pstatic.net/MjAyNDEyMDhfMjQ5/MDAxNzMzNjYwNTQxNDI3.paLhdx2bODYppIEdq9fBmPxOb8UrXX69cJamg2un8zkg.Uy332WMWHQHLJaLQ_Nq9uGn2Yl_2ygXEuRcX7ZARtGIg.PNG/img1.daumcdn.png?type=w80_blur)

  * **정의** : 시스템과 상호작용하는 외부 요소(사람, 조직, 외부 시스템 등)를 의미한다.

  * **특징** : 행위자는 시스템 내부에 있지 않고, 시스템에 특정 요구사항을 전달하거나 시스템으로부터 특정 서비스를 제공받는다.

  * **예시** : 온라인 쇼핑 시스템에서의 고객, 관리자, 결제 시스템.

​

​

**2\. Use Case**

![](https://postfiles.pstatic.net/MjAyNDEyMDhfMjQx/MDAxNzMzNjYwNTY3MTEy.GnyhaEk5GbRNeizd5GLJAkDKirRc7OfB2QwzaFnos4gg.Y_0DMIp5nxdHGQkCVKx9Y-JDZ8_flHhQP-XjSAZpMSgg.PNG/img1.daumcdn.png?type=w80_blur)

  * **정의** : 시스템이 행위자와 상호작용하는 방식이나 시스템이 제공하는 기능을 특정한 시나리오 형태로 표현한 것이다.

  * **특징** : 유스 케이스는 사용자의 관점에서 시스템의 행동을 기술하며, 기능 요구사항을 나타낸다.

  * **예시** : "고객이 상품을 검색한다.", "고객이 상품을 결제한다."

**​**

**​**

**3\. Extend**

![](https://postfiles.pstatic.net/MjAyNDEyMDhfMTUy/MDAxNzMzNjYwNTgyNjcy.sdNWht5gE4slIoLou7u7xj_rZ-FmvM7rdu2TSIWiiS4g.qPjwKXWHincQt2DmvwyDWSGlUgsNMl_sXZvx4VDdZckg.PNG/img1.daumcdn.png?type=w80_blur)

  * **정의** : 기존의 유스 케이스에 특정 조건에서 추가적인 행동을 추가하기 위해 사용된다.

  * **특징** : 기본 유스 케이스는 독립적으로 존재할 수 있으며, 확장 관계는 선택적이다.

  * **예시** : "고객이 상품을 구매한다"는 기본 유스 케이스에 "할인 쿠폰 적용"이 확장 유스 케이스로 추가될 수 있다.

**​**

**​**

**4\. Include**

![](https://postfiles.pstatic.net/MjAyNDEyMDhfNzMg/MDAxNzMzNjYwNTkzNzQw.D0MzHiEX6FQ1ey587WMoCatSoR5a5IokFdXoOikeJh0g.I4OyBZp3F_5zI8Go_tyEC_yEtFkp2Szzq3U5BXzPGyUg.PNG/img1.daumcdn.png?type=w80_blur)

  * **정의** : 두 유스 케이스 간의 관계를 나타내며, 하나의 유스 케이스가 반드시 다른 유스 케이스의 행동을 포함해야 할 때 사용된다.

  * **특징** : 포함 관계는 공통된 행동을 재사용하기 위해 사용된다.

  * **예시** : "상품을 결제한다" 유스 케이스는 항상 "결제 정보 입력" 유스 케이스를 포함할 수 있다.

**​**

**​**

**5\. Generalization**

![](https://postfiles.pstatic.net/MjAyNDEyMDhfMjIw/MDAxNzMzNjYwNjEwODM5.l1f66oLi5SCVleVxcWoapeOvSC0hBVMZgm3RkFUrqjEg.Gl4h4lbMjkuE7EECRyrPhEYXk2swoKAgmUTnte4rI_wg.PNG/img1.daumcdn.png?type=w80_blur)

  * **정의** : 유스 케이스나 행위자 간의 관계를 나타내며, 공통된 특징이나 동작을 상위 개념으로 추상화하여 나타낸다.

  * **특징** : 부모-자식 관계로 설명되며, 자식은 부모의 특성을 상속한다.

  * **예시** : "관리자"와 "고객 서비스 담당자"는 "사용자"라는 상위 행위자로 일반화될 수 있다.
