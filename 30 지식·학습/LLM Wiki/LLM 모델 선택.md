# LLM 모델 선택

LLM 모델 선택은 공개 벤치마크 순위가 아니라 실제 업무 평가셋에서 품질·안전·비용·지연시간·데이터 경계를 비교하는 의사결정이다.

## 평가 순서

1. 사용자 과업과 실패 비용을 정의한다.
2. 필수 기능과 배포 제약으로 후보를 줄인다.
3. 동일 프롬프트·평가셋·판정 기준으로 후보를 비교한다.
4. 평균 품질뿐 아니라 치명 오류와 최악 지연시간을 확인한다.
5. 공급자 장애, 모델 변경, 폐기 시 대체 경로를 정한다.

## 의사결정 표

| 항목 | 확인 질문 |
|---|---|
| 품질 | 실제 문서·언어·형식에서 목표 정확도를 충족하는가? |
| 안전 | 금지 요청, 개인정보, 도구 사용 경계를 지키는가? |
| 성능 | p95 지연시간과 동시 처리량이 SLO 이내인가? |
| 비용 | 입력·출력·도구·검색을 포함한 요청당 비용은 얼마인가? |
| 데이터 | 저장·학습·지역·보존 정책이 조직 기준에 맞는가? |
| 운영 | 버전 고정, 관측, 장애 대응, 대체 모델이 가능한가? |

## 배포 패턴

- 작은 모델을 기본으로 사용하고 어려운 요청만 상위 모델로 라우팅한다.
- 민감정보는 내부 모델, 일반 지식은 외부 API처럼 데이터 등급별로 분리한다.
- 모델 교체는 [[LLM 평가]] 회귀 게이트를 통과한 뒤 수행한다.

## 실패 패턴

- 단일 벤치마크나 공급자 홍보 점수로 결정한다.
- 프롬프트 최적화 수준이 다른 후보를 비교한다.
- 모델 가격만 비교하고 검색·재시도·장애 비용을 제외한다.
- 자동 업데이트되는 모델 별칭을 운영 기준으로 사용한다.
