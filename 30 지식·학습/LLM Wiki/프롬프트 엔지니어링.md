# 프롬프트 엔지니어링

프롬프트 엔지니어링은 모델에게 역할, 목적, 입력, 제약, 출력 형식과 평가 기준을 명확히 전달하고 결과를 반복 평가하는 작업이다.

## 기본 구조

```text
역할: 누구로 행동하는가
목적: 무엇을 완료해야 하는가
입력: 어떤 데이터를 사용하는가
제약: 무엇을 하지 말아야 하는가
절차: 어떤 순서와 기준으로 처리하는가
출력: 형식, 길이, 필수 필드
검증: 성공과 실패를 어떻게 판정하는가
```

## 실무 원칙

- 중요한 규칙은 암시하지 않고 명시한다.
- 예시는 필요한 형식과 경계 사례를 보여주는 데 사용한다.
- 자동 처리 결과는 구조화 출력으로 받는다.
- 프롬프트 변경은 평가셋으로 회귀 테스트한다.
- 사실성이 중요하면 출처를 제공하고 근거 없는 답변을 거부하게 한다.
- 모델의 내부 추론을 요구하기보다 판단 기준과 최종 근거를 요청한다.

## 적용 조건

- 반복 가능한 과업과 출력 계약이 정의되어 있다.
- 입력 데이터와 지시문을 구분할 수 있다.
- 결과를 판정할 평가셋이나 Schema가 있다.

## 실패 패턴

- 한 프롬프트에 서로 충돌하는 역할과 목표를 넣는다.
- 외부 문서 내용을 상위 지시로 취급해 간접 인젝션을 허용한다.
- 모델·데이터가 바뀌었는데 기존 예시와 임계값을 그대로 사용한다.
- 문구를 계속 늘리지만 실제 실패 유형을 평가하지 않는다.

## 검증 체크리스트

- [ ] 필수 입력과 누락 시 행동이 정의되어 있다.
- [ ] 허용·금지 범위와 승인 경계가 명확하다.
- [ ] 출력 Schema와 실패 응답이 정의되어 있다.
- [ ] 정상·경계·공격 사례를 같은 버전으로 회귀 평가했다.
