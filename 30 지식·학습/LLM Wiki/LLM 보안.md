# LLM 보안

## 주요 위험

- 프롬프트 인젝션과 간접 프롬프트 인젝션
- 권한 밖 데이터 검색과 정보 유출
- 도구 호출을 통한 외부 시스템 변경
- 민감정보의 프롬프트·로그·평가셋 노출
- 악성 파일과 신뢰할 수 없는 웹 콘텐츠
- 모델·플러그인·의존성 공급망 위험
- 과도한 비용과 자원 소모

## 방어 원칙

1. 사용자 입력과 외부 문서를 명령이 아니라 신뢰하지 않는 데이터로 취급한다.
2. 인증 후에도 데이터와 도구 권한을 최소화한다.
3. 읽기·쓰기 도구를 분리하고 파괴적 작업은 승인받는다.
4. 검색 단계에서 사용자 권한을 적용한다.
5. 민감정보를 프롬프트와 로그에 불필요하게 포함하지 않는다.
6. 출력은 정책·Schema·사실 근거를 검증한 후 사용한다.
7. 호출 횟수, 시간, 토큰, 비용에 한도를 둔다.

## 기업 내부망 체크리스트

- [ ] 데이터 등급과 외부 반출 기준이 정의되어 있다.
- [ ] 모델 호스팅 위치와 저장 정책을 확인했다.
- [ ] 사용자별 문서 권한이 RAG 검색에 반영된다.
- [ ] 감사 로그와 보존 기간이 정해져 있다.
- [ ] 운영·개발·평가 데이터를 분리했다.
- [ ] 사고 시 도구와 모델 접근을 즉시 차단할 수 있다.
