# AI Agent

AI Agent는 목표를 달성하기 위해 LLM이 상태를 해석하고, 도구를 선택하며, 여러 단계를 실행하는 시스템이다.

## 핵심 구성

- **목표**: 완료 조건과 허용 범위
- **상태**: 현재 입력, 중간 결과, 남은 작업
- **도구**: 검색, 파일, API, 메시지, 코드 실행
- **정책**: 허용·금지 행동과 승인 경계
- **메모리**: 단기 상태와 장기 지식
- **관측**: 실행 로그, 비용, 지연시간, 오류

## 권장 실행 패턴

```text
요청 이해 → 계획 → 읽기 전용 조사 → 실행 후보 검증
→ 필요 시 사용자 승인 → 실행 → 결과 검증 → 보고
```

## Agent가 필요하지 않은 경우

- 실행 순서가 고정되어 일반 워크플로가 더 예측 가능한 경우
- 단일 API 호출로 해결되는 경우
- 실패 비용이 큰데 승인과 롤백이 없는 경우
- 도구 권한을 최소화할 수 없는 경우

## 안전 기준

- 읽기와 쓰기 도구를 분리한다.
- 삭제·배포·외부 전송·비용 발생은 승인 경계를 둔다.
- 도구 결과를 성공으로 가정하지 않고 후속 검증한다.
- 반복 횟수, 시간, 토큰, 비용 한도를 둔다.

## 적용 조건

- 목표는 분명하지만 실행 경로가 입력과 도구 결과에 따라 달라진다.
- 각 단계의 성공 여부를 관측하고 재계획할 수 있다.
- 도구 권한, 예산, 반복 횟수와 종료 조건을 시스템이 강제할 수 있다.
- 실패 시 사람이 개입하거나 안전한 상태로 복구할 수 있다.

## 실패 패턴

- 도구 설명이 모호해 잘못된 도구나 인자를 선택한다.
- 성공 여부를 확인하지 않고 다음 단계로 진행한다.
- 동일 작업을 반복하거나 외부 시스템에 중복 요청한다.
- 메모리의 오래된 상태를 사실로 취급한다.
- 에이전트가 필요하지 않은 고정 절차까지 모델 판단에 맡긴다.

## 검증 기준

- 작업 성공률과 단계별 도구 성공률
- 승인 없는 쓰기·삭제·전송 발생 건수
- 평균 단계 수, 재시도율, 중복 실행률
- 실행 시간·토큰·비용 한도 초과율
